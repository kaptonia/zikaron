# ZIKARON Desk 使用手册

ZIKARON Desk 是一个本机桌面应用：把你的作品或文件记进一本只增不改的账本，把账本锚定到以太坊（或所选的二层网络）上，再凭账本签发授权；收到授权的一方可以在任何一台机器上独立核验。

本手册按 0.2.0 版写。界面上的字用「」标出，与窗口上显示的一字不差。

---

## 1 · 基本概念

**身份。** 一个身份就是一组签名密钥。身份有两种：

- **助记词身份**：由 12 个助记词派生，同时有记录者与使用方两把密钥。
- **本机身份**：导入的一把现成私钥或密钥文件，只占导入时选定的那一种角色。

**两种角色。** 每个身份都分「记录者」和「使用方」两种角色，在左栏顶上切换。两种角色各有自己的密钥、地址和账本（数据目录）。

- **记录者**：记录自己的作品，签发授权。
- **使用方**：收下别人的授权并核验，也可以转授权。

助记词身份的两把密钥分别由 `m/44'/60'/0'/0/0`（记录者）和 `m/44'/60'/0'/0/1`（使用方）派生，地址不同，各自需要少量 gas。每个身份记着自己选的网络，它的两种角色同用这一个；同一台机器上的不同身份可以在不同的链上。

**根与现行钥。** 每种角色的地址是它的根：身份页、地址簿、「复制地址」、备份与镜像的分层都用根，别人授权给你、加密给你也都填根。签条目、发交易用的是现行钥。新身份的现行钥就是根；换钥（见「身份与密钥」）之后现行钥换成下一把，根不变。助记词身份第 g 代的钥由 `m/44'/60'/0'/g/0`（记录者）与 `m/44'/60'/0'/g/1`（使用方）派生，第 0 代即上面两条。

**账本。** 每种角色有一本自己的账本，由一串签名条目组成，只能追加，不能修改或删除旧条目。第一条是「创建账本」，一本账只有这一个根。条目类型有：

| 类型 | 说明 |
|---|---|
| 创建账本 | 账本的根 |
| 存证 | 一件记录的内容指纹 |
| 授权 | 授权某个地址在一段时间内使用某件记录 |
| 撤销 | 撤销一份授权 |
| 注记 | 给某一条补充说明 |
| 换密钥或移交 | 把账本交给下一把钥（换钥）或另一个人（移交） |
| 迁至新法 | 旧法账本的最后一条；其后是新法的「创建账本」 |
| 收编(旧法) | 0.1.x 账本里的收编条目，只读 |
| 删除条目 | 把一条存证标为已删除（见附录 C） |

**新法与旧法。** 0.2.0 起账本照 `zikaron/2` 写；0.1.x 写的账本是旧法（`zikaron/1`）。旧法账本升级（见第 3 节「升级到新法」）后是一本账两段：旧段到「迁至新法」为止，新段从新法的「创建账本」起，账本页同列一表，中间一条分段线。旧段的锚照旧有效。

**上链（锚定）。** 新条目先进「待上链」队列，发出一笔交易（发到这个身份所选的网络：以太坊主网，或 Arbitrum One、OP Mainnet 等）后才算上链。队列里的条目可以一次全部发出，只花一笔交易的费用。上链之后，任何人都能对着链核对这本账在那个时刻已经存在。换过链的数据目录有几条链：新条目锚到当前的链，换钥与迁至新法的条目锚到每一条链，账本检查把各条链上的锚一并读。

**授权。** 授权条目写明被授权方、记录、有效期和条款文件指纹。交给对方有两种方式：

- **授权码**：以 `zikaron-grant:` 开头的一段文本，只能核验签名和有效期。
- **授权包**：`.zkgrant` 文件，带着授权链各跳与签发者账本里核验要用的部分（授权带撤销成员时只带该跳、它所名的记录与账本的创世、换钥、迁移；不带成员的旧授权带整本账），可以做完整核验；导出时可带原件，收件人凭所授作品取出，也可加密给被授权方。0.1.x 导出的授权文件照读。

使用方还可以在自己的账本里写**转授权**，把上游授权再授给别人。

**记录包。** 从账本导出的一个文件（`.zkit`），或一个文件夹，含所选条目、原文件和各条目的上链位置（链与交易），交给别人核验。

**本机加密。** 本机的全部数据都由一枚主钥加密。主钥由 8 位口令开启：锁着时，本机数据一份也读不出来。

**身份的面。** 记录者把平台账号、链上地址与显示名一条条写进账本，各用一笔带原文的交易发在世系链上；任何人只凭链就能从根读出此刻有效的面（「身份」页、核验页「查看他人账本」、命令行 `face-table`）。世系链要先「立链」；各链的换钥簿要「入簿」，记下在任钥。

**主身份。** 这台机器上第一个身份默认是主身份，之后可在「设置 > 身份密钥」改设。只有主身份的助记词或密钥文件能在忘记口令时重设口令（见第 5 节）。

## 2 · 安装

0.2.0 提供 Apple 芯片 macOS 与 x86_64 Linux 的安装包和 x86_64 Windows 的 zip 包。每个包都附带第三方组件许可（macOS 在 `ZIKARON.app/Contents/Resources/THIRD-PARTY-LICENSES.txt`，Linux 在 `/usr/share/doc/zikaron-desk/THIRD-PARTY-LICENSES.txt`，Windows 在解压出的文件夹里），应用内在「关于」里也能看到。

**从早先版本升级。** 从 0.1.3 至 0.1.5 升级：直接覆盖安装，机器目录与数据目录照用，形式不变。有旧法账本的身份首次打开时弹出「升级到新法」（见第 3 节），确认一次即走完；没升级的账本照读，写新条目要等升级之后。0.1.x 导出的记录包与授权文件照读。0.1.2 及更早版本留下的旧形式文件一律不读：点明它不是本版的加密形式，原样留着。那些版本写的机器目录（密钥库、身份登记、设置）也是如此，所以从那些版本过来，本版从一个空的机器目录起步；0.1.0 与 0.1.1 记的账本，条目也是旧形式。要把记录者的账本带过来：

1. 在 0.1.2 里「导出账本镜像」（见「账本镜像」）到机器目录之外的一个文件夹，然后退出。
2. 把早先版本的机器目录连同它的指针文件一起挪开（两者在哪见附录 B），让本版两样都找不到。放在机器目录里的数据目录随之挪走；带过来的是那份镜像。
3. 启动本版：它从一个空的机器目录起步。设口令，再用同一组助记词导入身份。
4. 向导走到「创建账本」时不要建新账本：点「收编已有账本目录」，选镜像里的 `author` 文件夹，按「原位收编」（见第 3 节「第 4 步 · 创建账本」）。条目逐条重新核验，账本再与链上这把密钥的上链记录核对；收编成了，这一步即算完成，向导接着往下走。已有自己账本的家不收另一本账。
5. 在账本页跑一趟账本检查，看它答「正常」。

本版写过的本机加密文件，0.1.2 及更早版本读不了。

**macOS**

- `ZIKARON-0.2.0-macos-arm64.dmg`：打开后把 `ZIKARON.app` 拖进「应用程序」。命令行 `zikaron` 在应用包内的 `ZIKARON.app/Contents/MacOS/zikaron`；要在终端里直接敲 `zikaron`，打开「设置 > 命令行与 AI 控制」的「启用 zikaron 命令」（见「命令行」一节）：它在 `/usr/local/bin` 放一个指向应用包内命令行的链接，需要时弹出 macOS 自己的管理员口令框。直接从 dmg 里运行的应用不能启用，提示「请先把应用移入「应用程序」文件夹」。
- `ZIKARON-0.2.0-macos-arm64.pkg`：安装包，把应用装进 `/Applications`，把命令行装到 `/usr/local/bin/zikaron`，装完即可在终端里敲 `zikaron`，不必再开「启用 zikaron 命令」（那一处已有 pkg 装的命令行，开关显示「被其他安装占用」）。
- 要求 macOS 11 或更新。
- 应用用自签证书（Kaptonia）签名，未经公证（没有经过 Apple 的公证）。从浏览器下载的文件带有 macOS 的隔离标记，系统会拒绝打开；在较新的 macOS 上，「系统设置 > 隐私与安全性」里的「仍要打开」也不一定有效。先用 `shasum -a 256 <文件>` 核对 SHA-256，再在「终端」里去掉隔离标记：

  - 用 dmg：打开 dmg 之前先运行下面这条，再打开 dmg，把 `ZIKARON.app` 拖进「应用程序」：

    ```
    xattr -d com.apple.quarantine ~/Downloads/ZIKARON-0.2.0-macos-arm64.dmg
    ```

    如果已经拖进去了，改为运行：

    ```
    xattr -dr com.apple.quarantine /Applications/ZIKARON.app
    ```

  - 用 pkg：先运行下面这条，再双击安装：

    ```
    xattr -d com.apple.quarantine ~/Downloads/ZIKARON-0.2.0-macos-arm64.pkg
    ```

  命令里的路径按你实际下载的位置改。

**Linux**

- `zikaron-desk_0.2.0_amd64.deb`：用于 Debian、Ubuntu 及其衍生版。运行 `sudo apt install ./zikaron-desk_0.2.0_amd64.deb` 安装；窗口程序是 `zikaron-desk`（应用菜单里也有），命令行是 `zikaron`，两者都装在 `/usr/bin`，装完即可在终端里敲 `zikaron`（「设置 > 命令行与 AI 控制」的「启用 zikaron 命令」显示「已由安装包提供」）。
- `ZIKARON-0.2.0-x86_64.AppImage`：不用安装，`chmod +x` 之后直接运行，打开的是窗口程序；包里的命令行 `zikaron` 不能直接调用，「启用 zikaron 命令」在 AppImage 里也不可用（显示「此安装方式不支持」），要用命令行请装 `.deb`。它要用 FUSE；系统没有 FUSE 时，加 `--appimage-extract-and-run` 运行。
- 两个包都要求 glibc 2.31 或更新（Ubuntu 20.04、Debian 11 起）。包没有签名，先用 `sha256sum <文件>` 核对 SHA-256。
- 别的架构或发行版，按仓库 README 的「从源码构建」构建。从源码构建的应用打开「启用 zikaron 命令」时，在 `~/.local/bin` 放一个名为 `zikaron` 的链接，这个文件夹要在你的 `PATH` 里。在 x86_64 的 Linux 上运行 `packaging/linux/build.sh` 可以自己打出 `.deb` 与 AppImage；在 aarch64 上它只打出 `.deb`，AppImage 一步因为没有这个架构的固定运行时而报错停下。
- 系统文件对话框要走桌面门户，需装 `xdg-desktop-portal` 和一个后端（如 `xdg-desktop-portal-gtk`）。没有门户时，点选文件会提示「系统的选档框在这台机器上开不了。」，这时可以把文件直接拖进窗口。
- Wayland 会话里（KDE、sway、Hyprland、niri 等，niri 配 xwayland-satellite 亦同），窗口走 Wayland，拖进来的文件和文件夹由窗口自己收；GNOME 上有 XWayland 时窗口走 X11，粘贴与拖放照常；X11 会话照常。只有关掉 XWayland 的 GNOME 上，粘贴照常，拖放到不了窗口，请用选档框。
- 选档框一次只能选一种，所以既收文件也收文件夹的拖放区（如新建存证）点开时先问选文件还是目录。

**Windows**

- `ZIKARON-0.2.0-windows-x86_64.zip`：用于 x86_64 的 Windows 10 与 11。不用安装：解压到任意文件夹，双击 `zikaron-desk.exe` 即开；命令行是同一文件夹里的 `zikaron.exe`。程序自带运行库，不需另装。
- `zikaron.exe` 是命令行，要在终端里运行：在它所在文件夹的空白处按住 Shift 再右键，选「在终端中打开」（Windows 10 为「在此处打开 PowerShell 窗口」），输入 `.\zikaron.exe` 加动词和参数。在资源管理器里双击它，会打开一个窗口、打印用法后立刻关掉，看起来像闪退，这不是出错。
- 先在 PowerShell 里用 `Get-FileHash <文件> -Algorithm SHA256` 核对 SHA-256。
- 程序没有签名。首次打开时 Windows 会提示「Windows 已保护你的电脑」，按「更多信息」，再按「仍要运行」。Windows 11 开着「智能应用控制」时，未签名的程序会被直接拦下，没有「仍要运行」，也不能单独放行这一个程序；要用就先在「Windows 安全中心 › 应用和浏览器控制 › 智能应用控制设置」里把它关掉。
- 升级：用新版的文件夹替换旧的。机器数据不在解压的文件夹里，而在 `%LOCALAPPDATA%\ZIKARON\`（见附录 B），删掉解压的文件夹不会删掉它。
- 开始菜单项和桌面快捷方式不会自动加上。要在任何终端里直接敲 `zikaron`，打开「设置 > 命令行与 AI 控制」的「启用 zikaron 命令」，它把命令行所在的文件夹加进本用户的 `PATH`（不需管理员权限），之后新开的终端才认得 `zikaron`。把解压的文件夹挪到别处后，开关显示为关，再打开一次即加进新位置；按升级的做法原地替换文件夹则不受影响。
- 在 Windows 上，既收文件也收文件夹的拖放区点开的选档框只能选文件；要给文件夹，请把文件夹拖进来。

窗口程序不接受参数，带参数启动时不开窗，只说明原因；要处理文件，先打开窗口，再把文件拖进去，命令行的事用 `zikaron`。窗口打不开时（多半是显卡驱动不支持所需的图形接口：macOS 上是 Metal，Windows 与 Linux 上是 OpenGL；或在没有 3D 加速的虚拟机、远程桌面里运行）也会说明原因；在 Windows 上从资源管理器双击启动时，这句话以系统对话框显示。

在 macOS 与 Windows 上从源码构建同样见仓库的 README。

## 3 · 开始使用

### 首次启动

以下情况打开应用时，向导会自己弹出，并停在第一个没完成的步骤：还没设口令、还没有签名密钥，或当前是记录者而账本还没创建。

向导左边竖列六步，右边是当前这一步。竖列里完成的步骤打勾，可以以后再做的步骤画虚线，已完成的步骤和当前步之前的步骤可以直接点过去。每一步是否完成都按实际状态判断，不是按过「下一步」就算。

| # | 步骤 | 必做？ |
|---|---|---|
| 1 | 设置口令 | 必做 |
| 2 | 创建身份 | 必做 |
| 3 | 网络 | 必做 |
| 4 | 创建账本 | 可「以后再说」 |
| 5 | 充值 gas | 可「以后再说」 |
| 6 | 整机备份 | 可「以后再做」 |

没设口令时向导只停在第 1 步；设了口令而还没有身份时，只停在第 2 步。

**底部按钮。**

- 左边是「上一步」，以及可跳过的步骤上的「以后再说」。最后一步上这个键写「以后再做」，按下关掉向导，提示与「完成」相同。
- 「上一步」回到前一页：从核对助记词那一页回到同一组十二个词（核对的三格清空），从一步的第一页回到前一步。
- 左栏左下角、「退出向导」上方的「中文」|「English」从第一步起就能切换界面语言。选择记在这台机器上，口令门也用它（口令门上不再切换）。
- 右边在这一步没完成时是它自己的动作键（第 1 步没有动作键，填满即提交），完成后换成蓝键「下一步」。最后一步是「完成」，按下后提示「首次启动已完成;未完成项见「设置 > 关于」」。

**退出。** 左栏左下角的「退出向导」（语言切换在它上方）或 Esc 回到打开向导之前的页面。这一键在这台机器上已有口令和身份时才有：首次启动设好口令、建好或导入身份之后即出现，关掉再开也一样；之前没有可回去的地方。在「创建账本」一步退出，只有身份、不建账本。做完的步骤照旧算完。下次启动时，若还缺口令、身份，或记录者的账本还没创建，向导会再弹出；其余没做的步骤可从「设置 > 关于」的「重新运行向导」接着做。

- 新生成的助记词还没核对时，会先问「退出向导?」：按「退出」作废这组词并离开，按「继续核对」或 Esc 留在向导里。
- 口令和身份还缺一样时（例如真正的首次运行，两样都还没有）没有退出口，Esc 也不离开。

**其他打开方式。**

| 入口 | 打开到 |
|---|---|
| 「设置 > 关于」的「重新运行向导」 | 第一个没完成的步骤；全部完成时第 1 步。当前角色还没有身份时此键不可按 |
| 「设置 > 身份密钥」的「去设置口令」 | 第 1 步 |
| 「转授权」页的「生成密钥」（还没有签名密钥时） | 第 2 步 |
| 「转授权」页的「创建账本」（还没有账本时） | 第 4 步 |

凡是还没设口令，都先停在第 1 步。

#### 第 1 步 · 设置口令

1. 在八个格里输入 8 位字母或数字。区分大小写，输入的字以圆点显示。
2. 填满一遍后提示「再输入一次」，再输一遍。两遍一致即设成；不一致时整排抖一下，重新填。

- 过于简单的口令当场被拒：八位全同，或纯数字而成连号或像日期。提示「过于简单,请换一个。」
- 格下说明：「8 位字母或数字,区分大小写。」忘了口令，可用助记词或主身份导出的密钥文件恢复（见 5.3）。

口令排在建身份之前，因为密钥要放进由口令开启的密钥库。应用不读也不写系统钥匙串，密钥只住在本机密钥库里。

#### 第 2 步 · 创建身份

可以先在「备注」里写一个名字（可选，只给自己认），然后点卡上三行之一：「生成助记词」、「导入已有密钥」或「从备份恢复」。

**生成助记词（新身份）**

1. 按「生成助记词」。
2. 确认没人看屏幕，点遮罩「确认无人看屏幕后点按显示」，12 个词分三行四列显出。词显出时，下方的「隐藏助记词」把它们遮回。
3. 按顺序抄在纸上，按「我已抄在纸上」（揭开过遮罩后才能按），词随即遮回。
4. 在随机抽的三格（「第 N 个词」）里填回对应的词，按「确认并创建」。三个词对上即建成。

**导入已有密钥**：按「导入已有密钥」，见「身份与密钥」一节的「导入密钥」。这时导入的是本机第一个身份，它会成为主身份；导入私钥时同一张单里一并导出它的密钥文件（填密钥文件密码两遍和保存位置），忘了口令时凭这份文件找回。

导入的密钥可能在别处写过账本，所以导入后先不能写：第 3 步选好网络后，应用自动把这把密钥在链上的上链记录与本机账本核对一次。链上没有这把密钥的记录（例如一把新钥），或记录都在账本里，就可以写了；链上有账本里没有的，见「存储」一节的「取回账本」。

**从备份恢复**：按「从备份恢复」，选整机备份文件，填「备份密码」，按「恢复」。身份、密钥、账本和设置整份回来，用刚设的口令重新加密，向导随即关闭。

这台机器上建成的第一个身份就是主身份。

#### 第 3 步 · 网络

可选的有两项：

- 「以太坊主网」，用公共节点；当前身份和这台机器都还没选过网络时默认选中它。
- 「自定义」：先空着，到「设置 > 网络」自己填链号、合约与节点（可选预设）。

按「下一步」即选定。这里选的就是第 2 步建的那个身份的网络，它的两种角色（记录者、使用方）同用这一个：选主网，当前角色的数据目录随即填好链号、登记合约、起始区块和两个公共节点，另一种角色的数据目录在第一次打开时同样填好；选「自定义」，当前数据目录里由预设填入的网络被清空（手填过的不动），读链与上链都会提示未配置，到「设置 > 网络」添加节点，在「链」一组按「编辑」手填或选一个预设，保存后才生效。这台机器也记住这一次的选择，下次向导与「新建身份」默认选中它。

Sepolia 测试网、Arbitrum One、OP Mainnet 不在这里列出，要用就选「自定义」，再到「设置 > 网络」在「链」一组按「编辑」，在「预设」里选（见附录 A）。例外：当前身份或这台机器已选过其中某一个（例如从这样的备份恢复而来），它会列在「以太坊主网」和「自定义」之间。

在主网上锚定要花真实的 ETH 付 gas。

#### 第 4 步 · 创建账本

第 2 步导入的身份，要等第 3 步之后与链上核对过才能创建账本（见第 2 步）。

1. 在「账本说明(可选)」里写账本的用途。
2. 按「创建账本」，出确认卡：「账本说明」「费用」（「免费(仅写入本地)」）；账本位置在「详细信息」里。
3. 在卡上再按「创建账本」才写。

**收编已有账本目录。** 已有一本账（账本文件夹，或「导出账本镜像」写出的镜像）时不必新建：「创建账本」旁边的「收编已有账本目录」（这个数据目录还没有账本时才有）打开同名的卡，卡上写「选一个账本文件夹,或早先版本「导出账本镜像」导出的那个文件夹。里面的条目逐条核过,封存进这个数据目录;那个文件夹本身一个字节不动。」

1. 在「账本文件夹」里选那个文件夹。
2. 按「原位收编」（选了文件夹才能按）。按「取消」或 Esc 关掉卡，什么也不收。

这与「设置 > 本机数据」「高级选项」里的「收编已有账本目录」→「原位收编」是同一件事，规矩与被拒时的说法都一样（见「存储」一节的「数据目录」）。收编成了，这个数据目录就有了根条目，这一步与创建了账本一样算完成：右边换成「下一步」，接着是充值 gas。导入的身份收编之后，账本自动与链上这把密钥的上链记录核对（见「取回账本」）。

#### 第 5 步 · 充值 gas

页面显示「密钥地址」「gas 余额」和一个付款二维码（「钱包扫码付款」）。

1. 从你的钱包往这个地址转少量 ETH。地址可以选中复制。
2. 按「我已转账」。向导不发交易，只读一次链上余额：大于零即完成，自动进入下一步；还是零时提示「链上还没看到这笔转账,稍后再按「我已转账」。」

读余额需要节点。第 3 步选了「自定义」的，先到「设置 > 网络」配好节点。

#### 第 6 步 · 整机备份

卡上「内容」一行列出这份备份装什么（几个身份、几条账本条目、几条记录、设置）。一个备份文件恢复全部；只有助记词，只能恢复链上读得到的数据。也可以按「以后再做」跳过。

按「导出备份」，填写方法见「存储」一节的「整机备份」。导出成功后这一步即完成。

#### 升级到新法

账本是旧法（0.1.x 写的）时，打开应用即弹出「升级到新法」卡（每次启动一次）；也可在账本页「这本账待升级到新法」一行按「继续」打开。卡上四步：「旧条目上链」「关闭旧账上链」「新法首条上链」「新法写入」，每步写现状。

1. 卡上写这次升级要发的全部几笔与估算费用（「共 N 笔,约 … ETH」）。按「升级」确认一次，之后自己走完：没上链的旧条目先上链，写「迁至新法」并上链，等链上时刻过了它所在的块，再写新法的「创建账本」并上链。
2. 等块时那一步写「等下一块」或「等链上确认」；写好还没发出的写「还没发出」，按「升级」即接着发。中途关掉应用或断网，下次打开从断处接着走，不重签、不重发。
3. 某一步被拒（余额不够、节点不通等）即停，卡上「停在这一步」写原因；改好后再按「升级」。

- 这把钥在旧法下把账交出过时不能用它升级，卡上写出路。
- 升级不改数据目录的形式。旧段条目照样可作存证目标、撤销、删除与注记。

## 4 · 窗口与通用操作

#### 4.1 窗口布局

左边是左栏，右边是页面。页面顶上是工具栏：左边有后退、前进箭头和页题，右边是这一页的按钮和筛选。导入的身份在链上有账本里没有的记录时，首页、左栏各项的主页面和设置首页的工具栏右边另挂一枚黄色「只读」。

**左栏从上到下：**

1. **身份牌**：写当前身份的名字（没取名写它地址的缩写）和种类（还没有身份时写「尚无身份」）。点开是身份菜单：
   - 顶上是标题「切换身份」，下面每个身份占两行：名字；种类，主身份后面标「主身份」，当前的标「正在使用」并套着蓝框。点另一个身份即切过去并回到首页。
   - 身份之后是「新建身份」「导入密钥」和「身份密钥」（打开设置里的身份密钥页）。
2. **角色切换**：分段「记录者」|「使用方」。切换后左栏整条换成那一种角色的页面，回到首页，并提示「已切换为…」。
3. **页面列表**：

   | 记录者 | 使用方 |
   |---|---|
   | 首页 | 首页 |
   | **记录**：记录存证、授权 | **授权**：我的授权 |
   | **查看**：核验、账本、提醒 | **查看**：核验、提醒 |

   - 「提醒」右边的数字是提醒页上黄灯和红灯的行数。
   - 再点一下当前所在的那一项，回到它的列表页。每一项记得你上次停在哪里。
4. **底部**：
   - 「设置」。
   - 「锁定」：设过口令才有。
   - 状态行：右端的小图标就是「同步」。

**状态行**依次显示最要紧的一种：

| 显示 | 含义 |
|---|---|
| 「进行中:…」 | 有你发起的后台任务在跑；同时有几项时写「进行中:… 等 N 项」。点它回到发起任务的那一页 |
| 「正在同步…」 | 同步在跑 |
| 「同步失败」 | 上一次读链失败；原句在「提醒」页的「详细信息」里 |
| 「上次同步 时:分」 | 上一次读链成功的时刻，照设置里的时区 |
| 「尚未同步」 | 还没读过链 |

**同步。** 点状态行右端的同步图标，按当前角色在后台读链：

- 两种角色都读一次签名密钥余额。
- 记录者建过账本的，再跑一趟账本检查。
- 使用方再复核一遍我的授权。

全部回来后给一条汇总提示。没配节点时提示「未配置节点:在「设置 > 网络」中添加」；其中某一项已经在跑时，提示「…正在进行,本次未执行」。

**读链怎样问。**
- 查锚时只问这本账相关地址（账本里写过的那些密钥）发的锚，别人的不问；回来的每一条照样在本机逐项核过。一个相关地址也没有的范围不问。
- 每台节点一问问整个范围。节点拒答时（每问只收 3 万块的公共节点会明说），稍等再原样问一次；仍拒，这台节点就不答这一问，读数以答了的节点为准：只剩一台即标为单源，拒答的节点连同它的原话列出。没有一台节点答了整段时，每台拒答的节点各自切段去读：拒了就把这一问对半再问，答了就按答成的这个宽度往下问，后面哪一段又被拒，把那一段再对半、新宽度接着用；拒话里的数不读。哪一台先把整段读完，其余即停，用它的读数，标为单源。每台节点每一读至多问「设置 > 网络」里「节点最大问数上限」那么多问（默认 256）：宽度小到整段要超过这个数才读得完、问数用到了、或中途读不下去，这一台即让位，不压别的节点读成的；每台都让位，这一读才不成，问题面板与命令行都说各节点没能在问数上限之内读完，可调大上限或添一台读得了整段的节点。本机记下每台节点上一回答成的宽度，下一读从它起。节点限流时照耐心表等；仍限，先歇几秒再问（一直限着就越歇越久，至多半分钟），这一读它让位，别的节点能给的那一份当即交给别的节点；限流、断路、超时都不切段。限流从不算节点缺这种问法；节点对多块的读日志只回 `-32601` 而话里没说没有这种问法的，或话里点了范围的（例如说多于一万块不支持），也不算。
- 几个节点一致确认过的锚，本机记下它的区块时间与判词，下次不再逐条追问。同一组节点读过的登记合约日志也记下，记到那次读到的链头往下 64 块为止：下一次同步，或命令行在凭据那条路上的下一次运行，只向节点问那之后的区块，所以链上有没有新锚每次照样现问；换了一组节点则整段重读。链上那一块若换了（区块哈希不同），或节点交回的那条日志与记下的不一样，即重新问。只一个节点读到的，记下并标为单一节点的读数：只有之后同样只读一个节点的（核验记录、只有一个节点的网络）才整条取用，要几个节点一致的读数从不整条取用；它的区块时间、发送者的代码与交易都自证过的，几个节点的读数只向各节点问它的回执。判词未证的不记。一组节点里有节点没答（拒答、让位、断路、超时、限流等过仍限）时，答了的那几台读得一致的照记；只剩一台答的，记下并标为单源，之后取用它的读数也标单源。要全部重新问一遍，用「设置 > 本机数据」「高级选项」里的「全部重新核对」。
- 带撤销成员的授权要读的告示输入（撤销告示与换钥簿的接任记录）同此：几个节点读得逐字节相同的，记到链头往下 64 块为止，连同每条日志判成的记录；下一次只问那之后的区块、只判新的那几条，同一次撤销的发前读与发后读回之间只补读新出的区块。谁在任、撤没撤，每次照记录现判。各节点的回执、告示交易与告示前后的码合成一批来问（每批至多 20 问），不收批量的节点照旧一问一答。核验页也记告示输入（整条链公开的记录，不涉核的是谁的授权），签发方的锚日志照旧不记。命令行不带凭据也不带钥的读（`scan --basis --endpoint`、`check-grant`、`chain-check`、`grant-package --package`、明文账本文件夹上的 `kit-export --to`，AI 应用经它们的工具同此）记在本机机器目录的 `cli-read/` 里：明文，只本人可读写，只有链上公开之事，节点地址只记摘要；带 `--key` 的 `anchor`、`revoke` 记在 `cli-sent/` 里，以那把钥导出的钥加密。「全部重新核对」一并清掉。
- 这些记录写不成（磁盘满、目录只读）时照样读完，桌面在问题面板说一次 `READS_UNKEPT`，命令行的答多一格 `unkept`，列出没写成的部分与原因；下一次照旧从头读。因上锁而写不成的不说。

**快捷键**（表里的 ⌘ 在 macOS 上是 Command 键，在 Linux 等其他系统上是 Ctrl 键；如 ⌘L 在 Linux 上按 Ctrl+L）：

| 键 | 作用 |
|---|---|
| ⌘1 起 | 按顺序打开左栏各项（记录者 ⌘1 至 ⌘6，使用方 ⌘1 至 ⌘4） |
| ⌘[ / ⌘] | 后退、前进 |
| ⌘, | 设置 |
| ⌘L | 锁定 |

口令门、向导或弹出的卡片开着时，快捷键不起作用。

在 macOS 上，菜单栏随应用的语言：应用菜单有「关于」（一个小窗，显示图标、名称、版本与这一版的日期）、「设置…」（⌘,，口令门、向导或卡片开着时变灰）、「服务」「隐藏」「隐藏其他」「全部显示」「退出」；「编辑」有剪切、拷贝、粘贴、全选，在系统的文件面板里同样可用（可把长路径粘贴进「前往」框）；「窗口」有最小化（⌘M）、缩放、关闭（⌘W），关闭与窗口的关闭钮相同。

#### 4.2 列表与详情

列表页（记录存证、待上链、账本、授权、我的授权；待上链是记录存证页工具栏上「全部」|「待上链」分段的后一段）顶上有一格搜索。记录存证、账本、授权、我的授权四页的搜索格旁另有「开始日期」「结束日期」两格：点开是一张月历，选一天即填上，「今天」「清除」在月历底下。设了日期（两格可只填一格），列表只留上链区块时刻在这两天之间（含两头）的行，还没上链的行不列；日子按「设置 > 语言和时间」的时区算。窗口窄时两个日期格排到搜索格下面一行。

要从一张清单里挑一项的地方（新建授权的「最近地址」、地址簿、注记的目标条目），点开都是一张带搜索格的浮卡；清单里有时刻的（注记的目标条目）也带两个日期格。新建授权的「选择记录」与导出记录包的「选择条目」打开的是弹窗，同样带搜索格和两个日期格。点一行进入这一条的详情页，用工具栏的后退箭头或 ⌘[（Linux 等其他系统上 Ctrl+[）返回。详情页往下滚时，页题出现在工具栏上。

窗口变窄时，带旁栏的页面（导出记录包）会把旁栏排到表单下面。

#### 4.3 页顶提示条

以下情况页面顶上挂一条提示，一次只挂一条：

| 提示 | 情形 |
|---|---|
| 「账本已断链,当前只读」 | 账本检查发现断链。点「去恢复」到「设置 > 本机数据」，从整机备份恢复，或在「高级选项」里对账 |
| 「账本已移交给新密钥,当前只读」 | 这本账已移交出去 |
| 「账本尚未与链上核对」或「链上有 N 条记录不在本机」 | 导入的身份还没取回账本（见「存储」一节的「取回账本」）；「查看」到「设置 > 本机数据」，那一页的红框里取回 |
| 「已交接到另一处,收回之前只读」 | 这本账已用 `hand-over` 交接到另一处（见「交接账本」），交回并 `take-over` 收下之前这里不写 |
| 「只读:…」或「只读:未取得锁」 | 同一个数据目录已被另一个 ZIKARON 窗口占用，这个窗口只能读 |
| 「这处数据由另一台机器在写,本机只读」 | 数据目录在同步盘或移动盘上，另一台机器在写它。提示条上的「改由本机写」把写入改到这台机器，另一台机器随之只读 |
| 「写者标本版读不了,本机只读」 | 这处数据的写者标是更新的版本写的或已损坏，本机一个字节不改。确认别处不再写这处数据后，按「改由本机写」接管 |
| 「旧数据 · 日期 · 仅供查看」 | 正在查看被替换下来的旧数据；按「返回」回到当前数据 |

#### 4.4 按钮与确认卡

**按钮颜色表示角色：**

- **蓝键**：这一屏的主要动作，一屏至多一个。
- **白键**：其他动作。
- **白底红字键**：打开确认卡，或进入下一步，本身不写入。
- **红色实心键**：按下即写入账本或发上链，只出现在写入的那张卡片上。
- **无框的键**（如「以后再说」「退出向导」）：次要的去处，不写入。

**写入流程。** 凡是写入账本或上链的动作，都要在一张卡片上按红色实心键才真正写入；按「取消」或 Esc 不写。卡上写出要写什么、费用多少，机器数据收在「详细信息」里。「新建存证」「注记条目」这类卡，填写与写入在同一张卡上；「换密钥或移交」这类分两步的卡，第一步按「下一步」，第二步核对后才按红色实心键；上链、删除存证等动作先出一张核对用的确认卡。

**卡片通用规则：**

- 卡片一次只开一张，卡外点击不起作用。
- 机器数据（条目 ID、交易哈希、原始判定等）收在「详细信息」折叠里，不常用的选项收在「高级选项」折叠里。

**耗时动作。** 按钮里显示进度，完成时打勾；失败时变红并抖一下。

**填格不合要求时。** 那一格描红；填了而不合要求的，原因一行小字写在那一格名字那一行的右端（名字在左的一行写在名字与输入框之间），放不下截断，指针停在字上或那一格上看全句；空着没填的只描红，不写字。按下「添加」「保存」等键才判出的也这样写，不另弹提示；一改字，红框与原因即去。整张卡共有的情形（链上时间读不到、时段重叠、节点不通等）写在卡外或卡首的提示条里。原因与提示都不占地方，各格的位置不随它们变。

#### 4.5 提示（吐司）

操作结果以一张小卡出现在页面顶部中间，一次只显示一张，新的替换旧的。

- **普通提示**：显示约 3 秒。
- **错误提示**：第一行说发生了什么，第二行说下一步怎么做，显示 6 秒。带「关闭」；有原始信息时再带「详情」，展开后提示停住，直到按「关闭」或「收起详情」（收起后再显示 6 秒）。
- **提醒提示**：以「提醒:」开头，带「关闭」，显示 6 秒。
- 任务完成时你已经离开它的页面的，提示上带「查看」，按下回到那一页。

**哪些事会提示：**

- 你按下去的操作，完成或失败时各提示一次。
- 应用自己在后台读数据，只在失败时提示；其中网络失败不弹提示，只在状态行显示「同步失败」。
- 卡片上的错误直接写在卡上，原句在「错误详情」里，不再另弹提示。

#### 4.6 拖放与选择文件

**拖放区。** 可以拖文件进来，也可以点一下打开系统的选档框；在选档框里按取消什么也不变。

- 一个拖放区一次只收一项。拖进多个文件时提示「一次只能拖入一项。多个文件先放进一个文件夹。」，一个也不收。
- 例外：记录包的附件区收多个；「添加授权」卡拖入多个文件时只取第一个。「新建存证」卡上没有拖放区：卡开着时拖到卡上的文件照收，一次可以多个（批量存证）。

**整窗拖放。** 在没有自己拖放区的页面上，把一个文件拖到窗口任意处：

- 记录者：打开「新建存证」。
- 使用方：转到「核验记录」并立即核验。

**选择路径。** 需要文件夹或文件路径的地方，一行显示已选的路径或文件名（没选时写「未选择」），「选择文件」「选择目录」或「选择文件或文件夹」（按那一处能选什么写）在那一行旁边，或在卡片左下角（如「新建存证」「从备份恢复」）。输出位置同样用「选择目录」选：记录包、授权文件、凭证和快照默认放在数据目录里的 `kits` 文件夹；备份和镜像默认上一次的位置，没有时在文稿目录；密钥文件没有默认位置，要先选。

## 5 · 口令、锁定与恢复

#### 5.1 口令门

设过口令的机器，每次打开 ZIKARON 先出口令门：「输入口令」，下面八个格。

- 输满 8 位即自动验证，验证时显示「正在验证…」。
- 输错时整排抖一下，提示「口令错误,还可再试 N 次」。
- 连错 5 次，卡片变为「已锁定」，只能走恢复。

错误次数记在盘上，重开应用也不清零。这一道限制挡的是有人坐在这台机器前随手试；有人把密钥库文件拷走的话，挡住他的是口令本身和每试一次都要跑的加密计算。

另外三种情况：

- 如果密钥库文件的加密参数低于本机标准（例如被人改低过），开锁时提示「加密参数低于本机标准。」「输入口令,按本机标准重新加密。」，这一次不计错次，输入正确口令后按本机标准重新加密。
- 开锁或设口令时发现密钥库文件损坏，会提示「密钥库文件已损坏。」，库不会被改动。
- 启动时密钥库文件就读不成，口令门那一侧显示「密钥库读不成」，并写出原因和那份文件的路径；不进首启向导，也不新建密钥库（里面的密钥还在那份文件里）。这一屏下方的「挪开本机数据,重新开始」把整个本机数据目录挪到旁边，进首启向导，再从整机备份或助记词找回。

#### 5.2 锁定与自动锁定

按左栏「锁定」或 ⌘L（Linux 等其他系统上 Ctrl+L）立即锁定：

- 内存里的主钥清掉，数据目录关闭，页面上读出的数据清空，屏幕上显示着的助记词也一并清掉。
- 后台工作不再新起：账本检查、授权复核、撤销监测、待上链发送与等待收据。正在发送或等收据、正在写入的任务会先做完，主钥随后清掉。
- 锁着时，要用密钥的动作被拒：「密钥库锁着。」「输口令解锁后再做这一步。」

解锁后，数据目录重新打开，并补做一次：该跑的账本检查和授权复核照跑，待上链队列继续等收据。

**自动锁定**在「设置 > 身份密钥」里，出厂开着：空闲满「闲置时长」（1、5、15、30、60 分钟，默认 15 分钟）即自动锁定。键盘或鼠标的任何动作都重新计时。关掉后只在按「锁定」或退出时锁定。已经发出去的交易不受锁定影响。

#### 5.3 忘记口令

在口令门按「忘记口令」进入「恢复」。只有**主身份**的凭据能重设口令：

- **主身份是助记词身份**：卡上写「输入主身份的助记词以重设口令。」，填 12 个词。
  - 整段助记词可以粘进任一格，从那一格起自动分开。
  - 每一格都以圆点显示，不在词表里的词会标红。
  - 十二个格下面有「用密钥文件恢复」折叠：不填助记词，改用主身份任一角色导出的密钥文件（「设置 > 身份密钥」的「导出密钥文件」）和它的「密码」。
- **主身份是导入的本机身份**：卡上写「用主身份的密钥文件重设口令。」。按「选择文件」选主身份导出的密钥文件，再填「文件密码」。密码不对时提示「密码错误。」；选的不是密钥文件，或文件里的加密参数越界，会在开始任何解密计算之前就被拒（「无法识别 keystore 文件格式。」「keystore 文件的加密参数无效。」）。

填好后设新口令（输两遍：「设置口令」，再「再输入一次」）。恢复成功后错误次数清零，旧口令作废，提示「已恢复,口令已重设」。

- 用次要身份的助记词或密钥文件来恢复，会被拒：「这是次要身份的助记词或密钥文件。」「只有主身份能恢复口令;用主身份的,或从备份恢复。」
- 没有主身份（这台机器还没有身份）时没有可用来恢复的凭据；这样锁死的机器改为提示重置空密钥库。
- 按「取消」回到输口令的卡片。口令门已经「已锁定」时没有「取消」，只能走恢复。

#### 5.4 在口令门从备份恢复

恢复卡片底部有「从备份恢复」：

1. 选整机备份文件，填「备份密码」，按「恢复」。
2. 出「以备份替换本机?」：写备份的名字和内容。按「替换」。
3. 「设置新口令」，输两遍。

本机的身份、密钥和数据整份换成备份里的，用新口令重新加密，错误次数清零，提示「已从备份恢复」，后面接着写备份里有什么。常见拒绝：

| 提示 | 情形 |
|---|---|
| 「备份密码错误。」 | 备份密码不对（不计口令错次） |
| 「不是 ZIKARON 备份。」 | 选的不是备份文件 |
| 「备份来自更新的版本。」 | 需先升级应用 |
| 「备份内容不成形。」 | 备份文件已损坏 |

#### 5.5 重置空密钥库

设了口令但还没建成任何身份，又连错 5 次时，库里没有可以恢复的东西。卡上写明这一点，只给一个「重置密钥库」：

- 按下删除这份空密钥库，回到向导第 1 步，提示「密钥库已重置,可以从头设置」。
- 之后设新口令即产生一枚新主钥。封在旧主钥下、再也打不开的本机数据，会被原样挪到机器目录的 `set-aside` 文件夹（同名已有即往后编号），不删除。
- 库里只要还有身份，这个按钮就不会出现。

## 6 · 记录者：一条完整的走法

**记录者席**（左栏顶上选「记录者」）：

1. **首次启动。** 按第 3 节走完向导：设口令、创建身份、选「以太坊主网」、创建账本，给记录者地址转一点 ETH，导出整机备份。
2. **存证。** 把作品文件拖进首页的拖放区，写「记录名称」，按「加入账本」。
3. **上链。** 点首页的「待上链」卡（或到「记录存证」的「待上链」分段按「全部上链」），在「上链」卡上按「确认上链」。
4. **授权。** 到「授权」按「新建授权」：
   1. 填被授权方地址。
   2. 按「选择记录」选一件已上链的记录。
   3. 拖入条款文件，选有效期。
   4. 按「加入账本」，确认卡上再按一次。
   5. 然后像第 3 步一样把它上链。
5. **交付。** 在授权详情里按「复制授权码」，或「导出授权包」，发给对方。授权包带着你的账本，对方能做完整核验。
6. **日常。** 看「提醒」页；需要时在授权详情里按「撤销授权」。

## 7 · 记录者各页

#### 首页（记录者）

链上有这本账的记录而本机没有时，最上面先出一张红卡「账本需要取回」：「链上有 N 条记录不在本机。取回前无法写入、上链或导出。」按卡上的「取回账本」去「设置 > 本机数据」。

**左上：拖放区**「拖入文件以存证」。拖进一项或点选一项，打开「新建存证」。

**右上：「待上链」卡**，显示队里的条数，有三种状态：

- 「点击卡片上链」：点它直接打开「上链」卡。
- 「正在等待上链」：交易已发出，在等确认。
- 「已全部上链」。

**中间三格**，整格可点：

| 格 | 显示 | 点它去 |
|---|---|---|
| 「账本状态」 | 上一趟账本检查的结论「正常」或「异常」，下面「共 N 条」 | 账本页 |
| 「记录存证」 | 没被删除的存证条数，下面是最新一件的名字 | 记录存证页 |
| 「30 天内到期」 | 按链上时间 30 天内到期、没撤销的授权份数，下面是最早到期的那份（「#N · 日期」） | 授权页 |

- 没有读数的格显示「--」，下面写原因：还没读到数据时写「尚未读取」（「账本状态」在第一趟账本检查之前也是这样）。
- 「30 天内到期」还没有链上时间时写「无链上时间」。
- 点「账本状态」格，到账本页，同时展开账本状态卡里的「账本检查」折叠。

**「最近」**：账本最近五条，含序号、类型、摘要和上链状态，点一行进入它的详情。没有条目时写「暂无条目」。

### 身份

记录者左栏「首页」之下，三个页签：「概览」「名字与面」「世系链」。页上每一格都取自重读的面表（`zikaron.face/1`）与各链的换钥簿；工具栏右端「重读」一次读这两样。面表读到各链链头中最早那一块的前一秒，刚上链的一笔要等下一块出来、再重读才见行。使用方左栏没有这一页。

#### 概览

显示名（可复制）、身份名（本机）、身份地址与标记 `zikaron:0x…`（各可复制）、在任钥与第几代、世系链、名下有效的账号与地址数、未落座数、读至何时、「未读」「读不出」两个数。「读不出」大于零时多一行：换一台能答全状态的节点重读。「未读」只是数（账本的普通条目上链只带哈希），不说缺了面。读时略去的链各一行，写明原因。没读过写「尚未读取」；读不成写原因，不显示空表。

#### 显示名

「名字与面」页签。没立世系链时只有一行「先立链」与「立链」；换钥途中各写键不可按，写「等换钥做完」。「设显示名」「改显示名」：1 至 32 个字，空格与不可见的字拒，点出是哪个字；写入时化成规范形（NFC）。历次逐行列起止，正在用的那个标「正在使用」，可「解除」。显示名不独占，谁都能取同一个名字；授权卡、核验结果等凭据处只写根与地址。

#### 面

- 账号：「关联账号」只填平台与账号名（平台给的 ASCII 名，非 ASCII 点出是哪个字）。账号行只是这一侧的话，另一半是平台页上挂的标记（单子上可复制）。解除后可「再关联」，行里多一段。
- 地址：「关联地址」填地址、角色、附言（可不填）、同意签名。把对方签出的同意文本贴进地址一格，地址、角色、签名自己填好；签给别的身份的当场拒。钥在本机的地址不用贴，过口令当场签。同意签了撤不回；合约地址签不出同意。签的一头在对方 app 的「设置 > 身份密钥」：「将地址签入 Zikaron 身份」。各单的键没填齐时灰着，悬停说「还差:…」。
- 写入：「写入并上链」写进账本，接着出「上链」卡，写链与预计 gas，按卡上的键发出；出块之后重读才见行。还在队里的标「待上链」，旁边「上链」再打开那张卡；已发出而面表还没读到的标「未落座」。
- 未落座：读者不认的条目逐条写原因（如换钥之后旧钥签的），「重签并上链」由在任钥重签。
- 面条目连附言永久公开，解除只止一段。

#### 世系链

当前世系链与立链时刻，「立链」或「换世系链」：只能选换钥簿已把在任钥记在根名下的链，没入簿的写「先入簿」。账本的开端还没上链时，头一张确认卡先发开端那一批，卡上写明下一张发什么；发完下一张卡自己出来，不用再按「上链」。世系链与锚定链各是各的：「设置 > 网络」的「换链」不带着世系链走，两者不同时这里写出锚定链，标「不是世系链」。下面「立链记录」逐次列出。

#### 入簿

「各链的换钥簿」：每条链簿上记在这个身份名下的钥，与在任钥是否一致。「未入簿」的链按「入簿」：根钥在簿上宣告在任钥，在任钥接任（根钥须在本机，不在写「根钥不在本机」）。入不了的照实写：根在这本簿已归别的根；在任钥已入别的根（先换钥，再用新钥入簿）；簿上是上一把钥（换钥还没在这条链接任）；簿上是别人的钥时写「已被他人接任」。根钥不在手之后，没入簿的链就入不了了。

#### 换根

根钥丢了或泄了、入不了新簿的身份，把面搬到一把全新的根上。「世系链」页签「换根」，单子填新身份名与新根的世系链链号（下面几枚预设点了即填；部署表里没有登记合约与换钥簿的链号当场拒），按「开始」。分两段，各在它自己的身份里做：

- 在原根：生成新身份（抄下助记词、核对三个词，不问口令）→ 原根写换根并上链（确认卡写「换根 · 撤不回」）→ 读回原根的面 → 给新根的钥转入手续费（数额照新根接下来要发的几笔现估；原根的钥在那条链上钱不够，照实写新根地址，转够了再往下）。
- 「切到新身份继续」：切过去单子不关，背后就是新根的「身份」页。
- 在新根：立链（一按写起源与世系链，直到确认卡；起源先发时卡上写「下一张发…」，发完接着出下一张；前一批还在上链时回到步骤，写「已写入,待上链;前一批上链之后再发」，键为「上链」；读簿之后写被拒，拒因写在单上）→ 写承根并上链 → 读两个根的面，互指即「已核」。发出的面条目，页面在落座之前自己隔一会儿重读，不用按「重读」。

中途关掉，下次从「继续」接着做。换根撤不回；只换到本机新生成的身份（命令行 `face-reroot --to` 照法只要求与根不同）。新根概览里「从原根搬来」逐条列出原根封存时的显示名、账号与地址，按「关联」逐条重写，每条一张上链卡：账号要在平台页上换成新根的标记，地址要对方就新根重签同意（本机的 ZIKARON 地址过口令当场签）。都落座后这一块消失。

换根之后原根的「身份」页只剩「已换根至 <地址>」一块；面在新根看。只搬面：原根的账本、授权、撤销与换钥照常，换钥不再等面条目落座与入簿；原根钥要留着，不用时交接给一把自己保管的钥。新根的「承自 <地址>」在世系链页签最下面。「查看他人账本」的面：对方已换根且两表互指才写「已换根至」并可「查看新根的面」，只有一面之词的写「声称换根至」。

### 存证上链

左栏「记录存证」。工具栏右边是分段「全部」|「待上链 N」。

「全部」分段从上到下：

- 拖放区「拖入文件以存证」，拖进或点选后打开「新建存证」。
- 搜索格「按记录名或内容指纹找」，旁边「开始日期」「结束日期」按首锚区块时刻筛。要看一份文件在不在这本账本里，把它的 SHA-256 填进搜索格。
- 记录表，列为「记录」「上链状态」「首锚区块时刻」，最新的在上。被删除的记录名划掉。还没有存证时写「尚无存证,拖入文件开始存证」。

#### 新建存证

「新建存证」是一张卡，填好按一次即写入。从上到下：

- **内容**：「文件」一行写所选文件、文件夹或 Git 仓库的名字和大小，没选时写「未选择」；下面是「内容指纹」，旁边可复制。要选或换内容，按卡片左下角的「选择文件」，或把文件、文件夹、Git 仓库拖到卡上。指纹在后台算，算好之前「加入账本」（或「立即上链」）显示「正在计算指纹」并转圈，不能按；附了几个文件时，按下后那一键显示「正在记录」，记完卡片才关。内容指纹这样算：

  | 类型 | 算法 |
  |---|---|
  | 文件 | 文件字节的 SHA-256 |
  | 文件夹 | 连同各文件名和内容一起算；文件夹里的路径在哪个系统上都以 `/` 连，同一个文件夹在 macOS、Linux、Windows 上算出同一个指纹 |
  | Git 仓库 | 按当前提交算 |

  「记录名称」为空时会自动填上文件、文件夹或仓库的全名，扩展名照留。
- 「费用」：「上链时计费」；开了「自动上链」时为「下一步估算 Gas 费」。「账本位置」在「详细信息」里。
- 「记录名称」。
- 「为谁留证」折叠，右边写「可选」，填过后改写所填的内容。里面四格：「应用」「对方身份(0x…)」「对方编号」「对方角色」。
  - 填了任一格，前三格都必须有，对方身份必须是 `0x` 加 40 位十六进制；「对方角色」可以空着。
  - 这些字原样写进存证条目，本应用自己不读。
- 「高级选项」折叠，右边写关联的仓库名，没关联时写「未关联仓库」。里面两行：
  - 「关联 Git 仓库」：按「添加仓库」选定一个仓库，记进设置。
  - 读数一行：「已关联,尚未检查」；按旁边的「检查新提交」后是「上次存证后新增 N 个提交」。
- 卡底：左边「选择文件」；右边「取消」和红色的「加入账本」（开了「自动上链」时写「立即上链」）。

按「加入账本」即写入账本并排进待上链队列，卡片关上，提示「已加入待上链,共 N 条」，下面一行「待进入账本手动上链」（离线时为「当前离线,上链前需核对」）。「为谁留证」的几格不合要求时具名拒绝，什么也不写。按「取消」或 Esc 关掉卡片，什么也不写。开了「自动上链」时，写入后直接估算 Gas 费，打开「上链」卡；卡上包括队里所有可发的条目。

**批量存证。** 卡开着时往卡上一次拖进两份以上文件，就成为一批（首页与「记录存证」页的拖放区一次只收一项）：

- 「文件」一行写「已选 N 个文件 · 逐条签入」，旁边「清除」可清空，下面逐行列出文件名。
- 按下后一个文件写一条存证（指纹是文件字节的 SHA-256），「记录名称」写进每一条。提示「签入 N 条,待上链 N 条」。
- 中途有一件失败即停下，已签入的不撤回，提示「签入 N 条后停在第 K 件:文件名 · 原因」；未处理的文件留在表里，处理后可再按。
- 批量里不能夹文件夹：遇到文件夹即在那一件停下。

每签入一个文件（单个文件，或批量里的每一件），这台机器记下当时的文件名和位置，供导出记录包时找原件用；文件夹和 Git 仓库不记。

#### 记录详情

点记录表的一行进入。页题是记录名，下面写「#N · 存证」和上链状态。

**「基本信息」：**

- 「上链状态」：已确认时这一行写首锚区块时刻并打勾；其余情形写状态，链上读到首锚时刻的另起一行「首锚区块时刻」。
- 「条目编号」。
- 「文件」：这台机器签入时的文件名。

「详细信息」里是「内容指纹」「条目 ID」「前一个条目」「大小(字节)」「上链交易」。

**「操作」**（已删除的记录没有这一组），每个动作占一行，整行可点：

- 「现在上链」：还在待上链队列里、尚未发出时才有。
- 「授权给他人」：状态为「已确认」才可点；之前这一行是灰的，鼠标停在上面提示「上链后才能授权给他人」，只有上一次的检查确认过时提示「等待本次确认」。
- 「导出记录包」。

页底是红字的「删除存证」（已删除的记录没有）。

#### 删除存证

按「删除存证」，出确认卡「删除这条存证?」。按「删除」。

- 账本里写入一条「删除条目」指向这条存证；原条目一个字节不动。
- 这件记录此后划掉显示，详情页上注明「已被条目 #N 删除,不能再授权。」，详情页不再出授权与导出的按钮，新建授权也选不到它。

删除条目本身是否上链，看被删的存证有没有公开过：

| 被删的存证 | 结果 |
|---|---|
| 还在队里没发出，或从没上链 | 存证从队里拿掉，删除只记在本地。两条分别显示「已删除」和「本地删除」，提示「已删除存证,不上链」 |
| 已经发出、入块或上链 | 删除条目进待上链队列，像其他条目一样上链；提示「已删除存证,N 条待上链」 |

第一种情形的两条只留在本机。在「设置 > 本机数据」打开「隐藏本机删除的条目」后，「记录存证」与「账本」的列表不再列出这两条；已经上链后才删除的照常列出。这只影响列表显示：条目编号、各处计数、账本检查和详情页都不变，关掉即恢复。

配了网络、账本还没检查过，而这条存证又不在待上链队列里时，删除会被拒：「账本尚未检查。」「点按边栏底部的「同步」。」

条目格式与读法见附录 C。

### 待上链队列

**待上链分段**（「记录存证」工具栏的「待上链 N」）：

- 顶上是搜索格「按条目序号或摘要找」。
- 表列序号、类型、摘要、入队日期和一盏状态灯；空时写「没有待上链的条目」。
- 命令行在「仅加入队列」方式下交给桌面的记录（「设置 > 命令行与 AI 控制」的「命令行上链」）也进这个队列，提示「命令行提交了 N 条记录,已加入队列」。
- 队列随账本与链：账本检查读到链上已有、却还在队里没发出的条目（例如命令行自己送上链的）移出队列、记为已上链，不再重发；账本里链上没有、又不在队里的条目（例如原位收编进来的），在下一趟各节点都答了的账本检查之后补进队列。
- 队里有条目或发过一批时，表下是「本批」卡：估算前写「N 条 · Gas 费待估算」，估算后写「N 条 · Gas 费估算 …」（后面是 gas 数）；按钮「全部上链」和「同步」。发过一批后，多出「上一批」一行（「已上链 N 条 · 移出 N 条」）。已提交的一批若在当前网络设置里找不到那条链的节点，表下提示「有一批已提交,正在等收据;当前没有链 N 的节点,继续不了。」
- 点一行进入详情：页题是条目摘要，下面写「#N · 类型」和上链状态。「基本信息」里是「上链状态」「条目编号」「加入时间」和「同批上链」（「前 N 条」，旁边是「现在上链」；已发出的写「已提交,等待收据」，没有按钮）；链上读到首锚时刻的另有「首锚区块时刻」。「详细信息」里是「内容指纹」（仅存证）「条目 ID」「前一个条目」「大小(字节)」。

**上链步骤：**

1. 按「全部上链」或「现在上链」，出「上链」卡。卡上写「条目」（「前 N 条」）「Gas 费估算」和「Gas 费上限」；估算回来之前两格都写「正在估算」。
2. 每次打开卡都重新估算（之前估过的不沿用）。估算在后台进行，这时「确认上链」显示「正在估算」并转圈，不能按，「取消」可以按（上链期间不可按）。估算完成后，按「确认上链」：签名、发出交易、等待收据；这期间那个键显示「正在上链」并转圈。

一批里的全部条目装在同一笔交易里发出。

**Gas 费上限**按链上的实际费率计算：（基础费 × 2 + 小费）× 这笔交易所带的 gas 额度。额度是节点估出的 gas 数的 1.5 倍（向上取整），最多 20 万；估出的数超过 20 万即拒，不发。基础费取两台节点都已到的最高一块（落后的那台不等），节点之间只比基础费这一项。小费取同一块往前 20 块里各块成交小费的中位数，再取这 20 个数的中位数（中位数为零的块不计，除非全都为零），最高 1 gwei；节点答不出、拒答、两个节点给的不一样或格式不对时按 1 gwei 计。读不到基础费时整组按保底（上限 3 gwei、小费 1 gwei；额度照样按估算定，最多 0.0006 ETH）计，确认卡上的上限即按保底算出，卡上注明「节点未给基础费,上限按保底值」，下一次打开确认卡会再问一次链。答的是别的链的节点不读它的费率，卡上点名。Gas 估算按同样的规则取块（两台节点都已到的最高一块）；各节点估出的数不同时取各节点所答最大的，超过 20 万照样拒。只问这一条链的节点。在 Arbitrum One、OP Mainnet 这两条二层网络上，小费同样按链上实际成交算，通常远低于 1 gwei，所以预留与实付都只有主网的零头。

**发出前的检查：**

- 余额不够付上限时一笔也不发，提示「余额不足。」「需 N ETH,当前 N ETH。」，提示上带「复制地址」，方便去充值。
- 余额按先到的两台节点里较低的那一块链头去问，各节点同时问；两台给出同一个数即成，还在路上的不等，没答或答「还没有」的不计；没有两台一致或节点链高差得太远时不发，提示「节点返回的结果不一致。」。节点答不出余额时不当作零。
- 估算失败时，卡片变成「无法估算 Gas 费」，写出原因，可按「重试」。
- 账本锁着时不能发送。这个数据目录只读（导入的身份还没取回账本，或链上有账本里没有的锚）、账本自己的条目断了链、或账本已交出到另一处时，一笔也不发。发出前还会现读一次链：链上有本机没有的记录时拒绝，提示「账本缺链上的条目」「链上有 N 条记录不在本机:别处有更新的条目,或同一位置另签过一条」。
- 签名之前先问链上这把钥是否已有这一批里哪个哈希的锚。有一条即一笔也不发，提示「这一批里有存证已在链上,这一次一笔也没有发。」「等账本自审读到链上已有的那几条、把它们移出待上链队列,再发其余的。」；没有节点答得出也不发，不靠猜。

**发出之后：**

- 30 秒内入块：提示「已上链 N 条」。收据以两台节点给出同一张为准，其余还说没有的不等，给出另一张的不计；节点表里有两台以上时，只一台给出不算。连发两笔之间，有两台节点的块高到了上一笔收据所在的块即接着读。
- 超时未入块：提示「已提交 N 条,等待确认」，之后每 15 秒再问一次收据。
- 一批在签成之后、广播之前就在队列里记作已提交（带交易哈希与 nonce；详情里写「已提交,等待收据」）。所以关掉再开应用，或发送中途停下，都按哈希接着等那一笔交易的收据，不另签、不重发。
- 收据显示执行失败：提示「交易已发送,但在链上执行失败。」，这些条目留在队里，可以重发。
- 一批等到时限仍未入块，而链上现价（链头那一块的基础费）已经高过它发出时的上限时，账本页顶上账本状态卡的「上一批」一行出现 **「加价重发」**。卡片「加价重发这一批」列「条目」「原来的上限」「链上现价」「重发的上限」，确认后以同一个 nonce 按现时算出的费率重签发出，两项费率都至少比原来高 10%（节点只在这样时才收替换）；原来的与新的都继续盯，先入块的作数。正在查收据时按下，会等这一轮查完再发（「本轮查收据后发出…」）。如果其间费率已涨过卡上显示的上限，重发被拒，重开卡片看新的数。一批至多重发 3 次，之后这一行写「已重发 3 次,不再加价」，继续等它入块。
- 节点池里已没有这一批（多半被挤出了交易池）而它的 nonce 还没被用掉时，「上一批」一行写「这一批已不在节点池,nonce 未用,可按现价重发」，按 **「按现价重发」** 打开同名卡片（「条目」「链上现价」「重发的上限」），以同一个 nonce、按现价和重新估算的 gas 再发一次。重发 3 次的上限同样适用。
- 节点池里没有这一批、它的 nonce 又已被别的交易用掉时，这一批作废：提示「这一批交易已作废:nonce 被其他交易占用,无一入块」，条目退回队列，可以重新发送。

**节点拒绝时的提示：**

- 交易本身被拒：「交易序号已被占用。」「交易已提交,等待确认。」「Gas 费出价过低。」「Gas 上限不足。」「登记合约拒绝了交易。」
- 节点限制或配置：「节点请求受限。」「节点不支持发送交易。」「节点需要访问凭据。」「节点与所选网络不符。」「这一 REST 服务不答这一问。」「这台机器上没有这一 REST 服务的钥匙。」
- 连接问题：「无法连接任何节点。」「节点未在时限内应答。」「节点应答过长。」「节点应答无法解析。」「无法与节点建立安全连接。」
- 其他情形：「节点拒绝了交易。」，节点原话在详情里。

**命令行也发这个队列。** 命令行经桌面（`anchor --home`）与凭凭据（`anchor --ledger`）发的也是这个数据目录的待上链队列，与「全部上链」用同一个发送器、过同一套检查（见第 12 节「一个发送器」）。「经凭据操作」开着时，桌面与命令行轮流拿这个数据目录的写者锁：一批等收据的那一段不拿锁，这时另一方可以写，也可以发队里余下的，它见到这一批在途即不碰、不重发。

**上链状态词**（各页通用）：

| 状态 | 含义 |
|---|---|
| 「待上链」 | 在队里，还没发出 |
| 「正在等待上链」 | 交易已发出，等待入块 |
| 「确认中」 | 已入块，等待账本检查确认 |
| 「已确认」 | 账本检查确认它已锚定 |
| 「已确认 · 上次核 月-日 时:分」（列表里简写为「已确认 · 时:分」） | 本次检查还没回来，照上一次的结论；超过一天变灰 |
| 「已回滚」 | 交易在链上执行失败，留在队里可重发 |
| 「未发出」 | 发出前就被拒（如余额不足），留在队里 |
| 「未上链」 | 不在队里，也没上链 |
| 「已删除」「本地删除」 | 见「存证上链」一节的「删除存证」；详情页的「上链状态」把被删的存证写作「已删除,不上链」 |

需要「已确认」才能做的事（例如起草授权时选记录），只认本次的检查结论。

**自动上链。** 「设置 > 网络」的「自动上链」开关（默认关）：

- 关着：写入账本的按钮写「加入账本」，写入后留在队里等你发。
- 开着：按钮写「立即上链」，写入后直接估算 Gas 费并打开「上链」卡。

这个开关适用于存证、授权、撤销等所有写入。

### 账本内容

左栏「账本」。工具栏右边：

- 「更多」菜单：「添加注记」。
- 分段「全部」「未确认」「授权」。「未确认」列出链上还没确认的每一条：队里的（待发、已发等收据、回滚、被拒），已上链但账本检查还没计入的，以及记下了却没排进队的。它比「记录存证」页按队列计的「待上链」宽。

记录者这一处还没有账本时，表下有蓝色的「创建账本」，按下打开向导到这一步；有账本即不出。

**账本状态卡**（页面顶上）：第一行「账本状态 · 正常/异常」，下面「共 N 条」。第一趟检查之前写「未检查」；节点、链 ID 或登记合约没配齐时写「未检查:尚未配置网络」。

- 有可发的条目时，右边有「全部上链」；还没入队的先排进队列。
- 根条目还没确认上链时，多一行「账本根」，写「根未确认上链」并打红叉。
- 有卡住的一批时，多一行「上一批」，写它的提示并带重发键（见「待上链队列」一节的「发出之后」）。
- 末一行是「账本检查」折叠，右边写检查结论；点开即在卡里展开账本检查。

下面是搜索格「按序号、类型或摘要找」，旁边「开始日期」「结束日期」按首锚区块时刻筛。

**条目表**，最新在上：

- 列为序号、类型、摘要、首锚区块时刻和上链状态。
- 删除条目的摘要写「删除存证 · 记录名」；不合约定的写「删除无效:…」（见附录 C）。

**条目详情**，点一行进入。页题是条目的摘要（存证即记录名），下面写「#N · 类型」和上链状态（被删的存证写「已删除」）。

- 「基本信息」：「上链状态」「条目编号」，写法同「记录详情」；存证另有「文件」。
- 授权：见「授权列表」一节的「授权详情」。
- 「操作」一组，每个动作占一行，整行可点；暂时不能做的那一行是灰的，鼠标停在上面说明原因：
  - 还在队里的：「现在上链」。
  - 没上链也不在队里的：「排进待上链」。已经上链过的条目排不进去：「这一条已经上链了。」「不必再排队。上链状态来自上一次同步,拿不准可先同步一次。」
  - 存证：「用于授权」（已确认才可点）和「导出记录包」；已删除的存证都没有。
  - 已确认的非存证条目：「添加注记」。
- 「详细信息」：「内容指纹」（仅存证）「条目 ID」「类型」「序号」「作者」「前一个条目」「大小(字节)」「上链交易」。
- 没删除的存证，页底有红字的「删除存证」。

### 账本检查

账本检查把本机账本逐条和链上的锚对一遍。它什么时候跑：

- 按「设置 > 通知」的周期自动跑，默认 300 秒；周期为 0 时不按周期跑，只在按「同步」或下一条的情况下跑。
- 这一处账本还没有检查结论，或账本变过（新写了条目、一批上了链）时，立即跑一趟。
- 前提是节点、链 ID 和登记合约都已配置。没配时显示「未检查:尚未配置网络」。

账本检查在账本状态卡的「账本检查」折叠里，折叠右边写结论「通过」「有缺项」或「未通过」。展开后逐项一个记号一个数，两项一行，依次是：

- 「已上链」「尚未上链」「本地删除」「与链上不符」
- 「发现的问题」「已排除」「导入未证实」「无法识别的类型」
- 「格式错误的条目」「无法查询」「未证实」「作废」「弃置」
- 「本地删除」只有读过账本表时才有，灰色，不算警告。

下面是这趟检查的「检查结论」「账本头」「根条目」「核对依据」「条目」「上次检查」。第一趟检查之前，折叠右边写「未检查」，展开后只写「尚未检查;点按「同步」开始」。

- **「正常」的条件**：有检查结论、没断链，且「与链上不符」「发现的问题」「导入未证实」「格式错误的条目」「未证实」「作废」「无法识别的类型」（删除条目以外）都是零。还没上链的条目、「已排除」「无法查询」「弃置」都不算「异常」。移交出去的账本，「与链上不符」只是后继其后写的，状态写「已移交」，下面「后继又写了 N 条」。
- 删除条目在检查里算作无法识别的类型；它们的条数正好等于删除条目数时，这一项显示为绿灯「约定条目 N 条」。
- 「尚未上链」与待上链队列、「提醒」同一判法：删除时还未公开的条目与它的删除记录（本地删除那一对，见「存证上链」一节的「删除存证」）留在本机、不上链，不计进去；它们单列在下一格「本地删除」，灰色，不警示。账本内容还没读出来时没有这一格，「尚未上链」照检查结论的原数。
- 结论为「未通过」（断链）时，整个账本转为只读，页顶挂断链提示条。

#### 注记

「更多」菜单里的「添加注记」，或条目详情里的「添加注记」，打开「注记条目」卡：

1. 写「注记内容」（必填）。
2. 「目标条目」旁按「选择」，在浮卡里搜索（按序号、类型或摘要，也可按首锚区块时刻的日期范围）并点选要注记的那一条；也可以在「高级选项」里「或粘贴条目 ID」。不选即注记整本账，格里写「不关联记录」；浮卡首项「不关联记录」可退回不指某一条。从条目详情打开时目标即那一条。
3. 按「添加注记」即写入。

注记另存为新条目，原条目不变。

### 授权列表

左栏「授权」。工具栏右边是蓝键「新建授权」。

**授权列表：**

- 搜索格「按被授权方、记录或状态找」，旁边「开始日期」「结束日期」按这份授权条目上链的区块时刻筛。
- 表列「记录」「有效期」「授权编号」「状态」，再加一盏上链状态灯。
- 状态按链上时间判断：「有效」「已到期」「未生效」「已撤销」「未知」。带撤销成员的授权写了撤销而链上告示还没读回时，写「未撤(链上未告示)」。
- 有不带撤销成员而仍有效的授权时，表上方出「授权迁移」卡，按「迁移 N 份」把它们各照原样重签一份带撤销成员的新授权（新授权写明替代哪一份），提示「已签新授权 N 份,M 条待上链」。旧授权不撤；撤其中任一份，两份一并算撤。
- 没有授权时写「还没有授权」。

### 起草授权

进入方式：

- 授权列表的「新建授权」：表单清空。
- 记录详情的「授权给他人」，或条目详情的「用于授权」：已预填这件记录。

表单各格：

- **「被授权方」**：粘贴 `0x…` 地址；右边「最近地址」打开一张带搜索的浮卡，列出地址簿和以前的被授权方。
- **「哪一条记录」**：按「选择记录」打开「选择记录」弹窗，上面是搜索格和「开始日期」「结束日期」两格（点开是日历），可按记录名或内容指纹搜，也可按首锚日期筛；下面每行一条记录：条目编号、记录名称、首锚区块时刻（还没上链写「未上链」），已选的那条带勾。点一行即选上并关上弹窗；「取消」或 Esc 关上，不改。只有已上链的记录能选，其余灰着并注明原因：
  - 「上链后才能授权」
  - 「上链中,请稍等」
  - 「等待本次确认」
  - 「已删除」
- **「条款文件」**（必填）：把条款文件拖进来或点选。
  - 选好后显示文件名和大小；「更换」换一份。
  - 文件的 SHA-256 自动填进「高级选项」里的「条款文件指纹」，并注明「已从条款文件填入」。
  - 签发时这份条款文件在数据目录里留一份，之后随授权文件和记录包交给对方，对方可以自己重算指纹核对。
- **「有效期」**：「7 天」「30 天」（默认）「90 天」或「自定义」。
  - 预设按链上时间起算：打开这一页时向当前网络读一次最新区块的时间，以它为起点。读不到最新而手上有上次读到的链上时间时，以那一个为准，卡下的提示条注明「以链上时间 年-月-日 为准,未能读到最新」。一处链上时间都没有时提示「无链上时间,无法使用预设:先同步,或选择自定义」，请先同步或改用自定义。
  - 「自定义」：起始的日期块点开日历选日；下面「起始时间」填时、分（空着即 0 时 0 分；起始日缺省为链上时间的那一天），「时长」填天、小时、分钟（天至多 999，小时至多 23，分钟至多 59，超了那一格标红，原因写在格名那一行）。截止由起始加时长算出，显在右边的日期块上；也可点右边的日期块在日历上选截止日（起始日及其之前不可选），截止落在那一天、与起始同一时分，时长随之填好。时长空着即不设有效期。从预设切到自定义时，各格照那个预设的时段填好。
- **重叠检查**：卡下的提示条写「时段重叠的有效授权:N」，数的是同一件记录上、本机标为独占、时段重叠且未撤销的授权。还没选记录（或自定义时段读不成）时写「选择记录后检查重叠授权」。
- **「独占、转授权与范围」折叠**：
  - 开关「独占授权」：「仅本机记录,签发后不可更改」。独占标记只记在本机，不写进授权；独占的约定应写在条款文件里。
  - 「上游授权(转授权用)」
  - 「使用范围」

被授权方、条款文件指纹、上游三格里的地址或哈希必须全小写。含大写字母时提示「地址含大写字母,改为全小写后再签发」，「确认」不可按。

**签发步骤：**

1. 按页底的「确认」（「取消」回到上一页）。被授权方、记录、条款文件指纹三样齐了才可按，没齐时在键上悬停会写「还差:…」；被授权方填的不是地址时，格上即说「地址为 0x 加 40 位十六进制」；有效期用预设时，还要先有链上时间。
2. 出确认卡「签发授权」：「被授权方」「记录」「有效期」「所附条款文件」（文件名，或「手填的条款文件指纹」）「独占、转授权与范围」「费用」（「上链时计费」；开了「自动上链」时为「下一步估算 Gas 费」），被授权方的完整地址、内容指纹和条款文件指纹在「详细信息」里。
3. 在卡上按「加入账本」（开了「自动上链」时为「立即上链」）即签发，提示「已签发授权,N 条待上链」。之后照「待上链队列」一节上链。

签发前先现读链：本链的撤销合约与换钥簿码对、换钥簿上这一席的现任钥就是这本账的现任钥、换钥已接任，才签；签出的授权带撤销成员（链号与撤销合约地址）。不成即拒签并写明原因：「该链无撤销合约。」「撤销合约读不到或码不符。」「换钥簿地址上的合约不对,没有读写。」「这一席的根钥不在换钥簿里。」「换钥未完成接任。」「换钥簿上的现任钥不是这本账的现任钥。」「现任钥是合约地址,发不出告示。」。根钥不在换钥簿里时，到「身份」页的「世系链」页签在这条链上「入簿」：由根钥在换钥簿上宣告、在任钥接任（根钥须在本机），之后再签。

同一件记录上已有独占授权且时段重叠时，拒绝签发，弹出「独占授权冲突」，列出撞上的授权；按「取消」关掉。撞上的授权若已撤销、而本机还没从链上读回那次撤销（换了机器或从备份恢复之后），先读链再判；每条链的撤销读回各走那条链自己的节点，读回的先记进本机记录，记录写不进时照记录的错拒，一笔不签；链现在读不成时一笔不签，拒因说那几份授权撤没撤还读不到，等网络恢复后再试。命令行答法相同，token 为 `E_GRANT_WITHDRAWAL_UNREAD`。

### 签发前检查

「签发前检查」打开新建授权表单（见上文「起草授权」）。表单占整个页面宽度，没有旁栏，也没有清单。

#### 授权详情

点授权列表的一行进入。页题是记录名，下面一行「#N · 授权」。

**「基本信息」：**

- 「被授权方」「有效期」
- 「上链状态」：已上链写首锚区块时刻；还在队里时写它的上链状态，右边是「现在上链」。
- 「记录」
- 「独占」：「是 · 仅本机记录」或「否」
- 「所附条款文件」：文件名，或「无条款文件」

**按钮**（在「基本信息」下方）：

- **「复制授权码」**：把 `zikaron-grant:…` 授权码放进剪贴板（提示「已复制授权码」）。转授权的授权码带着到根的每一跳，与这份授权的凭证和授权文件里的那一份同一串。
- **「导出授权包」**：打开「导出授权包」卡，卡上写「授权」（#N · 记录）、「带原件」「加密给被授权方」两个开关和「保存位置」（默认数据目录里的 `kits`，按「选择目录」可换）。按卡上的「导出授权包」，写出一份 `grant-<授权条目 ID 前十位>.zkgrant` 文件，同名已有即往后编号。
  - 包里有授权链各跳的条目、条款文件和授权码，清单写签发者账本的根。签发者账本随包的部分：授权带撤销成员时，只带它所名的那条记录（名了才带）和账本的创世、换钥与迁移（含旧法那一段），其余条目一概不带；不带成员时带账本的全部条目。
  - 「带原件」：所授记录的原件随包；本机记下了这件原件才能打开。
  - 「加密给被授权方」：只有被授权方的现行钥打得开。应用按被授权方的根找它的现行钥（本机有其账本即读账本，否则读换钥簿），找不到即不写。
  - 导出前会现读一次链，读不到链时拒绝；链上有本机没有的记录时也拒绝，提示「账本缺链上的条目」「链上有 N 条记录不在本机:别处有更新的条目,或同一位置另签过一条」。
  - 完成提示写明位置、授权链几跳、条款文件几份。

「详细信息」里有被授权方、条款文件指纹和条目的各项机器数据。

再往下一栏是「查看撤销历史」：每份撤销列一行「撤销 #N」及其上链时刻，没有时写「尚无撤销」。还没撤销时，它下面是「撤销授权」。

### 撤销授权

按「撤销授权」出「撤销这份授权」卡：

- 卡上写「记录」「原有效期」「被授权方」；下面一格「裁决文件指纹」，标「可选」。

按「确认撤销」：

- 授权带撤销成员（或是迁移的一对之一）时，先照签发那样现读链核对，再写入撤销条目，由现任钥向撤销合约发一笔告示，读回告示算数才提示「授权已撤销。」。告示没发成或没读回时写「未撤(链上未告示),可重发。」，状态为「未撤(链上未告示)」；再按「撤销授权」只重发告示，不再写第二条撤销条目。
- 不带撤销成员的授权：写入撤销条目，进待上链队列，提示「撤销条目已写入,N 条待上链;上链后他人才读得到。」。

### 记录包

从记录详情或条目详情的「导出记录包」进入，那一条已经选上。

**条目范围。** 「条目范围」一行显示「全部 N 条」（什么都不选即整本）或「已选 N 条」。

- 按「选择」打开「选择条目」：顶上一格搜索和「开始日期」「结束日期」，每条一个开关，可以挑任意几条。「全部」选上搜索与日期留下的那几条，「取消选择」全清；按「确定」采用，按「取消」作罢。
- 所选授权的撤销条目、账本的创建条目和移交条目会自动一并带上，核验方要靠它们认出这是谁的账本。
- 所选里有还没上链的条目时，提示「所选里有 N 条还没上链:包里没有这几条的上链位置」，下面是「现在上链」。

**所选记录的原件。** 列出所选存证当初在这台机器上签入的文件，每行写文件名和条目编号，可以逐件「移除」；移除的不再列出，另有一行「已移除 N 件原件」，按「全部放回」放回来。本机一件都没记下时写「无」，这时把签入时的那份文件或文件夹加进附件即可。

- 原位置已经没有文件时注明「签入时的位置已没有这份文件」。
- 文件被改动过时注明「不是所选记录的原件,不随包」。
- 已删除的记录，条目照样随包，原件不随包，导出前的原件单子与导出后都注明「记录已删除,原件不随包」。

**附件 · 可选。** 按「添加」选文件或文件夹，或直接拖到页上。每项显示在包里的名字（「导出为 files/…」），核对中写「正在核对…」，可以逐项「移除」；两项以上时多一行「清空附件」，按「清除」全部去掉。

- 包内文件名只能用小写字母、数字、`.`、`_`、`-`。不合的名字会自动转写：转小写，一段不合法的字符换成一个 `-`，去掉首尾的 `-` 和 `.`，在扩展名前加 `-` 和原名摘要的前八位（如 `name-1a2b3c4d.pdf`）。
- 改过名时，原名写进清单（`name_md`），取出原件时逐段复原。改名的文件与文件夹，取出时照原名还原。签过的文件夹在清单里是一行，内容是文件夹清单的指纹。
- 转不出合法名的那一行标红「文件名无法转换,请重命名。」，这时不能导出。
- 附件必须是所选记录的原件，其他文件不随包。

**其余设置。** 「附言」写一段附言。「导出为文件夹」默认关：关着导出一个 `.zkit` 文件，打开导出一个文件夹（要发布到网址时用文件夹）。

**锚的证据。** 不加密的记录包导出时，包旁另写一个文件夹 `<包名>.proofs`，一个所锚哈希一份文件、按该哈希命名（`0x…json`）：这本账每条锚的链上证据（块头、交易与回执及它们在块里的证明、发送钥的账户证明）。本机还没有的当场向设置里该锚那条链的节点取，取到的记在本机，下次导出不再取；节点不给整块回执的锚不写。别人读这份包时（核验页核这个包、查看他人账本与核验授权读到这个包或它的发布地址、命令行 `check-grant` 与 `chain-check` 的 `--ledger` 指这个包），包旁有它，就只读这一趟要核的那几条锚的文件，在本机核这些证据，不再为这几条锚问节点；缺的或核不过的照常问节点，读出的结论与没有它时一样。命令行 `scan --basis` 与授权文件里带的账本手里没有包，用不上它。发布到网址时把这个文件夹放在包旁。加密的包不写它。

**加密记录包。** 「启用记录包加密」每次导出都从关开始。打开后「导出为文件夹」变灰：加密只用于单文件记录包。加密后的包只有指定的那把密钥打得开，别人拿到连核验都做不了。

- 「导出记录包」卡上多两格「记录接收方地址」「记录接收方公钥」，填其中一格，另一格即变灰。所填的格合形才能按「导出」：地址为 `0x` 加 40 位十六进制；公钥须是曲线上的点（`0x` 加 66 位或 130 位十六进制）。
- 填地址（对方的根）：导出键里出进度。应用先找它的现行钥（本机有其账本即读账本，否则读换钥簿），再扫本机当前网络和所有已添加的只读网络，找这把钥签过的锚定交易，以交易签名恢复出公钥。经中继或合约发出的锚，签名的不是这把钥，不算。
  - 找到：加密写盘，键上出对勾，稍停后弹窗自动关上，提示「成功导出加密记录包」。这把公钥记在本机，下次导出给同一地址不再为它读链。
  - 各网络都读完，没有这个地址的锚：弹窗关上，提示「导出加密记录失败:该地址未进行链上锚定」，不写任何文件。
  - 没找到，且有节点给的交易证不出自身：弹窗关上，提示「导出加密记录失败:节点给的交易证不出自身,请换一台节点」，不写任何文件。
  - 没找到，且有网络没读成（节点不通、几处节点读数不一致）：弹窗关上，提示「导出加密记录失败:读链失败」，不写任何文件。
- 填公钥：不扫链，直接加密写盘。对方的公钥在他「设置 > 身份密钥」「详细信息」里的「公钥」一行，复制发来即可。从没上过链的人走这条路。
- 加密包的默认名是 `kit.zkit`（不取自内容），同名已有即往后编号，可以改。
- 包头只有格式标、版本和一把一次性公钥，不写接收方的地址或公钥；从外面只看得出它是 ZIKARON 的加密记录包、大致多大、叫什么名字。
- 「本机导出过的记录包」照样记下加密包，记的是加密前那份包的事实，不记接收方的地址与公钥；「删除本机副本」照样删得掉。

**加密的限制：**

- 不是接收方，连核验都做不到：核验页、命令行、AI 应用打开加密包一律具名拒，不留明文。导出方若不是接收方，自己也打不开。
- 接收方解开后仍可以把明文转给别人；加密只管传送这一路。
- 外层加密不证明是谁发的：有接收方公钥的人都能造一份加密给他的包。记录真伪照旧由解开后那份记录包的核验（签名与链上锚）判。
- 没有前向保密：接收方的身份私钥日后泄露，先前发给他的加密包都打得开。直接以地址为接收方必有此代价。
- 签名钥兼作解密钥：同一把密钥既签交易又解密（以太坊节点通信的加密同此用法，没有已知的实用攻击）。若另派生一把加密钥，链上恢复出的公钥就用不上，填地址这一路即断，所以共用。
- 接收方换钥之后，加密给他的根的包封给他的现行钥；换钥前封给旧钥的包，旧钥还在他的密钥库里即打得开。
- 填公钥这一路，公钥是谁的，由导出方经什么渠道拿到它决定；应用只核它是曲线上的点。
- 只经命令行直接裸锚上链（不经登记合约）的地址没有锚日志，扫不到，请走填公钥。
- 交给 GALEED 判官的证据另照 GALEED 的送达法办（明文记录包的文件，以 age 加密给判官公布的钥），不用这里的加密。

**导出。** 按页底的「核验并导出」（「取消」回到上一页），弹出「导出记录包」卡：写着「条目」（N 条）和「保存位置」（默认数据目录里的 `kits`，按「选择目录」可换）。按卡上的「导出」：

1. 先现读一次链。链上有本机没有的记录时拒绝，提示「账本缺链上的条目」「链上有 N 条记录不在本机:别处有更新的条目,或同一位置另签过一条」。
2. 在保存位置写一个 `kit-<所选最早一件记录的指纹前八位>.zkit` 文件（打开「导出为文件夹」时是同名文件夹；所选里没有记录即 `kit`），同名已有即往后编号。单文件按需逐件写进去，没有大小上限。
3. 包先自验，通过才写出，卡随即关上，提示「记录包已导出到 …」，页上显示「记录包已导出 · N 个条目 · N 个文件」，没随包的文件逐个写出原因。

写不成时按原因提示：

| 提示 | 原因 |
|---|---|
| 「无法写入这个位置。」 | 保存位置不可写 |
| 「保存位置已有同名的东西。」 | 同名冲突 |
| 「有文件名无法放进包内。」 | 文件名无法转写 |
| 「包内有两份文件用了同一个名字。」 | 包内重名 |
| 「包没有通过自验,没有保存。」 | 自验失败 |

**包里写明锚在哪里。** 清单写明这本账锚在哪条链（`anchoredOn`：链 ID、登记合约、起始区块，取自导出那一刻这个数据目录的网络；没配网络即不写），并逐条写每个已上链条目最早的那一枚锚（`anchors`：链与交易，取自最近一次账本检查；旧段条目取自旧段的读数）。附言照你写的原文。这两项只是指路：核验时不按它判，只按它提示要添加哪个网络（见「记录核验器」）。

**附旧版记录包。** 账本有旧段时，导出页多一个「附旧版记录包」开关（默认开）：同一处另写一份 `<名>-kit1.zkit`，只载旧段条目及其原件，给还在用 0.1.x 的人读。

**旁栏：**

- 「本机导出过的记录包」：这台机器从这本账导出过的每个包各一行（文件名和导出日期），没有时写「还没有导出过记录包」。点一行打开以文件名为题的卡：
  - 先列「存放位置」「记录包 ID」。
  - 「取处」（标「可选」）：这个包在网上的 https 地址，按格里的「保存取处」存下；文件夹形的包空着即用发布地址加包的路径，单文件的包没有默认取处。
  - 按「删除本机副本」后它变成「确认删除本机副本(账本不动)」，再按即删除本地的包（文件或文件夹），账本不动。「关闭」关上卡。

## 8 · 使用方

#### 一条完整的走法

**以使用方身份**（左栏顶上选「使用方」）：

1. 第一次打开应用时，向导按记录者走：设口令、建身份、选网络、创建账本（免费，只写本地），其余可以以后再做。
2. 在左栏顶上切到「使用方」。使用方的账本只在转授权时才需要，到时在转授权页按「创建账本」即可。
3. 在首页「核验一份授权」卡里贴入对方发来的授权码，按「开始核验」，看结果。
4. 到「我的授权」按「添加授权」，贴授权码或拖入授权文件，按「核验并添加」，把它收进库里。
5. 收到作品文件后，到「核验 > 核验授权」，把授权、文件和条款文件一起放进去，按一次「核验」，三件一起核对。
6. 看「提醒」页：授权快到期、被撤销、签发者账本被移交，都会在这里出现。

#### 首页（使用方）

- **左上「核验一份授权」**：贴授权码，按「开始核验」，转到「核验授权」看结果。
- **右上拖放区「拖入记录包以核验记录」**：拖入或点选记录包，转到「核验记录」并立即核验。
- **三格**，整格可点：

  | 格 | 显示 | 点它去 |
  |---|---|---|
  | 「需要处理」 | 复核过而没全部通过的授权份数 | 我的授权 |
  | 「有效授权」 | 在有效期内的授权份数，下面「N 个签发者」（库里全部授权的签发者数） | 我的授权 |
  | 「核对收到的记录」 | 上一次授权核验里文件是否「相符」 | 核验授权 |

  - 本次还没复核时：「需要处理」照上一次的结论显示，并注「上次核 月-日 时:分」；「有效授权」显示持有的总份数，注「未核验」。还没有一次存下来的判定时，「需要处理」是「--」，注「尚未读取」。
  - 「核对收到的记录」只看这一次运行里的授权核验：还没核过，或核验时没放文件，显示「--」。
- **「最近」**：这一次运行里的授权核验和记录核验结果、撤销监测提醒，以及有转授权等着上链时的「待上链 N 条」，点一行进对应的页面。没有时写「暂无活动」。

### 授权库

左栏「我的授权」。工具栏：分段「全部」|「按签发者」、「重新核验」、蓝键「添加授权」。表格上方有搜索框「按记录、签发者或判定找」，以及「开始日期」「结束日期」两格，按每份授权的上链时刻筛选。

#### 添加授权

「添加授权」对话框：

- 在「授权码」格里贴入授权码；或按左下角「选择文件」选授权文件，也可以把授权文件直接拖到卡上，文件名显示在「授权文件」一行（没选时写「未选择」）。授权码若带着转授权链，链上各跳一并收下。
- 选了授权文件时，当场在「授权码」格名那一行显示「… 已验证 · 授权链 N 跳 · 条款文件 M 份」；读不成时那一格描红，同一处写原因。
- 贴授权码时提示：授权码不带签发者账本，只能核验签名和有效期；要完整核验，请让签发者导出授权文件。
- 可选「授权备注」「签发者备注」，只存本机。备注只记在这次添加的那一份授权（转授权链的最末一跳）和它的签发者上，链上更早几跳的签发者不受影响。签发者备注按签发者地址记，这位签发者的每份授权都显示它。

按「核验并添加」：

- 先核验签名和格式；任何一份不通过，这次一份也不收，对话框不关，写出原因。
- 库里已有且完全相同的会跳过；全部都已在库里时提示「该授权已在「我的授权」中。」，对话框不关，什么也不留。
- 同一份授权的新包（签发者账本比库里那一份更长，或带着这份授权的撤销）会换下库里那一份，提示「已收下这份授权的新包」；此后核验读新包。
- 授权文件会在数据目录里留一份，其中的签发者账本以后用于核验。

#### 每份授权

每份授权一行：「记录」「签发者」「有效期」「首锚区块时刻」（这份授权在签发者账本里的上链时刻，还没读到时写「上链时间未读取」）「判定」。

- 判定有「全部通过」「有缺项」「未通过」「已被撤销」。
- 本次还没复核的，显示上一次的判定并注「上次核 …」，超过一天变灰。
- 从没复核过写「未核验」；复核正在走写「核验中」。这一趟没读成链（没配节点、读不到链、读不到链上时间）而只缺这些的，不算一次判定：照旧显示上一次的判定，没有上一次即「未核验」，也不存下。
- 库里有读不成的文件时，页面顶上逐份注明「未通过的文件:…」，并写「未添加。可联系对方重新发送。」。

点一行进入详情。页题是记录名，下面一行是签发者：

- **状态提示**（在页题下）：
  - 被撤销：「签发者已撤销这份授权。」「由它派生的转授权同时失效。」
  - 有缺项：哪一处都没找到签发者账本时，提示缺少签发者账本；其余缺口（包括读不到链、没配节点）一律提示「这份授权还未确认上链:几分钟后再核验。」
  - 签发者账本已移交：「签发者账本已移交给新密钥」。
  - 复核时没读成的网络，逐个写出名字和「不通」或「指纹不符」。
- **「基本信息」**：
  - 「签发者」「有效期」「首锚区块时刻」
  - 「剩余」：如「N 天后到期」，按链上时间计算
  - 「上游」：「无(签发者即作者)」，或上游那一份授权
- **「凭证」**：一行「生成凭证」，右边是同名的键（见「凭证」一节）。本次运行复核过且六项核验全部通过时，下面另有「转授权给他人」。
- **「上游账本目录」**：写已记下的目录或「未设置」。右边「更换目录」打开「上游账本目录」卡：按「选择目录」选好「文件夹」，按「保存上游」记下；已有目录时「文件夹」一行右边「清除」把它去掉。
- **「详细信息」**：签发者地址、「授权给」、条目 ID、条款文件指纹、内容指纹、记下的上游账本目录、判定与六项原始结果。旧法授权与续接账本的授权卡上写「待定」，首锚区块时刻写「未读」，注「旧法授权:在「核验授权」里审计后才能判定。」；重开或解锁后、复核跑完之前，照上次核的结论仍写「待定」。

#### 重新核验

「重新核验」逐份复核整个库：

1. 找签发者账本，先在本机找，再在保管库里找（收下的授权文件带来的账本，以及「保存上游」记下的目录）。
2. 扫链（日志照旧全读，只检验各份授权所依的那几条锚），更新每张卡片的判定，并记下这次的结论。卡上不出签发者账本的状态与条目数，也没有审计键。读的是主网络，再加设置里全部「只读网络」；没读成的网络在授权详情上写出名字，只可能落在它上面的锚不算缺。链上时间只从主网络的节点读：没有主网络节点时「在有效期内」无法判定，授权一直是「未核验」，也不会出「转授权给他人」。

复核也会在每次同步时跑，并按「设置 > 通知」里的「授权核验周期」自动跑（默认 600 秒；空着或填 0 即仅手动）。前提是主网络的节点、链 ID 和登记合约都已配置。

### 上游账本

「我的授权」工具栏的分段切到「按签发者」，按签发者分组，签发者账本断链的组排在最上。组头写签发者名字和「最近上链 N 天前」（或「上链时间未读取」）。还没复核过的单列一组「未核验」，注「重新核验后才能按签发者分组」。

### 凭证

凭证是给第三方（例如你的顾客）看的授权证明，是一份文本和一张二维码。在详情的「凭证」一栏按「生成凭证」，出「生成凭证」卡（「保存位置」默认数据目录里的 `kits`，按「选择目录」可换），按卡上的「生成凭证」：

- 需要已配好网络，并现读一次链；链上有本机没有的记录时拒绝，提示「账本缺链上的条目」「链上有 N 条记录不在本机:别处有更新的条目,或同一位置另签过一条」。
- 应用从库里把授权链一直接到根，在保存位置建一个 `badge-<授权 ID 前十位>` 文件夹，里面有 `badge.txt` 和 `badge.svg`（二维码）。
- 「生成凭证」一行下注「凭证已生成」，列出「授权链」（N 跳）、「文本文件」「二维码图片」，旁边是二维码。

对方在「核验 > 核验授权」贴入文本即可核验。

### 起草转授权

**入口。** 本次运行复核过、六项核验全部通过的授权，详情上有「转授权给他人」：

1. 出确认卡「转授权」：写「记录」「签发者」「上游有效期」。
2. 按「起草」进入转授权页。这一步还不写任何东西。

**转授权页。** 上半写上游授权的信息，下半是与「起草授权」相同的表单：

- 记录固定为上游的那件。
- 有效期不会自动按上游封顶，请自己留意。
- 按页底的「确认」，出确认卡「签发转授权」（「详细信息」里多一行「上游」），在卡上按「加入账本」（开了「自动上链」时为「立即上链」）即签发。

转授权写进你自己（使用方）的账本，进你自己的待上链队列。签完后表单下出现「去上链」和「待上链 N 条」。

**前提。** 转授权需要使用方有签名密钥和账本：

- 没有密钥：页面提示「尚未生成密钥。」，按「生成密钥」。
- 没有账本：提示「还没有账本。」「先开账,再转授权。」，按「创建账本」。

### 撤销监测

每次整库复核之后，应用检查两件事：

- 你持有的某份授权是否已被撤销（带撤销成员的授权读它所写那条链上的撤销告示，复核时现读；不带成员的读签发者账本）。
- 签发者账本是否移交给了新密钥。

发现其中之一时：

- 窗口向系统请求一次注意（macOS 上程序坞图标会跳动），并出一条提示「提醒:我的授权已被撤销」或「提醒:签发者账本已移交给新密钥」。一次复核发现好几件时，提示写第一件，再加「另有 N 条提醒,见「提醒」」。
- 「提醒」页末尾加一行红灯「撤销监测」，链接到我的授权。

同一件事只提醒一次，重启应用也不再提醒；账本又移交给另一把新密钥，算新的一件，会再提醒。首次启动向导开着时，既不弹提示，也不请求注意。

## 9 · 核验

左栏「核验」。两种角色都有「核验记录」「核验授权」和「查看他人账本」三个标签，从左栏进去落在「核验记录」。首页与整窗拖放的去处仍按角色分：记录者拖入的文件进「新建存证」，使用方拖入的进「核验记录」。

核验不发交易。会写进本机的有三样：地址簿的增删，「存快照」写出的快照文件，和「核验记录」写出的核验结果档（见「记录核验器」）。

### 授权核验

一次准备好三样，按一次「核验」：

1. **「授权码」**：贴进「粘贴收到的授权码」一格，或按格里的「选择文件」选授权文件。
2. **「文件」**（标「可选」）：按「选择文件」选收到的作品文件；把文件拖到窗口上时，这一行变成「拖入或选择文件」的落点。
3. **「条款」**（标「可选」）：同上，选条款文件（「拖入或选择条款文件」）。

没选时写「未选择」；选了显示名字和大小，旁边「更换」「移除」。没贴授权码时「核验」不可按，写「粘贴授权码后开始核验」。

**「高级选项」**（右边写「签发者账本 N 跳」）：

- 「第 1 跳」「第 2 跳」…：授权链每一跳一行，按「选择目录」手动指定签发者账本的目录；「添加下一跳」即选下一跳的目录。
- 「核验用节点」（标「可选」，每行一个）、「核验用登记合约」（标「可选」；不成形即格红、说形，「核验」灰着说同一句）、「核验起始区块」：预先填着设置里主网络的值，可以改；只决定主网络。
- 「核验时间点(秒)」（标「可选」）：空着即按链上时间。

**读哪些网络。** 核验读主网络，再加设置里全部「只读网络」；只配了只读网络、没配主网络时照样核，不报「未配置节点」。没读成的网络逐个写出名字和「不通」或「指纹不符」；这时没找到锚的「上链已确认」灰灯写「暂时读不到链」，下一步是「暂时读不到链:稍后再核验。」，不写「未确认上链」，因为锚可能在没读成的那条链上。

**签发者账本从哪里来。** 应用按以下顺序自动查找：

1. 本机：同一台机器上签发者的账本。
2. 保管库：收下的授权文件带来的账本，以及记下的上游目录。
3. 记录包：你指定的记录包或授权文件，以及正在核验的授权文件自带的账本。
4. 发布地址：签发者公布的 https 地址，逐个文件取回并通过包验证后才用。

结果下面「账本来源」一组，每一跳一行「账本来源:本机/保管库/记录包/发布地址」，一处也没找到写「账本来源:无」。

- 这一行右边是「更换」，没找到时是「添加」。按下出一格「签发者账本」（格里提示「https 地址、记录包、账本目录或授权文件」），可以给一个 https 地址、记录包、账本目录或授权文件：按格里的「选择文件或文件夹」选好即重新核验，手填的按回车重新核验。这一跳的账本取自本机且六项都通过时，没有可补的，不出这个键。
- 取自发布地址时，下面一行写「来自 https://… · N 个文件 · 已验证」，旁边「重新获取」。
- 哪一级读不成，都会逐级写明原因：「…读不成:…」。

**结果卡**头一行是结论，下面是记录名，再下面三格「授权方」「有效期」「首锚区块时刻」（多跳时都是最末一跳的）：

- 「全部相符」（绿）：授权六项全部通过，提供了的文件和条款都相符。没提供的不影响这个结论。
- 「N 项不符」（红）：授权未通过，或文件、条款不符，每样算一项。
- 「未全部核成」（黄）：没有不符，但授权有缺项，或文件读不出。

- 「未能判定」（黄）：旧法授权或续接账本的授权，只读这一趟检验的锚判不了，等审计；首锚区块时刻写「未读」。审计出了结果，页头、六项与首锚区块时刻照审计的判定写；审计中或读不成时仍是「未能判定」。

「有缺项」永远不等于通过。

结论只读这一趟检验的锚（日志照旧全读，只检验六项所依的那几条），与整本审计的判定相同，不出签发者账本的状态与条目数。**「账本审计」**一组一行「整本账本」：没审计时写「未审计」，右边「审计」；按下在后台读整本账本，逐条取证，这时写「审计中」，前台有读链时它先让开；读完写判定、「账本状态」与条目数、「审至」（时刻与区块），右边「再次审计」。审计结果按根、基底与账本副本记在本机，再核验同一份授权时直接显示。读不成时写「读不成」与原因，可再按。

**「六项核验」**一组。头上先列说得比结论多的几行：

| 行 | 何时出现 | 显示 |
|---|---|---|
| 「授权」 | 授权没有全部通过时 | 「有缺项」或「未通过」；标签「待定」或「无效」 |
| 「文件」 | 提供了文件时 | 文件名，读不出时写原因；标签「相符」「不符」或「读不出」（与授权指向的作品哈希比，多跳时比最末一跳） |
| 「条款」 | 提供了条款时 | 同上（与授权记录的条款指纹比） |

接着按缺口各给一句下一步，例如「缺少签发者账本:给出记录包、账本目录、授权文件或 https 发布地址后再核验。」「这份授权还未确认上链:几分钟后再核验。」；没配节点时是一行「未配置节点」，右边「前往设置」。这一次没读成的只读网络逐个写名字和「不通」或「指纹不符」，读不出的文件逐个写名字和原因。

然后是六项，每项一行一个记号：

- 「授权签名」「签发者账本完整」「在签发者账本里」
- 「上链已确认」「在有效期内」「未被撤销」

授权带撤销成员时，「未被撤销」只问链：签发者在任钥在所写链的撤销合约上发了这份授权的撤销告示即未通过，没有即通过；账本里的撤销条目不算。在任与否按那条链上的换钥簿判。不带成员的授权照签发者账本判。

没能核成的项是灰的，旁边注明缺什么：「缺少签发者账本」「签发者账本读不成」「未配置节点 · 前往设置」「暂时读不到链」「未确认上链」「读不到链上时间」；带撤销成员的授权读不成所写链的告示时，写「告示未读」、链号与原因（例如节点表里没有该链的节点）。

**转授权（多跳）。** 每一跳的六项在一行「第 N 跳 · … 签发 · 判定」下面，各跳之后每一处衔接一行「第 N 跳接上第 N+1 跳」。

结果下面的**「详细信息」**里有最末一跳的授权方、被授权方和作品地址、判定、「所读链段」与「告示链段」（带撤销成员的授权才有）、每项核验的原始结果、每份读不出的文件的原因，以及「等价动词」：做同一项核验的命令行动词（单跳为 `check-grant`，多跳为 `chain-check`）。

### 核对收到的记录

收到作品文件后，在「核验授权」页的「文件」一格放入它，与授权一起按「核验」：应用算出文件字节的 SHA-256，与授权指向的作品哈希比（多跳时比最末一跳）。结果卡「文件」一行显示「相符」或「不符」；「详细信息」里并排写字节数、实算摘要和应为摘要。作品必须是单个文件：放入文件夹会被拒，这一行写「读不出」。换了文件要再按一次「核验」。使用方首页的「核对收到的记录」格显示上一次的结果。

### 记录核验器

左栏「核验」的「核验记录」标签（两种角色都有）。

把记录包（`.zkit` 文件或文件夹）、授权文件或单个记录文件拖进「拖入记录包或记录文件」，或点按选择；单文件的包逐件读出再核，没有大小上限；放入即核验。发布地址拖不进来，填在「高级选项」的「记录内容」里，按「立即核验」。

**加密记录包。** 放入加密记录包时，应用以本机的各个身份逐个试开（每个身份的两种角色各一把钥）。有一个是接收方即解开，照常核验，接着可以取出原件；都开不了即拒「这份加密包不是给本机身份的」；包被改过、截断或换过段序时拒「加密记录包已损坏或不完整,没有解开」。解开只用私钥算，不签任何东西，不花 gas；失败时不留任何明文。加密授权包在「核验授权」「添加授权」照样以本机身份解开、当授权包读。在他人账本、尽调、授权核验等别处放入加密记录包，提示「这是加密记录包,请在「核验记录」打开」。

**「高级选项」**（右边写填了的记录哈希，没填写「无」）：

- 「记录内容」：本地文件或目录，或 `https://` 发布地址，拖入的也显示在这里；填 `http://` 等别的地址时，那一格描红，格名那一行写「仅支持 https 地址。」。
- 「记录哈希」（标「可选」）。
- 「立即核验」：按「记录内容」再核一次。

**结果卡**头一行是结论：有不符时「有 N 处不符。」；没有不符而核的是记录包时，「记录包完整,签名有效」或「记录包校验未通过:…」（后接出问题的文件名）；否则「全部相符」。取自发布地址时，结论下面写「来自 https://… · N 个文件 · 已验证」，右边「重新获取」；核的是本机的记录包、授权文件或加密记录包时，右边是「取出原件」（见下）；单个文件没有这个键。

结论下面只列没达到的几行：

| 行 | 可能的显示 |
|---|---|
| 「记录包」 | 有不符且记录包校验未通过时：「记录包校验未通过:…」 |
| 「上链状态」 | 读不到链（包括没配网络）、有网络没读成时「未与链上比对」；包写明的网络没添加时「未添加」 |

上链只核包里各条记录自己的锚：节点上的日志照旧全读，只检验所称哈希是包里各条条目号的日志，不读签发者整本账本，所以不给签发者账本的检查结论，也不给「N 条未上链」一类的总数；各条的上链状态在下面「逐条记录」里。这一页没有「审计」。记录包带着授权时，那份授权照「核验授权」的快速核验判；定不了（旧法授权、续接账本）时写「未能判定」与「待定」，去「核验授权」按「审计」判。

**不符：**

- 有不符时，卡上另有一句「查看错误详情,与对方核实后再接收。」，逐处明细在「详细信息」的「不符」里。以下各算一处：记录包校验未通过、包里有不合格式的文件、条目文件读不出或签名不对、记录未上链、填了记录哈希而账本里没有这件记录。
- 链没读成也算不符：读链失败算一处，没读成的网络里每件记录各算一处。所以包写明的网络没添加、没配网络或节点不通时，包再完整，结论也是「有 N 处不符。」。


**逐条记录。** 核验的是记录包、授权文件或发布地址时，下面有「逐条记录」一组，包里每件记录一行：左边是记录名（没有名字写「未命名记录」），右边是上链状态「已上链」「未上链」或「未读链」。重算原件指纹与记录不符时，名字下面写「包内原件 ✗」；包里没有原件时写「包内原件 缺」；相符时不写。包里的账已删除的那件，右边写「已删除」，名字下面写「被条目 #N 删除」（照附录 C 读删除条目，无效的删除不算）；账给某件记录加的注写在那一行下面。

**包写明的网络没添加时。** 记录包写明锚在哪条链（见「记录包」），而那条链连同登记合约既不是主网络、也不在「只读网络」里时：

- 包照核，上链不核，「上链状态」一行写「未添加」，逐条记录的上链状态是「未读链」。
- 卡上一行：链名，「作者自述 · 请在设置中添加网络」，右边「添加」。按「添加」会转到「设置 > 网络」，打开新只读网络的弹窗，链 ID、登记合约、起始区块已经填好，节点自己填。

**读了哪些网络。** 有网络（只读网络，或配了只读网络时的主网络）这一次没读成的，卡上逐个写出名字和「不通」或「指纹不符」。这时在读成的链上找不到锚的记录，上链状态是「未读链」，不写「未上链」，因为它的锚可能在没读成的那条链上。「详细信息」里有：
- 核验对象、条目数、未通过的条目
- 记录包的结论、「已读网络」（这一次读成的网络名）
- 记录哈希、记录包 ID 与判定
- 「链 ID」「登记合约」，以及「首锚位置」：每件记录首锚的时刻、区块号与交易号，交易号写全
- 这次结果档的路径在「结果档」里，写不成时写原因

**取出原件。** 「取出原件」在结果卡结论的右边，只在核的是本机的记录包、授权文件或加密记录包时出现：单个文件没有它，取自发布地址时那里是「重新获取」。记录包核验通过、且有与记录对得上的原件时可按（授权包里与所授作品对得上的原件同算）；否则不可按，并写明原因（「记录包没有通过核验」「没有与记录对得上的原件」）。按下出弹窗：

- 「取出到」一行是目录：本次运行里上次用过的，否则是文稿目录。左下角「选择目录」经系统框改；右下角「取消」与「确认取出」。只有按「确认取出」才写盘，在后台进行，写完提示「已取出 N 份原件」。
- 弹窗列出「将取出」的原件名和件数（「N 份原件」）；与记录对不上的按名列出，写「与记录对不上,不取」；包里没有的写「包里没有,不取」。
- 对得上的判法：单个文件，字节的 SHA-256 等于记录所证；签过的文件夹，按签名时同一算法重算目录摘要等于记录所证，整个文件夹照原样取出；早先版本在 Windows 上签的文件夹（路径以 `\` 连）也认得出。取出时重新读包、重新判，不用核验时的结果。
- 名字：照包里的原名对照表还原原名。原名不是一个合法的单段文件名（带路径分隔、`.` 或 `..`、控制字符、系统保留名）时用包内名，弹窗里写「原名不能作文件名,用包内名」。包内路径不合记录包的格式即拒：「记录包里有不合记录包路径形制的路径,没有取出。」。两份原件要取成同一个名字（不分大小写）时整批拒：「有两份原件要取成同一个名字,没有取出。」。
- 所选目录里已有同名的，整批不取，一个字节也不写，提示「所选文件夹里已有同名的文件或文件夹,没有取出。」并说出是哪几个。所选的不是文件夹时拒：「所选的不是一个文件夹,没有取出。」。所选目录里那个名字是链接时拒：「所选文件夹里这个名字是一个链接,没有取出。」，绝不顺着链接写到所选目录之外。逐份核对时指纹与记录对不上，提示「取出的原件与记录对不上,记录包可能在取出时变了,没有取出。」；写盘失败，提示「写盘失败,已撤回,没有取出。」。
- 先全部写进所选目录里的一个暂存目录、逐份核对指纹，再逐份换名就位；中途任何一步失败，已就位的撤回、暂存删净，所选目录回到取出之前的样子。
- 加密记录包解开后同样可取。

**核验结果档。** 每核一个记录包、授权文件或发布地址，就在机器目录的 `kits/verified/` 里写一份结果，文件名是 `0x<包清单文件的 sha256>.json`，再核整份替换。

- 写的是：核验时刻；包的判定；包清单的指纹；每件记录的内容指纹与最早那一枚计入的锚（链 ID、登记合约、区块、时刻、交易）；这次读成的各条链与窗。包不成立时只写判定。
- 包不成立也写；包成立而这一次一条链也没读成时不写（包写明的网络没添加、没配网络、节点都不通）。
- 这份档不加密，是给别的应用读的。ZIKARON 自己不读它，它也不改任何判定。

### 他人账本

左栏「核验」的「查看他人账本」标签。

填「作者地址」（格里右边「地址簿」可选），按「读取」：按「授权核验」一节的四级顺序找它的账本内容，读出账本副本里的条目与身份，并读对方的面表；这一步不扫链核锚。账本状态、条目数、各条的上链状态与首锚时刻、历史授权的撤否、尽调的结果，按页上「账本审计」一组的「审计」后才有：审计在后台读整本账本（逐条取证），给前台动作让位，没出结果时写「审计中」，出了结果写「账本状态」（结论与条目数）与「审至」（时刻与区块），右边「再次审计」；读不成时写「读不成」与原因，右边「再次审计」。结果留在本机，再读同一份副本时读回。要先配好主网络（只配了只读网络时不读）；配了只读网络的，在主网络之外一并读。改了作者地址或记录内容而还没按「读取」时，下面的结论撤下。

- 「高级选项」里的「记录内容」（标「可选」）可以给出记录包、授权文件、账本目录或 https 发布地址，也可以按格里的「选择文件或文件夹」选（系统对话框只能选文件的平台上写「选择文件」）。
- 「读取」旁边，地址不在地址簿里时是「存入地址簿」，在时是「从地址簿移除」；只影响本机的地址簿。

**「概览」**头一行审计前写「未审计」，审计后是账本检查的结论，下面写「作者地址」，审计后加「· N 条」（条目数）；没有账本内容时，审计前写「未取得」，审计后写「仅有上链存证,无账本内容」。再下面三格（「最近上链」审计后才有，此前写「未审计」）：

| 格 | 显示 |
|---|---|
| 「记录数」 | 不含已删除的记录 |
| 「历史授权」 | 授权份数 |
| 「最近上链」 | 最近一次上链的日期与条目号（「日期 · #N」） |

- 账本从哪一级取到写在「详细信息」的「账本来源」里，审计后另有「检查结论」。有哪一级读不成或四级都没取到时，概览上另起一行「账本来源:…」，读不成的那几级逐个写明原因（「…读不成:…」）。
- 四级都没找到账本时写「未取得账本内容:提供记录包或发布地址」，记录数和授权数写「未取得」，不写 0。
- 再往下是「历史授权」一组，每份授权一行：记录名，右边是首锚区块时刻（审计后才有）和有效期（一份也没有时写「还没有授权」）。审计后，带撤销成员的授权没读定撤没撤时（告示读不成、告示未算数、告示输入不适用），那一行多一句「撤否未定:…」，写明哪条链、什么原因，不当作未撤。

**「条目列表」**逐条列出对方账本副本里的条目，点一行看只读详情；各条的首锚时刻与上链状态审计后才有，副本里有而链上没找到它算数的锚的一条写「未上链」。删除条目的读法与本机相同（附录 C）。审计时有网络没读成，「概览」里逐个写出它的名字与「未读链」；读成的链上找不到锚的条目是灰灯，点开详情「上链状态」写「未读链」，不写「未上链」。

### 尽调

使用方在「查看他人账本」这一页做尽调：「高级选项」里多几样：

- 「记录哈希」（标「可选」）
- 「所需有效期」（标「可选」）：「起(秒)」「止(秒)」
- 「存快照」（见下）

审计后，概览下面多一组「授权冲突检查」：检查你所需的期限是否与对方已有的有效授权重叠。要同时填「记录哈希」和「所需有效期」才检查；缺记录时写「未填记录,未检查」，缺期限时写「未填期限,未检查」。

- 重叠时红：「N 份有效授权与所选期限重叠」
- 没有确定的重叠，但有撤否未定的授权与所选期限重叠时，不红不绿：「N 份撤否未定的授权与所选期限重叠,未能判定」
- 不重叠时绿：「无有效授权与所选期限重叠」

审计后，页底「详细信息」里另有「密钥沿革」（对方账本从第一把钥起依次用过的钥）与「换密钥或移交」：对方账本每换一次密钥、每移交一次，在后一行里各占一条，写出条目序号、是换钥还是移交、交给哪把钥。

「存快照」打开同名弹窗：「快照存放位置」是本次运行里上次用过的目录，否则这个数据目录里的 `kits`，否则文稿目录；左下角「选择目录」可改，右下角「取消」「存快照」。按「存快照」把上一次尽调审计的结果（先按「读取」再按「审计」）写到那里，文件名 `snapshot-<地址前十位>.json`。审计结果是这次启动之前存的、全本不在手里时，键灰着，悬停说「再点按一次「审计」读取全本。」。快照不能作为凭据。

## 10 · 提醒

### 提醒事项

左栏「提醒」。只列需要处理的事，每行一件：一盏灯（黄或红）、事项和现状。「待上链」「队列积压」两行右边有「全部上链」，按下即发出能发的全部；其余每行整行可点，点了即转到该处理的页面，并打开相关的部分（例如账本检查卡、按签发者分组）。没有要处理的事时，卡里只有一个勾和一句「没有需要关注的事」。

| 记录者 | 使用方 |
|---|---|
| 「待上链」 | 「我的授权即将到期」 |
| 「队列积压」 | 「授权被撤销」 |
| 「授权即将到期」 | 「账本移交」 |
| 「账本检查结论」 | 「上游异常」 |

- 「待上链」和「队列积压」说的是同一件事时，合并为一行。
- **「授权即将到期」**和**「我的授权即将到期」**数的是七天内到期的授权，只按链上时间算；「我的授权即将到期」也数已过期的（这时是红灯）。没有链上时间的不算进来，不猜。
- 整机备份不在这一页：它的状态见「设置 > 本机数据」的「上次备份」，以及「关于」页「设置检查」的「整机备份」一行。
- **「授权被撤销」**是红灯，**「账本移交」**是黄灯。
- **撤销监测**的提醒排在表末，每件一行：名为「撤销监测」，红灯，写「我的授权已被撤销 · 记录名」或「签发者账本已移交给新密钥」，点了到「我的授权」。它们只在发现的那一次运行里列出（「授权被撤销」「账本移交」两行也只数这些）；重启应用后不再列出，被撤销的授权在「我的授权」里仍标「已被撤销」。
- 左栏「提醒」旁的数字，数的是这一页的行数。
- 已入块的条目，账本检查一直没读到它已锚定时，每 15 秒再读一次链；十分钟后停下不再自动重读，这一页多一行「账本检查结论」（黄灯），写出是哪几条、之后还会不会自己再读（周期自审开着即照读）。其后任何一次账本检查读到它已锚定，这一行即消失。
- 上一次读链失败的原句在「详细信息」里。

**提醒怎么通知你。** 发路是窗口注意请求加吐司。下列事项新出现时，窗口向系统请求一次注意，并出一条提醒提示：
- 记录者：「授权即将到期」，以及「账本检查结论」为断链时；
- 使用方：「我的授权即将到期」（含已过期）、「上游异常」，以及撤销监测。

提示写「提醒:」加这一行的名字，适用时后面再写所涉的授权或签发者；撤销监测写「提醒:我的授权已被撤销」或「提醒:签发者账本已移交给新密钥」。同时来了好几件时，写第一件，再加「另有 N 条提醒,见「提醒」」。其余黄灯、红灯（例如「待上链」「队列积压」）只在本页和左栏数字里显示，不另行提醒；整机备份不提醒。首次启动向导开着时不弹提示。

- 同一件事只提醒一次，提醒过的记在数据目录的设置里。情况变了（期限变了、账本在别处断了、上游账本有了新条目）算新的一件，会再提醒。
- 网络错误不提醒，只在状态行显示「同步失败」。
- 设置里没有关闭通知的开关。

## 11 · 设置

左栏「设置」打开设置首页，列出八项，点一项进入那一页。两种角色的设置项相同。

| 项 | 内容 |
|---|---|
| 「语言和时间」 | 界面语言与时区 |
| 「外观」 | 浅色、深色或跟随系统 |
| 「身份密钥」 | 身份、口令与密钥备份 |
| 「网络」 | 节点、登记合约与发布地址 |
| 「通知」 | 账本检查或授权核验的周期 |
| 「本机数据」 | 加密、备份与数据目录 |
| 「命令行与 AI 控制」 | 终端与 AI 代理自动控制 |
| 「关于」 | 版本与设置检查 |

**设置存在哪里：**

- 外观与最后选的语言：存在这台机器上，对所有身份生效，口令门上也用。自动锁定、上次整机备份的记录、「只读网络」「代理」「命令行上链」与命令行的两个开关也存在这台机器上，所有身份共用；其中除「只读网络」外都加密，开锁后才读（见附录 B）。向导里最后选的网络也记在这里，但只决定新建身份时默认选中哪一项；每个身份用自己的网络。
- 其余设置：存在当前数据目录里。没有数据目录或只读时改不了，页面不变并提示原因。

#### 11.1 语言和时间

- **「语言」**：「中文」或「English」。选择记在这台机器上（口令门与首次启动向导用它；首次启动向导上也能切换）；开着数据目录时，也记进那个数据目录的设置；只读的数据目录拒绝这次更改。
- **「时区」**：「跟随系统」（默认）或「UTC」。窗上的时刻都照这里的时区写，不另带时区标。
  - 窗口里所有时刻都按它显示。完整的写法是 `2026-09-24 23:46:12`，位置窄的地方只写日期或「月-日 时:分」。
  - 读不出系统时区时提示「读不出系统时区,时刻按 UTC 显示」。

#### 11.2 外观

「浅色」（默认）、「深色」或「跟随系统」，立即生效。

### 身份与密钥

设置「身份密钥」。

顶上一张卡写当前身份的名字和「角色 · 种类」，按「复制地址」复制当前角色的签名地址。卡上三个读数：

| 项 | 说明 |
|---|---|
| 「身份地址」 | 当前角色的根（见第 1 节「根与现行钥」）；取不到密钥时写原因：「尚无签名密钥」或「密钥不在本机密钥库」；本机身份空着的那一种角色写「未占」，页顶另有一条说明「这把密钥已用在另一身份上。这一身份不能签名,也没有数据目录。」 |
| 「gas 余额」 | 当前角色签名地址的余额，或「未读取」；上一次读失败时写「这一次没读成:…」与原因 |
| 「备份状态」 | 「已抄录助记词并导出密钥文件」「已抄录助记词」「已导出密钥文件」或「未备份」；导出的密钥文件此刻不在盘上时改写「记为已备份,但文件当前不存在」 |

**「口令」组：**

- **「修改口令」**：一次一格：先输当前口令，再输新口令，再输一遍新口令；一格输满即自动进到下一格，最后一格按「修改口令」。新口令不合规则时就在那一格说明。提示「口令已更新」。输错当前口令会计入错误次数。
- **「自动锁定」**开关，打开时下面还有**「闲置时长」**（见 5.2）。
- 还没设口令时，这一组只有「口令」一行，写「还没设口令」，右侧「去设置口令」。

**「导出」组：**

- **「导出密钥文件」**：给别的钱包用的标准 keystore 文件。主身份导出的密钥文件（任一角色）也能在口令门恢复口令。步骤：
  1. 输入本机口令。
  2. 在「密码」（提示「至少 8 位」）里设文件密码，在「确认密码」里再输一遍。强度读数只作参考，不会拦你。
  3. 在「保存位置」选文件夹，按「导出密钥文件」。
  - 文件权限为仅本人可读。写出后应用会读回核对一次，通过才提示「密钥已备份到 …」并更新备份状态。
  - 当前角色没有签名密钥时，这一行不可用。
- **「显示助记词」**：输入口令后显示 12 个词，按「收起并关闭」清掉。本机身份没有助记词：这一行不可用，注明「此身份无助记词,只能用密钥文件备份」。

**「当前身份」组：**

- **「主身份」**：当前就是主身份时写「这个身份」，否则写主身份的名字，下面是「设为主身份」。主身份是能凭助记词或它导出的密钥文件恢复口令的那一个。
  - 在「设为主身份」卡上输入本机口令，按「设为主身份」。
  - 原主身份降为次要身份。所有密钥和本机数据都换一枚新主钥重新加密，口令不变。这一步要么全部完成，要么完全不变。
  - 只用私钥导入、还没导出过密钥文件的本机身份，要先导出密钥文件才能设为主身份。
  - 有数据目录不在原处（外置盘没接），或有后台写入在跑时，会拒绝，稍后再试。
- **「切换身份」**：右侧写共有几个（「N 个」）；只有一个身份时写「仅此一个」，不能点。点开的卡里每个身份一行：名字与种类（主身份后接「主身份」），右侧「切换」，正在用的那一个标「正在使用」；各身份两种角色的完整地址收在卡底「详细信息」里。按「切换」才换过去。换身份在后台进行（状态处写「正在切换身份」），窗口不停顿，新身份的页面读好后原位替换；途中再换另一个身份，以最后一次为准；换不成时说明原因，仍留在原身份。
- **「新建身份」**：写可选的「备注」，在下面的「网络」里选这个身份用哪个网络，然后生成、抄写并核对 12 个词，方法同向导第 2 步。
  - 「网络」列出附录 A 的各个预置网络，加「自定义」；默认选中这台机器上次在向导里选的那一项，从没选过即以太坊主网。
  - 选的网络填进这个身份两种角色的数据目录，两种角色同用。
  - 选「自定义」，这个身份的数据目录没有网络，读链与上链都会提示未配置；到「设置 > 网络」填好保存（手填或选预设）后才生效。在其中一种角色里填好保存，另一种角色打开时取同一份；别的身份不受影响。
- **「导入密钥」**：三个标签「助记词」「私钥」「密钥文件」。
  - 助记词：12 格，整段可粘贴。
  - 私钥：64 位十六进制，可带 0x。
  - 密钥文件：拖入 keystore 文件，填「密钥文件密码」。
  - 导入私钥或密钥文件时选「导入为哪一身份」（「记录者」或「使用方」）；这把密钥只占这一种角色，另一种留空。
  - 这台机器上还没有身份时，导入的即成主身份。这时导入私钥要同时导出它的密钥文件：单上多出「密码」（提示「至少 8 位」）「确认密码」和「保存位置」，导出的文件读回核对过才建成身份；不填即拒「这个身份还没导出过密钥文件。」。
  - 可选「备注」，「网络」同「新建身份」。按「导入身份」。在向导里打开时没有「网络」这一格，由向导第 3 步决定。
  - 已有身份时导入的是次要身份，不能恢复本机口令。已经在本机的身份不会重复导入，但如果它缺了密钥，导入会把缺的补回来。
  - 导入的身份先不能写，要等它的账本与链上这把密钥的上链记录核对过（见「存储」一节的「取回账本」）。
- **「改名」**：给身份改一个备注名，只用于分辨，不影响任何判定。
- **「换钥」**：给当前角色换一把现行钥，根不变。按下先过两道闸，再选方式。
  - 还有条目没上链时，卡名「先上链,再换钥」，写「待上链」几条；「去上链」关卡并到「记录存证」页的「待上链」。账本有新写入而没对过账时先自审，完成后再继续。
  - 基底有链读不到换钥簿时，卡名「有链读不到换钥簿」，列出链号；「再查」重读。没有换钥簿就不能换钥。
  - 有面条目还没落座、或有链的换钥簿没把在任钥记在根名下时，不开始换钥，卡上写明；去「身份」页重签或入簿。还没入簿的链，根钥不在手之后就入不了。
  - **「本机派生换钥」**：新钥在这台机器上。选「新钥来源」：「同一组助记词」（同一组词的下一代，按「开始」）或「新助记词」（按「下一步」，显示、抄写并核对一组新词）。没有助记词的身份（凭私钥或密钥文件导入的）没有这一种方式，只能「给定地址换钥」。之后卡上四步「新钥」「写入换钥」「旧钥余额」「各链上链」，每步写现状：
    1. 「新钥」：新钥地址显示在卡上；按「继续」，旧钥在每条链的换钥簿上申报这把新钥。
    2. 「写入换钥」：按「继续」写入换钥条目。
    3. 「旧钥余额」：之后上链与接任的手续费由新钥付，余额不够时写「新钥余额不足」。可自己转，或按「从旧钥转入」，逐条链把旧钥的余额转给新钥（「转入新钥 … ETH」；不够付转账费时写「余 … ETH,不够付转账费」）。
    4. 「各链上链」：按「继续」，由新钥把换钥条目锚到基底的每一条链；再按「接任」：新钥在换钥簿上接任，世系链那一条先，再到其他链。接任之前，签发与撤销一律拒（「换钥未完成接任。」）。
  - **「给定地址换钥」**：新钥的私钥在别处。填「新钥地址」（不成形即格红、说形，「下一步」灰着说同一句），按「下一步」查验：这本账的根和用过的钥、本机身份占着的钥、基底的链上发过锚的地址、换钥簿上已入册的地址，都拒收并写明。不查对方持有这把钥。下一步核对「新钥地址」「方式」，按红色的「确认换钥」。之后卡上三步「新钥」「写入换钥」「各链上链」：旧钥在换钥簿上申报新钥，写入继任条目，由旧钥发到基底的每一条链。写入后只有这个地址的私钥能接着写，本机只读；手续费由旧钥付，这一步不能撤回。对方接任之前，撤销权仍在原钥。
  - **对方接任**：新钥的持有者收下账本后，继任已上链而换钥簿指向他的现行钥时，他的「换钥」卡上出「接任」，手续费由新钥付。不接任不影响账本，但别人读换钥簿得到的仍是旧钥。
  - 有一条链没读到即不往下（「读不到链 N」，按「再查」）。
  - 换新助记词以身份为单位：两种角色都换完，新词才取代旧词；没换完时卡上写「旧词仍须保管:还有一席在旧词下。」还没有账本的那一种角色换后地址会变，卡上事先写明。
  - 换下的钥留在密钥库里，只用来打开先前封给它的件，不再签。删掉它不影响账本。
  - 按下即上链、之后没有确认卡的键是红色：申报新钥的「继续」、「接任」、「从旧钥转入」与「转出旧钥余额」、「确认换钥」。转入或转出那一步旁边，下一步的键（「继续」或「接任」）为次键。
  - 「放弃」作罢没写的部分；「以后再说」关卡，下次从断处接着做。
  - 簿里已声明了下一把钥而这次换钥放弃了(或卡关了)，链上的声明仍在，持有那把钥的人可以接任。卡上照实说（「现行钥对下一把钥的声明仍在」），给「撤回声明」键：把声明改指一个谁也接任不了的地址（`0x…dEaD`），链上看得见这一笔。给定地址那一种换钥按「放弃」即当场撤回；撤回发出后卡等它落块再读链，落块说「声明已撤回。」。对方已接任的，卡上照说，这台机器撤不回。

新建和导入的身份都是次要身份。这台机器上还没有身份时除外，建成的第一个即是主身份。

**删除身份。** 页底「删除身份」：

- **主身份不能直接删除**：先把另一个身份设为主身份（「去设主身份」）；只有它一个时，先新建或导入一个再设。
- **删除次要身份**：
  - 卡上写影响（记录者「账本将无法续写」，使用方「此身份下的授权不再归你」），并列出哪种角色的账本已有条目。
  - 输入本机口令后按「删除身份」。
  - 只删除密钥库里的密钥和身份登记，数据目录保留。
- **现行钥没备份过的身份不能删**（换过钥之后，旧钥的密钥文件不算），除非它的某本账本已从现行钥换给给定地址：「此身份尚未备份,无法删除。」「先备份密钥或确认助记词;记录者也可先在设置里换钥给给定地址。」
- 记录者删除前，应先换钥到给定地址（见下文「换钥」），否则新密钥无法续写这本账。

**「详细信息」：**

- 当前角色的「身份地址」（根）、「密钥地址」（现行钥）与「密钥代数」，下面一行是现行钥的「公钥」，带复制图标：别人把记录包加密给你时填它（见「记录包」）。两种角色的完整地址（空着的角色写「未占」）。
- 「备份档」：导出过密钥文件的，导出的时刻；再一行写那个文件此刻是否在盘上：「文件当前存在」「记为已备份,但文件当前不存在」或「没有导出过密钥文件」。
- 「建于」：这个身份建成的日期，或「未记」。
- 「保存位置」：「本机密钥库(口令加密)」。
- 派生路径：仅助记词身份有。
- 身份列表文件。
- 「签名域」，以及当前角色下「这一身份签得出的域」：记录者能签条目（`entry`）、发锚定交易（`anchor`）；使用方能签自己账本的条目、发锚定交易。

#### 11.4 网络

**总览**：头一行是网络名和链号（「网络名 · 链 N」），右边「读取链上数据」；下面一行是上一次读链的读数。

- 网络名：
  - 「以太坊主网」等预置的名字：这个数据目录的四格与附录 A 那一行相同。身份日后改选别的网络，已有网络的数据目录不跟着变。
  - 「自定义」：自己配置过
  - 黄色的「尚未配置网络」：节点、链 ID、登记合约一样也没有；这时「读取链上数据」不可按，「链」一组的「编辑」是主键。
- 读数：
  - 「N 个节点一致」
  - 「仅 1 个节点响应,无法交叉核对」
  - 「未读取」
  - 上一次读失败时：「这一次没读成:…」与原因
  - 有节点没答时，读数后面接「N 处节点未作答」，各节点的原话在「各处原话」折叠里；这一次没读成时也一样，只有一台节点也列出它的原话。

**「RPC 节点」**：每台节点一行，写节点地址；不是这个数据目录那条链的，地址后标「链 N」。行末的移除键删掉那一台。卡底「添加节点」一格填 `https://…` 或 `链号=节点地址`，按「添加」或回车：
- 只写地址的，记在这个数据目录的链上；还没设链 ID 时拒：「还没有链 ID:写成 链号=节点地址」。
- 地址中间带空格（「节点地址中间不带空格」）、已在列表里（「这台节点已在列表里」）、读不成的，那一格描红，格名那一行说出原因，不添加。

**「节点最大问数上限」**一行：右边一格只收 1 至 1000 的整数（默认 256），按「确认上限」即存进这个数据目录的设置，与节点表存在一处，命令行与 AI 应用读同一个数；界外的数不存，格名那一行写「填 1 至 1000 的整数」。调到 1 即不切段。

**「REST API 模式」**开关，默认关。开着时下面出「REST API」卡：每一个 REST API 与 RPC 节点一样算一台节点，同进对照、单源与扫链；关掉时已填的各行留着，不再问。
- 支持 Etherscan（V2 API）、Blockscout，以及照 Etherscan 写法答的服务，按 Base URL 的主机认。
- 每个一行：服务名、Base URL、「钥匙 ••••」加钥匙末四位；这台机器上没有它的钥匙时写「这台机器上没有钥匙」，那一行不问，读数里点名一次。行末的移除键连这台机器上的那把钥匙一起删。
- 卡底填「Base URL」（只收 `https://`，不带查询串）与「API Key」，按「添加」。同一服务（同一主机）只算一处：已在列表里而这台机器上有它的钥匙，拒「这个服务已在列表里,同一服务只算一处」（写在「Base URL」格名那一行）；「API Key」空着而没有钥匙文件可用时，那一格只描红；钥匙中间带空格时写「API Key 中间不能带空格」；这台机器上没有它的钥匙时，只存下钥匙，那一行照旧。
- 钥匙存在这台机器的加密机器设置里，不进账本，整机备份带着它；已存的钥匙不再显示。别的机器打开同一本账，REST 行写「这台机器上没有钥匙」，在那台机器上照那一行的 Base URL 再添加一次即可。
- 也可以不填钥匙：带环境变量 `ZIKARON_REST_KEYS` 起窗（指一个钥匙文件，与命令行 `--rest-keys` 同一写法：每行 `<服务> <钥匙>`，服务写主机或 `etherscan`、`blockscout`、`etherscan-like`，空行与 `#` 行略过），这台机器上没有某服务的钥匙时即用文件里的；添加时「API Key」留空即可，那一行写「钥匙取自启动时给的钥匙文件」。这台机器存着的钥匙为准；文件里的钥匙不写进任何设置、备份或读数，也不显示。从访达或开始菜单直接打开的窗不带环境变量，用不上它，要带上变量起（macOS 上如 `open --env ZIKARON_REST_KEYS=<档> <应用>`）。文件读不了、不是 UTF-8 或有一行不是「服务 钥匙」时，卡上方的红色提示条照实说出是哪一种，整份不用，别的照常。
- 服务答不了的问（如 Etherscan 按某一块的余额）不拿它作证，读数照实记作单源，读数里写「该服务不答这一问」。
- RPC 节点被问的每一问，REST 行同时一起问；它的链头是它的服务已收录的那一块，一次读取的链头取先到的两台节点里较低的那一块。凡问多台节点的读都同时问出去，两台给出同一个答即成，还在路上的不等、晚到的答不用。Etherscan 每秒至多问三问。

**「链」**一组：「链 ID」（右边「编辑」；没有时写「未设置」）、「登记合约」，以及「自动上链」开关（默认关，每个数据目录各记一份，见「待上链队列」）。节点、链 ID、登记合约、起始区块的全文在页底「详细信息」里。

**按钮：**

- **「编辑」**：打开「编辑链」。没有网络的数据目录在这里填链。
  - 上方二选一：「以太坊主网」，链 ID、起始区块、登记合约三格照附录 A 那一行填好，节点也换成那一行的节点；「自定义」，三格清空，节点照留，右边出「预设」，可下拉选附录 A 的一个预置网络，三格与节点照那一行填。预设只是填格子，按「保存」才生效。只读网络弹窗里的「预设」是同一张表。
  - 「链 ID」「起始区块」「登记合约」各一格。三格都填好才能按「保存」，没填好时「保存」灰着，悬停说「还差:…」；登记合约不成形时格红、说形，「保存」悬停说同一句；「取消」不存。
  - 按「保存」：链设置改过的先存链设置；预设带来的节点与现有的不同时，再存节点。存链设置时先问节点那个登记合约的代码：不是 ZIKARON 钉定的那一版登记合约即不保存，提示「登记合约 … 不是钉定构建，链设置没有保存」。还没配节点时照存（读数记作未核），配好节点时同一道核再走一次。上一次核的读数留在「登记合约」格旁边：「一致」「单源」「不通」「指纹不符」或「未核:无节点」。
  - 自己保存过后，「网络」显示为「自定义」；若存下的链 ID、登记合约、起始区块与节点（不论次序）与附录 A 某一行今天的值全等，即显示那一行的名字。
  - 存下别的节点、REST 行或链设置后，手上的 Gas 估算与费随即作废，下次打开「上链」卡重新估算。
  - 这个身份建时选的是「自定义」时，链 ID、登记合约和节点在一种角色里配齐，就记在这个身份上：另一种角色的数据目录打开时照它填，不用再配一遍。别的身份不取。
- **「读取链上数据」**：读一次签名密钥余额。
- **「换链」**：把这个数据目录的锚定换到另一条链。卡上四格「链 ID」「登记合约」「起始区块」「节点」，按「换到这条链」；登记合约不成形时格红、说形，键灰着说同一句。先在新链上依次锚好历来的换钥与迁至新法的条目，再锚其余，整本账在新链上重锚一遍。原来的链留在「先前的链」一行，照读。现行钥不在旧法那一段的世系里时，旧段不在新链重锚，卡上写「只读新链的人看不到旧法条目的上链记录。」已在用的链拒「已在用这条链。」它不动世系链（身份的面落座的那条链）；换世系链在「身份」页。

**节点连接。** 节点地址以 `https://` 或 `http://` 开头。连 https 节点时每次都校验证书和主机名，证书不通过就读不到链。节点拒绝或连接失败时，提示写明原因（限流、要凭据、网络不符、证书、超时等），原话在详情里。一个节点地址解析出几个 IP 时逐个试；每一问有一个总期限，连上、发出、读完都算在里面；节点限流时按一张表等一等再问。节点地址里带的访问密钥（如路径或查询串里的 key）不会出现在任何提示、详情或日志里。

**「代理」**：节点连接从哪里出去，这台机器上所有身份共用。本机上的节点（`localhost`、`127.0.0.1` 等）从不经代理。

- **「跟随系统代理」**（默认）：照系统的代理设置走：先看系统里填的自动配置脚本（PAC）地址，再是系统里手填的代理与例外表。系统里的「自动探测 / 自动检测代理」一项不读：应用不按名字去找 `wpad`，只开了它而别无设定的，当作什么都没设（直连）；要用这类网络给的代理，请在系统里填配置脚本地址或手填代理。脚本由应用自己取（不经代理，至多 1 MiB、5 秒）：`https://` 的地址哪里都取（证书照验）；`http://` 的地址只取本机的——字面的回环地址（`127.0.0.0/8`、`::1`）与名字 `localhost`，照写的判、不查域名；别的机器上的 `http://` 脚本不取，跳转中途跳到这样的地址也不取，照没有脚本走（`PAC_REMOTE_HTTP`），这时请让它改用 `https://` 地址，或在「自定义代理」里填代理——代理地址可在浏览器里打开那个脚本地址，找 `PROXY 主机:端口` 那一行，或问网管（网络上的人因此递不进脚本；升级前用着远程 `http` 配置脚本的，升级后不再用）；`file:` 的不取。取到的脚本在隔离的 JavaScript 引擎（QuickJS）里跑：只有标准的 PAC 函数，没有网络、文件、模块与定时器，每次至多 2 秒、8 MiB 内存、512 KiB 栈；脚本里要的域名解析由应用在外面答，每次至多 1 秒。脚本只看得到节点的协议、主机与端口，看不到路径（路径里常有访问密钥）。脚本给出的几条路逐条试，一条连不上换下一条；`SOCKS` 先试 SOCKS5、再试 SOCKS4。脚本用不上时照没有脚本走；这样走又连不上时，失败的下一步那一句说出脚本之因与出路（连得上不说，也不另立状态行）：别的机器上的 http 脚本说「代理脚本在远程 http 上,未用。请填自定义代理。」，取不到说「取不到代理脚本。请开启代理软件,或填自定义代理。」，其余说「代理脚本出错(码)。请填自定义代理。」；命令行在报错那一行说同一件事，出路是 `--proxy`。码如下：`PAC_UNFETCHED`（取不到）、`PAC_SCHEME`（地址不是 http/https）、`PAC_REMOTE_HTTP`（别的机器上的 http 地址）、`PAC_TOO_LARGE`（过长）、`PAC_FAILED`（出错或读不成）、`PAC_TIMEOUT`（跑太久）、`PAC_MEMORY`（内存或栈用尽）、`PAC_NO_FUNCTION`（`FindProxyForURL` 与 `FindProxyForURLEx` 都没有）、`PAC_ANSWER`（答的读不成）。各系统从哪里读：macOS 读系统网络设置；Windows 读系统答的当前设置（统一为整机设置时读整机的）；Linux 先读桌面存在盘上的设置（KDE 的 `kioslaverc`，GNOME、Cinnamon、MATE 的 GSettings），读不到才看 `https_proxy`、`http_proxy`、`all_proxy`、`no_proxy`。
- **「关闭代理」**：一律直连。
- **「自定义代理」**：分格填：类型（HTTP、HTTPS——到代理一段也走 TLS，代理的证书照验——、SOCKS5、SOCKS4）、主机、端口，要验身的代理再填用户名与密码（照原样填，不必把 `@`、`:` 写成 `%40`、`%3A`；SOCKS4 只有「用户 ID」一格），按「保存」。端口只收 1 到 65535 的整数；哪一格不对，那一格描红、格名那一行说出原因（填了密码而没填用户名，用户名格只描红），「保存」按不了。从代理软件抄来的整段地址（`socks5://用户名:密码@主机:端口` 或 `主机:端口`）粘进主机格，即拆进各格；在主机格里手打的地址，离开主机格时才拆，打到中途不拆；地址里没写用户名或密码的，已填的那一格照留。密码存在加密的机器设置里，保存后密码格空着，格名那一行只说「已设密码」；类型、主机、端口、用户名都不变而密码格空着再保存，原来的密码留着；换了其中任何一格，密码不随（不交给没给过它的代理），要重填。私网（`10.x`、`172.16`–`172.31`、`192.168.x`）、链路本地（`169.254.x`、`fe80::`）、本机与 `.local` 的节点不经自定义代理，一律直连。
- **代理要凭据**：代理要用户名与密码而没给时，提示「代理要用户名与密码」（`PROXY_CREDENTIALS_MISSING`），所给的被拒时提示「代理不收所给的用户名与密码」（`PROXY_CREDENTIALS_REFUSED`），下一步都指到自定义代理的用户名、密码格；跟随系统而系统代理要密码时也是这样，把那一代理与它的用户名、密码填进自定义代理即可。命令行答 `E_UNREACHABLE`，`token` 同名，并说 `--proxy` 怎样带凭据。

用 VPN 时：全局隧道式的 VPN 不用改这里；只开了系统代理（含自动配置脚本）的 VPN，用「跟随系统代理」即可；连不上节点时，可以把 VPN 给的代理地址填进「自定义代理」。

**「发布地址」。** 你打算把记录包放到网上的 https 地址：

- 只收 `https://`，填别的提示「仅支持 https 地址。」
- 应用不替你上传，记录包需要你自己放到那个静态托管上。
- 发布的是文件夹形的记录包（导出时打开「导出为文件夹」）。对照单文件的包即提示「单文件记录包不发布到网址;要发布,导出为文件夹。」
- 「发布地址」一行右边是「编辑」，打开弹窗填地址，按「保存发布地址」。下面「检查发布」一行一直在，没存地址时不可按；按下打开「检查发布」弹窗：「对照的记录包」默认填这个数据目录里最新的一个文件夹形记录包，左下角「选择目录」可另选，按右下角「检查」即从发布地址逐个文件取回记录包，与本地那一份比对：
  - 「已发布」：「N 个文件全部一致。」
  - 「发布不完整」：「缺 N 个文件,M 个不一致。」，并列出缺的和不一致的文件。
  - 「无法访问发布地址」，并写明原因。

**只读网络。** 主网络之下的「只读网络」一栏，这台机器上所有身份共用，存在机器目录里，一个也没有时不留文件。

- 只用来核别人的东西：「核验记录」、「查看他人账本」、授权核验和尽调读主网络加这里的每一个网络。写账本、上链、余额、账本检查只用主网络。
- 列表末行「添加」打开「新网络」弹窗；「名称」格里的「预设」可选附录 A 的各个预置网络，选了即把各格填好。
- 弹窗里填「名称」「节点」（一行一个）「链 ID」「起始区块」「登记合约」，按「保存」；没填好时「保存」不可按，说出还差哪几格；「取消」不存。保存只写这台机器，不读链。
- 「名称」：链 ID 是以太坊主网、OP Mainnet、Base、Arbitrum One 或它们的测试网时自动显示，不能改；别的链可以自己起名，不填即显示「链 <链 ID>」。名称只在这台机器上显示。
- 同一条链、同一个登记合约已在列表里，或就是主网络时，拒绝：「该网络已存在。」
- 列表每行写名称、「链 N」和读数；点一行打开它的弹窗：顶上「链上读取」一行写读数，旁边「读链」；下面是各格，右下「保存」「取消」，左下「移除」。「移除」按一次出「移除此网络?」，再按「移除」才移除。
- 「读链」的读数：「一致」（两台节点给出钉定那一版登记合约的代码即成，别的节点不等）、「单源」（只有一个节点答）、「不通」（没有节点答）、「指纹不符」（那一处合约的代码不是 ZIKARON 钉定的那一版）。
- 每次读只读网络之前都先核它登记合约的代码。「指纹不符」的那一栏这一次不用，它上面的锚一枚也不算。主网络在「编辑链」按「保存」时核（见上）。
- 同一条链上的几栏读成一扇窗：登记合约全读，起始区块取最早的那个。哪一栏这一次没读成，结果里点名，其余照核。

#### 11.5 通知

两种角色都有这两行，每行一格秒数、单位「秒」，旁边是保存键：

- 「账本检查」：默认 300 秒，按「保存间隔」保存。
- 「授权核验周期」：默认 600 秒，按「保存复核间隔」保存。

格里只收整数秒；不是整数时那一格描红，格与名字之间写「周期须为整数秒」，保存键不可按；与已存的相同时也不可按。在格里按回车与按保存键一样；存好后格旁写「已保存」，再改即撤下。空着或填 0 即不自动跑，格里显示「仅手动」。

### 存储

设置「本机数据」。

**顶部总览：** 头一行写数据怎样存、能不能写：「口令加密 · 可写入」；「口令加密 · 已暂停:恢复后需对账」；或这台机器此刻不能写时（另一窗口正在写、账本已移交或已交接到另一处、账本断链）「口令加密 · 本机只读」，与顶部的只读提示条同一判断；右边「立即对账」：离线核一遍本机账本，通过即恢复写入。下面三格：

- 「账本条目」
- 「上次对账」：检查结论与「N 条」；还没对过账写「尚未运行」
- 「上次备份」：时刻，或「从未」。上次备份后又多了账本条目或收到的授权时，时刻后面接「N 条」，这一格变琥珀色。

「用量」（「已用 … / …」，超过上限时下面一行红字）见「数据目录」。这台机器上有什么（「N 个身份 · N 条账本条目 · N 条记录 · 设置」）写在页底「详细信息」的「内容」里。

**清理明文导出。** 「清理明文导出」一行打开同名的卡：列出这台机器记下写过、至今未改的明文导出件（明文记录包、明文授权包、账本镜像），逐件写名与种类；发布到网址的记录包注明「网址上的那份不动」。记录包旁的锚证明文件夹随包列出，随包删，包改过即随包留；包不在原处时，原处剩下的那一夹只装着锚证明即删；夹里有别的文件的不删，列在「保留」里。改过的、不在原处的列在「保留」里并写明为什么。按「删除」才删，删后写「已删除 N 件,保留 N 件」。加密的件不在其内；名单之前写的件不在名单里，不删（「更早导出的不在名单内,未删」）。命令行同一件事是 `clean`。

#### 整机备份

一份备份文件恢复全部：这台机器上的所有身份和密钥、全部本机数据和设置。「只读网络」也随备份带着。不含主钥、口令和错误次数；也不含已核对事实（恢复后重新问链）、已删身份留下的数据目录、导出的记录包及其索引与核验结果。

「整机备份」一组有「导出备份」「查看备份」「从备份恢复」三行，记录者还有「导出账本镜像」（见「账本镜像」）。备份到了哪里，看顶部的「上次备份」，以及「关于」页「设置检查」里的「整机备份」一行：从没备份、备份后又有新增、上次导出没写成或读不回时，那一行右边是「导出备份」；都已备份时写「已完成」。再导出成功一次即恢复。

- 「导出备份」：弹窗顶上「内容」一行写这次备份装什么；「保存位置」默认是上次选的目录，否则上次备份所在的目录，否则文稿目录，左下角「选择目录」可改。
  1. 在「备份密码」（至少 8 位）里设备份密码，在「再输一次」里再输一遍。
  2. 输入「本机口令」，按「导出」。
  - 文件名为 `zikaron-backup-年-月-日.zikaron`，同一天再导出即往后编号，不覆盖；弹窗的「详细信息」里写着文件名、档头、加密方式和「不含」的几样。
  - 导出途中弹窗留着，逐步写出「整理」「加密」「写入」「回读核对」，途中不收返回与 Esc。写出后应用会读回并打开一次核对，通过才提示「已导出备份:…」并关上弹窗。
  - 忘记备份密码，备份就无法恢复。
- 「查看备份」：左下角「选择文件」选备份文件，填「备份密码」，按「读开」。卡上写这份备份的「建于」时刻和「内容」（几个身份、几条账本条目、几条记录）。只读开看，本机一个字节不动；按「关闭」收起。
- 「从备份恢复」：
  - 左下角「选择文件」选备份文件，填「备份密码」和「本机口令」，按「恢复」。
  - 本机的身份、密钥和数据整份换成备份里的，口令不变。本机有而备份里没有的内容会失去。备份里的只读网络取代本机的；备份里没有只读网络时，本机的不动。
  - 这一步要么全部完成，要么完全不变。
  - 恢复后仍然打不开的旧文件，会被原样挪到机器目录的 `set-aside` 文件夹，不删除。

只有助记词而没有整机备份时，只能恢复链上读得到的数据。

#### 取回账本（导入的身份）

凭助记词、私钥或密钥文件导入一个身份时，它的账本不会随之回来，而这把密钥可能在别处写过。所以导入后这个身份先不能写账本（能读），这一页顶上出现红框「账本尚未与链上核对」。

能不能写只看一件事：这一种角色的账本与链上这把密钥的上链记录核对过，链上的每一条都在账本里。账本从哪来不论：

- 配好网络后应用自动核对一次（导入时已配好网络的，导入后当即核对）。链上没有这把密钥的记录（例如一把新钥），或记录都在账本里，即可写。
- 还没有账本时，核对只对当时那条链算数：换链或清空网络即重新核对。核对过之前，只给「取回账本」，不给「创建账本」。
- 用「原位收编」接管了一个既有的账本目录后，会再核对一次，对上了即可写。
- 链上有账本里没有的记录时，红框变为「链上有 N 条记录不在本机」，仍然只读。两种可能：别处有更新的条目（从整机备份或另一台机器取回账本即可）；或这把钥在同一位置另签过一条并上了链（钥匙外泄，或两台机器同时写了这本账），取回补不上。

从整机备份取回：

1. 选一份整机备份，填「备份密码」，按「取回账本」。
2. 应用从备份里取出这个身份的账本，再与链上这把密钥的锚核对：
   - **全部对上**：提示「取回 N 条,链上 N 条上链记录都在账本里:可以写了」，恢复写入。
   - **链上有账本里没有的锚**：红框变为「链上有 N 条记录不在本机」，仍然只读。若是别处有更新的条目，找到那一份再取一次。收养一份在已有位置上另有条目的账本整份被拒、一条不收，提示账本分叉、请重新取回：在设置「本机数据」中用「取回账本」重新取回。
   - **本机已有的条目与取回的冲突**：出冲突卡，按「取回并替换」后，本机原有的数据保留为「旧数据」，可以在这一页的「旧数据」组里「查看」（只读）。

### 账本镜像

记录者的「本机数据」页才有。

「导出账本镜像」打开同名弹窗，副题「账本的导出件,不能用来恢复本机。」，三行「上次导出」「之后新增」「镜像位置」。位置默认是上次导出处，否则文稿目录下的 `ledger-mirror`；左下角「选择目录」可改，右下角「取消」「导出镜像」。按「导出镜像」：

- 把账本导出一份到指定文件夹，按 `ZIKARON-backup/<地址>/author` 分层（地址小写，不带 `0x`）。
- 同一文件夹里已有这个身份较早的镜像时，只补上新增的条目。
- 镜像是给别的工具读的导出件，不能用来恢复本机；恢复请用整机备份。

#### 数据目录

每个身份的每种角色有一个数据目录。

- 「更换数据目录」：选另一个文件夹，按「打开数据目录」。换数据目录就是换家：当前身份这一角色的数据目录从此记在新文件夹，下次启动也开它。新文件夹打不开时，什么都不改，仍记在原来的数据目录。
  - 只能选已经是数据目录的文件夹（缺一间的旧数据目录也算），或空文件夹（只有系统自动留下的 `.DS_Store`、`Thumbs.db`、`desktop.ini` 之类也算空）；空文件夹会在里面建好数据目录。
  - 别的文件夹（例如命令行建的账本目录、放着文档的文件夹）拒绝：「这个文件夹不是数据目录,也不是空的。」，那里一个字节不写，当前的数据目录不变。要接管命令行建的账本，用下面「高级选项」里的「原位收编」。
  - 属于别的身份或别的角色、或在别的机器上封存的数据目录，同样在写入任何东西之前即拒。
- 「计算用量」：统计用量和条数。
- 「隐藏本机删除的条目」（记录者，开关）：打开后，「记录存证」与「账本」的列表不列出删除时还未上链的条目及其删除记录（见「存证上链」一节的「删除存证」）；已上链后删除的照常列出。只改列表显示，默认关，记在这个数据目录里。
- 本机身份的空着的那种角色没有数据目录，这些按钮不可用。

**「高级选项」：**

- 「用量上限」一格（单位「字节」）→「保存上限」；在格里按回车与按保存键一样，存好后格旁写「已保存」。
- 「迁移到空文件夹」：
  - 选一个文件夹后按「迁移」，把数据目录搬过去，并改为这个身份的数据目录。复制在后台进行，键上显示「正在迁移」；这期间这处数据只能看，写入与再次迁移都会被拒，复制、核对完才换到新位置，原处一个字节不动。
  - 选的文件夹不空时，搬进其中新建的 `ZIKARON` 子文件夹。
  - 新位置不能是当前数据目录本身或在它里面（按符号链接解开后的真实路径判）：这样选会被拒，提示「新位置在当前数据目录之内,未复制。」
  - 旧处不动，搬完由你自己删除。
- 「收编已有账本目录」→「原位收编」：接管一个既有的账本目录，逐条重新核验后接入。也收「导出账本镜像」写出的那一束（本版或 0.1.2 写的），条目照镜像自己的清单逐条核，一条不过即整束拒收。收编的须是一整本账，恰有一条根条目（「创建账本」那一条）：一条也没有（例如只是一本账的几份文件，没有它的第一条）或有两条的，整份拒收、一字不写（「要收编的条目里须恰有一条「创建账本」(根条目),这里没有,或不止一条:不是一整本账,未收编。」「选账本的整个文件夹或账本镜像,不要只挑其中几条。」）。这处家已有自己的账本时，另一本账整份拒收、一字不写（「这处家已有自己的账本,要收编的是另一本账,未收。」）；同一本账再收编一次照收，已有的跳过。导入的身份收编之后，账本自动与链上这把密钥的上链记录核对，对上了即可写（见「取回账本」）。首次启动向导的「创建账本」一步有同一个收编（见第 3 节）。
- 「导入授权文件夹」（使用方）：选一个文件夹，按「导入文件夹」，文件夹里的每一份文件（授权文件、授权条目文件，不论文件名）逐份核验后导入；不是授权的那一份具名拒绝，其余照收。库里已有的授权带来新包的，提示里与新添加的分开计数。
  - 系统自动留下的旁件不算。文件夹里一份文件也没有时提示「这个文件夹里没有任何文件。」。
- 「重新核对上链状态」→「全部重新核对」：清掉本机记下的已核对事实与已读定的日志（见 4.1 的「读链怎样问」），下一次同步整段重读，每一条锚重新问一遍。

「详细信息」里有数据目录路径、本机数据的加密方式、上一份整机备份的路径和备份的加密方式、目录设置保存于何处、实例锁，以及缺失的子目录。

同一个数据目录只能有一个窗口写入，后打开的只能读，页顶显示只读提示条。

#### 11.7 命令行与 AI 控制

设置「命令行与 AI 控制」：终端里的 `zikaron` 命令与 AI 应用的接入，命令行怎样操作这台机器上封存的数据，以及它上链时怎么办。「自动控制等级」的两个开关与「命令行上链」存在这台机器上（加密的机器设置），所有身份、所有数据目录共用；「启用 zikaron 命令」改的是这台机器上本用户的命令路径。

**「终端」：**

- **「启用 zikaron 命令」**：打开后（显示「已接入终端」），在任何终端里直接敲 `zikaron` 就能用随应用装的命令行：macOS 在 `/usr/local/bin` 放一个链接（文件夹没有即建；系统用它自己的对话框要管理员口令），Linux 在 `~/.local/bin` 放一个链接，Windows 把命令行所在的文件夹加进本用户的 `PATH`（之后新开的终端才看得到）。关掉只移除这个开关放的东西。安装时命令行所在的文件夹已在命令路径上（Linux 的 `.deb` 包；Windows 上已在系统范围的 `Path` 里），显示「已由安装包提供」；那一处已有别的文件时不覆盖，显示「被其他安装占用:…」（用 `.pkg` 装时 `/usr/local/bin/zikaron` 已经是装好的命令行，即是这一形，不必打开）；从磁盘映像或 AppImage 里直接开的应用接不进终端，显示「此安装方式不支持」，原因在「详细信息」里。
- **「接入 AI 应用」**：按「复制配置」，把让 AI 应用起本机命令行的那段配置复制下来，提示「已复制接入配置」。「经凭据操作」开着时，按下即过口令添一把程序钥，附注「接入 AI 应用 · <时刻>」，钥写进配置的 `env`（`ZIKARON_CLI_PASS`）一并复制，提示「已添一把程序钥并随配置复制」；每按一次添一行，不用的可在「程序钥」里删掉；口令取消或不对、添不成时什么也不复制。关着时复制的配置不带钥。贴进 AI 应用的 MCP 服务器设置，AI 应用即可经命令行读写这台机器的数据（见第 12 节「接入 AI 应用（`mcp`）」）。配置里写的是本机命令行程序的完整路径，所以不必先打开「启用 zikaron 命令」。从磁盘映像或 AppImage 里直接开的应用这一键灰着，悬停说「此安装方式不支持」。AI 应用能做什么，照下面的「自动控制等级」与「命令行上链」，不另设开关。

**「自动控制等级」：** 两个开关管命令行怎样写这台机器上封存的数据、怎样发它的待上链队列，高的盖住低的，任何时候只有一条路。

- 「经桌面 App 操作」（默认开）：桌面解锁、开着这个数据目录时，命令行带 `--home` 交给桌面去写、去上链（见第 12 节「经桌面」）；不要口令。拨动时提示「命令行可经桌面 App 操作」或「命令行不再经桌面 App 操作」。
- 「经凭据操作」（默认关）：拨开时出同名的卡：输口令，填有效期（天、小时、分钟三格，合计一分钟到一年；或打开「不过期」），按「打开」。之后命令行不带 `--home`，凭一份凭据直接写封存的数据、发数据目录的待上链队列，桌面开不开都行（见第 12 节「经凭据操作」）。打开后提示「经凭据操作已开,…」（后接「到期:…」或「不过期」），关掉提示「经凭据操作已关」。凭据存在机器目录里，只有本人能读写；关掉开关即删，到期即删并提示一句，换了主钥（换主身份、整机恢复）即作废、开关自动回到关并提示「主钥已换,「经凭据操作」已关。」；改口令不影响它。开着时这一行下面写着凭据何时到期。
- **「程序钥」**：「经凭据操作」开着时，「添加程序钥」填一句备注、输口令，钥只在这一张卡上显示这一次（可复制），关掉之后取不回；列表每行只有备注与添加时间，「删除」当场作废那一把；已添的钥列在上，其下是「添加程序钥」一行，可再添。关着时写「先打开「经凭据操作」」。
- 「经凭据操作」开着时，「经桌面 App 操作」变灰、不能拨（行下写「「经凭据操作」开着时不可拨。」），门关着。
- 「经凭据操作」开着时，桌面每次写账本或待上链队列才拿这个数据目录的写者锁，写完即放；拿到时若命令行已写过，先把账本、队列和设置重读一遍再写。这时桌面解锁着，即使没人动它也每秒看一眼盘上的账本（为此每秒醒一次，与自审周期等定时同一处要），命令行写进来的条目随即出现在账本、待上链计数与本机数据页里；「经凭据操作」关着或桌面锁着时，不为看盘醒。正赶上命令行在写时，这一笔不做，提示「命令行正在写入。」「稍后再试,或关掉「经凭据操作」。」，提示上的「去设置」直接到这一页。

**「上链操作」：**

- **「命令行上链」**：命令行上链时怎么办，经桌面 App 与经凭据两路都照这一项。「自动发送」（默认）照「全部上链」直接发出队里能发的全部；「仅加入队列」一笔不发，条目留在待上链队列等你在桌面上发，命令行答 `E_QUEUED`（退出码 3）；经桌面那一路，桌面还提示「命令行提交了 N 条记录,已加入队列」。改选时提示「命令行上链:…」。

## 12 · 命令行（`zikaron`）

命令行读写的是你指定的账本目录；给 `--home` 时改由正在运行的桌面应用在它的数据目录里代做（见下文「经桌面」）。

ZIKARON Desk 自己数据目录里的账本是加密的，命令行没有口令；「经凭据操作」开着时，命令行凭那份凭据读写桌面数据目录里的账本、发它的待上链队列（见下文「经凭据操作」「经凭据上链」「经凭据读」）。封存的条目离了它的数据目录（单拷出来的 `ledger` 文件夹）读不了：标准错误第一行是 `E_UNREADABLE`，后面跟 `--ledger` 那个参数排第几、有多长（例如 `#3 (40 bytes)`），下一行「已锁定:这是 ZIKARON Desk 封存的本机数据;命令行只凭凭据读桌面所管之家的账本」（英文系统上是英文），退出码 2。`audit`（以及经它的 `check-grant`、`chain-check`）和 `show --entry` 的 `--ledger` 也可以直接指向镜像文件夹（含 `mirror.json` 的那一层）或记录包（`.zkit` 文件或文件夹）。记录包先按记录包的法核一遍，不通过即拒 `E_KIT`。写条目的动词与 `init` 只收账本目录与桌面的数据目录。

**经凭据操作。** 「设置 > 命令行与 AI 控制」的「经凭据操作」开着时，`history`、`grant`、`revoke`、`annotate`、`retract` 与五个写面条目的动词（见下文「身份的面」）的 `--ledger` 指向桌面某个数据目录（「设置 > 本机数据」所示；相对路径从命令运行处算，在数据目录里给 `.` 也是它）或其下的 `ledger` 文件夹，即凭那份凭据直接写进封存的账本（要带程序钥，见下文「程序钥」）：签名用桌面钥库里为这个数据目录的身份与角色存的那把钥（没有角色的数据目录用当前身份与角色的），不收 `--key`、`--key-file`（给了即用法错误）；照样先审（`E_WOULD_BREAK`），写进去之后照桌面的样子加入待上链队列；`history --file` 写进来的那份文件，照桌面签入时那样记进本机签入索引，之后导出记录包时随包带上原件。`anchor` 的 `--ledger` 指向那里，即凭同一份凭据发这个数据目录的待上链队列（见下文「经凭据上链」）。`init` 不收：账本里已有条目的答 `E_NOT_EMPTY`，还没有的答 `E_ON_DESKTOP`（在桌面上创建账本）。每写一笔，命令行拿这个数据目录的写者锁，写完即放。被拒时一个字节也不写，退出码 1：没有凭据（开关关着）`E_CREDENTIAL_MISSING`；凭据过期 `E_CREDENTIAL_EXPIRED`（同时删掉）；凭据不成形（旧版的凭据档在内）或所带的钥开出的不是这台机器钥库的主钥 `E_CREDENTIAL_SHAPE`（同时删掉）；没带程序钥 `E_CREDENTIAL_PASS_MISSING`；所带的程序钥开不了（从未添过、已删或不成形）`E_CREDENTIAL_PASS_UNKNOWN`；桌面正在写这个数据目录 `E_HOME_HELD`（稍后再试）；这个数据目录的写者标记是另一台机器的（同步盘上的数据目录）`E_HOME_OTHER_MACHINE`；这个数据目录只读或账本断了链 `E_READ_ONLY`、账本已交出 `E_HANDED_OFF`（见下文「一个发送器」的三道写闸）；账本末位分叉（同一序号不止一条）`E_TIP_FORKED`。详见 `CLI-SCHEMA.md` 第 12 节。

**程序钥。** 凭据里不放钥，只放一张程序钥的列表：每一行是用那把钥封起来的主钥、一句备注和添加时间。程序钥在桌面上一把一把地添（过口令），32 字节随机，写成 `zkp_` 加 64 位十六进制，只在添的那一刻显示一次，之后界面、盘上、日志里都取不回；备注一行、1 至 40 个字，至多 16 把。把钥输进要用凭据的那个程序自己的入口，由它每次起命令行时放进环境变量 `ZIKARON_CLI_PASS`（不收命令行参数：参数别的程序看得见）。命令行只在打开桌面封存的数据目录时读它，拿它去开列表里的行；走明文账本目录、`--home`、钥路时环境里有它也不读、不报错。删一把钥，那一行即去掉，那把钥当场作废，别的钥不受影响；关掉开关、到期、换主钥，整份凭据删去，全部钥作废；改口令照用。同一把钥输进两个程序，两个都能用，产品分不出：一个程序一把钥，靠的是钥只显示一次。删钥拦得住守规矩的程序；用过钥的程序有能力留下它开出的主钥，事后才发现不可信的程序，删钥之外还要换主钥。同一系统账户下有意去偷别的程序所存之钥的恶意程序，产品挡不住，所用程序是否安全由使用者自己确保。0.1.x 留下的旧凭据档（一把钥给所有程序）不再认：桌面开锁时遇到即删去、关掉开关并说一次，命令行遇到即答 `E_CREDENTIAL_SHAPE` 并删去；重新打开「经凭据操作」、再添程序钥即可。

**经凭据上链（`anchor --ledger`）。** `anchor --ledger <桌面某个数据目录里的 ledger 文件夹>` 凭那份凭据发这个数据目录的待上链队列，不必开桌面：链号、登记合约、节点取这个数据目录的设置，代理取这台机器的设置，签名用桌面钥库里为这个身份与角色存的那把钥。不收 `--key`、`--key-file`、`--endpoint`、`--form`、`--registry`、`--hash`、`--calldata`、`--proxy`（给了即用法错误，退出码 2）；`--wait-secs` 照收（缺省 90 秒）；`--ledger` 指的不是桌面数据目录里的账本也是用法错误。照「设置 > 命令行与 AI 控制」的「命令行上链」：「自动发送」即发出队里能发的全部（装在一笔交易里）、等收据、结清（条目出列、记下块号）；「仅加入队列」一笔不发，答 `E_QUEUED`（退出码 3）。队里没有可发的而有一批在途（上次停在半路）时，按交易哈希接着问那一批；那一批已不在任何节点池里时，照直发 `anchor` 重跑的同一条规则按 nonce 判：nonce 已被别的交易用掉即作废；还没用掉，「自动发送」即在同一个 nonce 上照原样重签这一批再发（过的检查与新发一批相同，答也同形），至多一笔能入块，「仅加入队列」一笔不发、答 `E_TX_NOT_YET`。都没有即答 `E_SEND_REFUSED`，`token` 为 `QUEUE_EMPTY`。答与经桌面那一路同形：入块退出码 0，带 `blockNumber` 与 `tx`；回滚 `E_TX_STATUS`；等到时限还没进块 `E_TX_NOT_YET`（退出码 4，那一批留在途，桌面或下一次 `anchor --ledger` 接着问）；没有节点答收据 `E_UNREACHABLE`（带 `tx`）；作废 `E_TX_VOID`（退出码 1，条目退回队列）；链上已有 `E_ON_CHAIN`（这一次一笔不发；各节点一致读到链上已有的那几条随即移出队列、记为已上链，下一次只发其余的，只一处节点说有不移）；发出之前别的拒 `E_SEND_REFUSED`（`token` 照桌面的码，例如余额不足 `INSUFFICIENT_FUNDS`；`detail` 是证据：节点、以 wei 计的数；网络那一族退出码 4，其余 1）；打开数据目录的拒因同上一段。加价重发只在桌面上按，不开给命令行。

**一个发送器。** 桌面的待上链队列、经桌面的 `anchor --home`、凭凭据的 `anchor --ledger` 用同一个发送器发，三路同判：

- 签名之前先问链上这把钥是否已有这几个哈希的锚（照扫链的读法），有一条即一笔不发：桌面提示「这一批里有存证已在链上,这一次一笔也没有发。」，码 `ON_CHAIN`；命令行答 `E_ON_CHAIN`，带 `names`、`tx`、`blockNumber`。没有节点答得出也不发。
- 一批签成之后、广播之前先在队列里记作已提交（带交易哈希与 nonce），中途停了再起即按哈希接着问那一笔，不另签。
- 一批在途而各节点池里都没有它时，按那个账户在链上的 nonce 判，与直发 `anchor` 重跑同一条规则：nonce 已被别的交易用掉即作废，条目退回队列；还没用掉，桌面在账本状态行给「按现价重发」由你按，`anchor --ledger` 在「自动发送」时就在原 nonce 上照原样重签再发；同一 nonce 至多一笔入块。
- 链上已有的条移出队列只凭账本自审那一判（两台节点一致读到），桌面的自审与凭凭据那一次发送都照它；只一处节点说有，不移。
- 写者锁：备好与签发两段拿着这个数据目录的写者锁；等收据那一段不拿锁，这时另一方（桌面或命令行）可以写，也可以发队里余下的，它见到这一批在途即不碰、不重发，只发余下的；结清时再拿锁、重读队列，只动仍在等这一批的条目。命令行六十秒内拿不回锁即答 `E_HOME_HELD`，那一批留在途，由桌面或下一次 `anchor --ledger` 结清。
- 三道写闸，发送与凭凭据写条目同查，凭凭据交出（`hand-over`）查前两道：这个数据目录落着只读标记（导入的身份还没取回账本 `LEDGER_NOT_FETCHED`；链上有账本里没有的锚 `NEWER_ELSEWHERE`，标记记着缺的是哪几枚，`detail` 是还缺几枚；它们的条目不论从哪条路进了账本，标记即不再拦，由这一笔撤掉）、账本自己的条目断了链（`BROKEN`）、账本已交出（`HANDED_OFF`）。发送答 `E_SEND_REFUSED`，`token` 为那一码；凭凭据写条目与交出答 `E_READ_ONLY`，`token` 为那一码（写条目遇已交出仍答 `E_HANDED_OFF`；已交出的账再交出，照旧写出同一份交接件，见下文「交接账本」）。被拒时一个字节不写、一笔不发。

**经凭据读。** 同一份凭据也开读：`audit`、`check-grant`、`chain-check`、`show --entry`、`kit-export` 的 `--ledger` 指向桌面某个数据目录（「设置 > 本机数据」所示）或其下的 `ledger` 文件夹时，照写的同一开法读那本封存的账本，拒因也同一组（`E_CREDENTIAL_MISSING`、`E_CREDENTIAL_EXPIRED`、`E_CREDENTIAL_SHAPE`、`E_CREDENTIAL_PASS_MISSING`、`E_CREDENTIAL_PASS_UNKNOWN`、`E_HOME_OTHER_MACHINE`）；读不拿写者锁，桌面同时在写也照读。`check-grant` 这样读到签发方的整本账，撤没撤销答得出来。`kit-export` 从这样的数据目录导出时，所选存证的原件照桌面的同一出处取（这台机器签入时记下的文件，还在原处、字节没变的才带上，名字照桌面的转写），所选授权签发时留下的条款文件也照桌面带上，附言末尾照桌面加上「锚在哪条链」那一行；答话里 `originals` 列出带上的原件，`leftOut` 列出没带上的（原处已没有、已不是签入时的字节，或名字转写不出）；给 `--originals none` 即一件原件也不带，两项都为空。普通账本文件夹没有签入记录，给 `--originals` 即按误用拒，它的原件以 `--file` 逐个给。`scan` 给 `--ledger` 代替 `--basis` 时，底账（链、登记合约、起始区块、发送者）取自这个数据目录的设置与账本，扫到的末块是节点报的链头；不给 `--endpoint`（也不给 `--fixture`）时，节点取这个数据目录设置里那条链的节点，代理在不给 `--proxy` 时取这台机器的设置，与「经凭据上链」同一读法；这台机器上没有某个 REST 行的钥匙时，可用 `--rest-keys <档>` 给（每行 `<服务> <钥>`；这台机器存着的钥为准；钥不写进设置、不回显）；那条链没有节点答 `E_UNREACHABLE`，节点地址不回显。`scan` 的两路（`--endpoint` 直扫与 `--ledger`）同一判法：有节点不答即标单源，在 `unanswered` 里点名，其余照比；都不答才 `E_SCAN`。节点答了预读的块头或账户证明却证不出的，另在 `unproven` 里点名：它给的不用，读数照样完整。

**收编之后的原目录。** 命令行自己建的明文账本，经桌面「导入密钥」再「原位收编」之后，就由桌面那份封存的账本接着写：命令行再往原目录写（含 `hand-over`、`take-over`）即拒 `E_ADOPTED`（退出码 1），一个字节也不写，标准错误上一行人话说这本账已被桌面收编、原目录不再写；要从命令行接着写这本账，到「设置 > 命令行与 AI 控制」打开「经凭据操作」，改给桌面那个数据目录里的 `ledger`。目录挪了位置或改了名照样认得出来，开关开着关着都拒；原目录本身一个字节也不动。桌面在机器目录里存一个随机的盐和一张收编清单，每一行是「盐 + 账本根条目号」的 SHA-256：清单单拿出去看不出是哪本账，只有手里有那本账的人才对得上那一行。

**身份的面（`face-table` 与五个写动词）。** `face-table` 读一张面表：`--root <根>` 只凭链读那个根（`--endpoint` 给节点，链须在部署表里），`--ledger` 读那本账之根（桌面数据目录的账本凭凭据、在它自己的链与节点上读；明文账本目录在 `--endpoint` 给的链上读），`--home` 经桌面读本席自己的（与「身份」页重读同一张表），三者给一个。答 `table`（面表原样）、`moment`（读至的时刻）与 `omitted`（略去的链及其缘由）；一张也读不成答 `E_FACE_REFUSED`，`token` 为 `FACE_UNREAD`，退出码 4。写面条目的五个动词：`face-home --chain`（立链或换世系链）、`face-account --platform --handle [--note]`、`face-key --address --role [--sig] [--note]`、`face-name --name`、`face-release --subject`，直写（明文账本目录加钥与 `--endpoint`）、经凭据、经桌面与 MCP 四路同一道闸、同名同答：写之前现读面表，面表要在账本之根下读成、在任钥就是签名之钥；关联、解除、显示名要世系链立着；立链的链要在基底里、那条链的换钥簿要在根名下记着在任钥；显示名写成 NFC 再按法的表校验，账号名只收可见 ASCII，附言至多 280 字节。`face-key` 的同意由 `--sig` 给（对方 app 签出的整段 `zikaron-consent:…` 文本或签名本身），或沿用账本里同一根、地址、角色的那一份；命令行与 MCP 都不签同意，两样都没有即拒 `CONSENT_REFUSED`。被这道闸拒时答 `E_FACE_REFUSED`，`token` 是闸的码（`FACE_NO_HOME`、`FACE_ROW`、`FACE_UNWRITABLE` 等），一个字节也不写；立链的条目已发出、面表还没读到它所在的块（面表只读到各链最新一块之前）时答 `FACE_UNREAD`，退出码 4，`detail` 写那一条与读到的块，等链再出一块再做；立链的条目还没发出时答 `FACE_NO_HOME`，先上链；入簿与换钥只在桌面上做。换根两个写动词同此：`face-reroot --to <新根>`、`face-origin --from <原根>`（与本根相同即拒；已有承根的再写即拒）；换根一写下，这个根的一切面条目都拒 `FACE_SEALED`（换根会先于其后写的条目落座）；承根写过了再写即拒；队里没发的面条目撤下不发。`face-joined --root <原根> --to <新根>` 读两张面表，答 `joined`（是否互指）与 `readTo`（两张各读至的时刻与略去的链），读链之法同 `face-table`。

**写之前先审。** 每个写条目的动词（含 `init`、`retract`）写之前，把「这个账本加上这一条」交核心离线审一遍；会新添一条链上发现（换了密钥之后旧钥再写、跳号、同一位置写第二条、接错上一条）即拒 `E_WOULD_BREAK`，`names` 写明是哪几种，一个字节也不写。所给之钥不在这本账的世系里（拿错了钥档），写的条目永远不算这本账的，同样拒 `E_WOULD_BREAK`，`token` 为 `NOT_IN_LINEAGE`，`names` 为空。手给 `--seq`、`--prev` 也一样过这一道。

**节点地址**可以是 `http://` 或 `https://`，大小写都认；https 校验证书链与主机名，与应用同一个连法。`anchor` 等收据时，一轮被节点拒了不算答案，按间隔再问，直到 `--wait-secs` 用完；整段时间里节点从没答过才报 `E_UNREACHABLE`。

**`anchor` 发前先估气。** 读完费之后，先请节点按这一笔交易估一次 gas（与应用同一个算法），交易所带的额度是估数的 1.5 倍（向上取整），最多 20 万。节点以关乎这一笔的理由拒答这一问（会回滚，原话在 `detail`），或估数超过 20 万，即拒 `E_GAS_REFUSED`（退出码 1），一笔也不发；节点出于自己的缘由拒答（限流、不支持这一问、要凭据、链不符等），或没答，报 `E_UNREACHABLE`（退出码 4），也不发。估完之后、签名之前，按这一笔最多花的数比这把钥的余额：不够即拒 `E_SEND_REFUSED`（`token` 为 `INSUFFICIENT_FUNDS`，`detail` 写所需、现有与这把钥的地址；退出码 1），一笔也不发；余额读不到报 `E_UNREACHABLE`（退出码 4）。

**`anchor` 不重上链上已有的。** `--form registry` 带 `--hash` 时，签名之前先问节点：登记合约里是否已有这把钥对这几个哈希的锚（照扫链的读法读合约的 `Anchored` 日志，从合约部署块到链头；不认得的合约从第 0 块问起）。不论是桌面还是别的机器上的，有一条已上链即答 `E_ON_CHAIN`（退出码 1），`names` 列出已有的，`tx`、`blockNumber` 是最早那一笔，一笔也不发；节点答不出即 `E_UNREACHABLE`（退出码 4），也不发。`--form bare` 与 `--calldata` 没有日志可问，照旧发。经桌面与凭凭据两路发队列时同样先问（见上文「一个发送器」）。

**明文账本目录上链（带钥的 `anchor --ledger`）。** `anchor --ledger <明文账本目录> --key-file <密钥文件> --endpoint <链号>=<地址>`（一条链；`--endpoint` 可重复，给它的节点）把这个目录里还没上链的条目送上链，不经桌面、不要凭据：照桌面自审读数据目录那样读链（声明目录自己的钥，从已知部署的起始块读到节点公认的链头），取出那条链上还没锚定的条目，按账本顺序取下一批（不跨换钥、不跨迁到 `zikaron/2`，与桌面队列取批同一条规矩），经已知部署表为那条链所列的登记合约直发（先问链上是否已有、等块时刻屏障、估气、等回执，重跑先问，见下）。不收 `--form`、`--registry`、`--hash`、`--calldata`（发什么由目录自己定）；部署表里没有这条链即用法错误。条目全在链上即答 `E_ON_CHAIN`（退出码 1），带链上已有的锚。所给之钥发的锚这本账不认时，签名之前即拒：`E_SEND_REFUSED`（退出码 1），`token` 为 `NOT_IN_LINEAGE`（从没任过这本账的席）或 `RETIRED`（已把席位交出），`detail` 写所给之钥与现行钥。面条目在它落座的那条链上单独一笔、带原文发出，发之前同桌面一样核登记合约的码、发送者是不是作者、那条链的换钥簿是否在根名下记着它，不过即拒 `E_SEND_REFUSED`，`token` 为那一道的码。

**`anchor` 重跑先问。** 直发的 `anchor`（凭 `--key` 或 `--key-file`，不带 `--home`、`--ledger`）把它为同一次锚定（同一条链、同一把钥、同一个去处、同一段数据）签过的每一笔交易的 nonce 与哈希记在机器目录的 `cli-sent/` 里，不记私钥，也不记节点。同一条命令再跑时，先按哈希问各节点那几笔的下落：已入块即照答入块，不再发；还在节点池里就接着等收据；都不在而 nonce 没被用掉，按同一个 nonce 重签再发，至多一笔能入块；nonce 已被别的交易用掉即答 `E_TX_VOID`（退出码 1），什么也不发，再跑一次即重新发起。所以成功之后把同一条命令再跑一遍，答的是先前那一笔，不会再付一次费。

**经桌面（`--home`）。** 给 `--home <桌面的数据目录>` 时，`init`、`history`、`grant`、`revoke`、`annotate`、`retract`、`anchor`、`kit-export`、`kit-verify` 与 `face-table` 及五个写面条目的动词交给正在运行、已解锁、并以写者打开这个数据目录的 ZIKARON Desk 去做：条目以桌面的身份写进桌面的账本，窗口里随即可见；命令行这一路不持私钥，也不要口令。带 `--home` 时一律不收 `--ledger`、`--key`、`--root`、`--seq`、`--prev`；`history` 收 `--file` 与 `--note`，`anchor` 不收别的参数。`migrate` 带 `--home` 也一律答 `E_ON_DESKTOP`（退出码 1），不去问桌面：把账本迁到新法是桌面自己的升级，只在桌面上亲手做。`kit-export` 收 `--entry`、`--note`、`--out`、`--as`（缺省一个文件）、`--to`、`--to-key`（加密给一个接收方，见下文「加密记录包」；地址由桌面在它的网络上找公钥）、`--originals`：所选存证的原件照桌面导出页的同一取法带上，给 `--originals none` 即不带，答话里同有 `originals`、`leftOut`；别的附件在桌面上选。`kit-verify` 收 `--kit`、`--originals-to`：桌面在它自己的网络上核，加密包以桌面的身份试开。一个身份的「记录者」「使用方」两个角色各有一处数据目录，桌面一时只开着一处，就是左栏顶上此刻所在那个身份与角色的；切角色或切身份即换数据目录，原来那处的门关上、另一处的门打开，所以 `--home` 给哪个角色的目录，就只在窗停在那个角色时答（`kit-verify` 这类使用方的动作，窗停在「使用方」时给使用方的数据目录）。桌面锁着、没有运行，或开着的不是这个数据目录（窗停在另一个角色或身份上）时答 `E_DESKTOP`（退出码 4）、`detail` 为 `NOT_OPEN`，给人看的那一行三种情形一并说，并说去处：在桌面上切到这个目录所属的身份与角色，或把 `--home` 改成「设置 > 本机数据」里的「数据目录」；「经凭据操作」开着时桌面不开这扇门，答 `E_DESKTOP`、`detail` 为 `ALONE`，去掉 `--home` 直写即可；被账本规则拒的（再删、授已删作品、撤销或注记不在账本的条目、会断链）答与直写、经凭据同一个拒因与 `token`（`E_RETRACTION`、`E_GRANT_WITHHELD`、`E_REVOCATION`、`E_ANNOTATION`、`E_WOULD_BREAK`）；`anchor` 以外的动词被命令行自有其因的拒绝（签发、撤销前读链把关 `E_ISSUE_REFUSED`，数据目录只读 `E_READ_ONLY`，账本已交接给别处 `E_HANDED_OFF`，撤销告示没发出 `E_SEND_REFUSED`、未入块 `E_NOT_NOTICED`）照凭据那一路答同一个名；桌面以别的原因拒绝时，答命令行直接跑同一动词时为同一原因给的那个名（已有开端 `E_ALREADY_ROOTED`、条目被拒 `E_ENTRY`、档落不了盘 `E_LEDGER`、原件取不出 `E_EXTRACT`、加密记录包 `E_ADDRESSED`），命令行没有对应之名的答桌面自己的代码前加 `E_`（`E_DOOR_UNREAD`、`E_IN_FLIGHT`、`E_HANDED_OVER` 等，`zikaron contract` 答的 `reasons` 列全），`detail` 不随桌面的语言（输出在两种系统语言下一样）（网络没有答退出码 4，其余 1）。导出时出口闸没读成链，答与经凭据同名、同成员：没设链或登记合约 `E_SCAN`（`token` 为 `E_NO_BASIS`），节点不答 `E_UNREACHABLE`，节点读数不一 `E_ENDPOINTS_DISAGREE`，退出码都是 4。账本已移交给新钥之后经门写条目，答与经凭据同一个 `E_WOULD_BREAK`，带 `entryId` 与 `names`（`AUTHORITY_MISMATCH`），一个字节也不写；桌面窗口上照旧说「已移交」。面条目被拒答 `E_FACE_REFUSED`，与其余三路同名同成员（见下文「身份的面」）。`anchor` 照「设置 > 命令行与 AI 控制」的「命令行上链」：「自动发送」即照队列页的「全部上链」发出队里能发的全部，答与 `anchor --ledger` 同形（入块退出码 0，带 `blockNumber` 与 `tx`；`E_TX_STATUS`、`E_TX_NOT_YET`、`E_TX_VOID`、带 `tx` 的 `E_UNREACHABLE`）；链上已有答 `E_ON_CHAIN`（带 `names`、`tx`、`blockNumber`）；发出之前别的拒答 `E_SEND_REFUSED`（`token` 是桌面的码，`detail` 是它的证据；网络那一族退出码 4，其余 1）；「仅加入队列」只入队、答 `E_QUEUED`（退出码 3）。各动词带 `--home` 时收哪些参数，见 `CLI-SCHEMA.md` 第 11 节。

**接入 AI 应用（`mcp`）。** `zikaron mcp` 让没有终端的 AI 应用经模型上下文协议（MCP）来问命令行（起它时可给 `--rest-keys`；也可给钥路 `--key-file <密钥文件>`，连同 `--endpoint`、`--proxy`，见下文）：AI 应用把它当子进程起，在标准输入输出上一行一条消息。它不是又一扇门，也不另有权限：每一次工具调用就是命令行的一个动词，照人在终端里敲的样子另起一个本程序去做，答的就是那条命令的答，字节与退出码一字不差。写入的工具只写本家：每次调用时看这台机器有没有凭据，有即凭凭据写（`--ledger <家>/ledger`），没有即交给桌面（`--home <家>`），两条都关着时照终端那样答，主钥只在那一次的子进程里打开。程序钥由 AI 应用起 `mcp` 时放进它的环境，每次调用的子进程随环境带上；哪个工具都不收钥，`mcp` 自己也不读钥。上链照「命令行上链」：「自动发送」时会花这个身份的 gas。`face-table` 读本家的面表、五个写面条目的工具写本家，走法同写入的工具；哪个工具都不签地址的同意。
- 工具：写入 `history`、`grant`、`revoke`、`annotate`、`retract`、`kit-export`（含 `to`、`to-key`，加密给一个接收方；`originals` 为 `none` 即不带原件）、`anchor`、`kit-verify` 与七个写面条目的工具（`face-home`、`face-account`、`face-key`、`face-name`、`face-release`、`face-reroot`、`face-origin`），参数是各动词带 `--home` 时收的那几项，外加 `home`（数据目录的完整路径）；`kit-verify` 收 `kit`、`fragment`、`originals-to`、`home`，给了 `originals-to` 即把原件取到那里，`home` 可以不给（普通包核验与取出不要家；加密包给 `home`，照开关凭凭据或经桌面以本机身份打开；经桌面那一路不收 `fragment`，给了即按名拒）。只读 `show`、`audit`（不收 `out`）、`scan`（`home`；链设置与节点取本家的）、`check-grant`、`chain-check`、`badge`（只解读）、`contract`、`face-table`（`home`；本家的面表，走法同写入的工具）、`face-joined`（`home`、`root`、`to`）。`keygen`、凡带 `--key` 的路、`migrate`、`hand-over`、`take-over` 与加价重发都不给；任何工具都不收私钥。
- 钥路：以 `zikaron mcp --key-file <密钥文件>` 起时，写条目的工具（`history`、`grant`、`revoke`、`annotate`、`retract`）与 `anchor` 先走这把钥，先于凭据与桌面：`home` 指一个明文账本目录，照人在终端敲 `--ledger <home> --key-file <密钥文件>` 去做；起时给的 `--endpoint`（可重复）与 `--proxy` 交给收它们的动词（签发与撤销时读链把关；`anchor` 把这个目录里还没上链的条目送上链）。密钥文件只传路径，在那一次的子进程里才读，不是任何工具的参数，也不出现在任何答里。不给 `--key-file` 而给 `--endpoint` 或 `--proxy`，即用法错误。其余工具（`kit-export`、`kit-verify`、`clean`、`grant-package`）照没有钥路时那样走。
- 路径参数只收完整路径；给了相对路径、不是这个工具的参数或类型不对，一笔不起，答错并点名哪一项。退出码 0、1、3、4 照实给出，只有用法错误（2）标为错误。
- 一次做一件，按到达先后；取消时只读的即停、不答，写入的做完照答（广播到一半不能撤回）。桌面答「已关」照实说，不自动重试。答里的账本文字（注记、陈述、他人账本内容、节点回话）是数据，照原样给。
- 接入配置在「设置 > 命令行与 AI 控制」的「接入 AI 应用」复制；协议细节见 `CLI-SCHEMA.md` 第 13 节。

**记录包是一个文件。** `kit-export` 缺省写一个文件（`--as file`）：记录包先排好、自验通过，再逐件写进 `--out` 那个文件，没有大小上限；`--as folder` 写一个文件夹。这个文件与授权文件同一种格式（头一行 `zikaron-kit-file/1`），桌面导出时名为 `.zkit`。凡收记录包的地方，文件与文件夹都收。

**核验记录包。** `kit-verify --kit <记录包>`（文件或文件夹）照桌面「核验记录」的同一判法逐条答：包里每件存证的原件对不对（`original`：`match` 对、`mismatch` 不是记下的那一份、`missing` 包里没有），上没上链（`anchored`：`anchored` 带首锚区块时刻 `firstAt`、`notAnchored`、`unread`）；包里的账已删除的那件另带 `deleted`（删除它的那一条的条目号）。链照 `--fragment`（`scan` 的读数）读；不给即都是 `unread`，不说成「没上链」。全都对上并上链退出码 0；有原件不对即 `E_RECORDS`、退出码 1；其余（有没上链、没读链或缺原件的）`E_RECORDS`、退出码 3。包不合记录包的法即拒 `E_KIT`。

**取出原件。** `kit-verify --kit <记录包> --originals-to <目录>` 核完把与记录对得上的原件取进那个已有的目录，与桌面「取出原件」同一判法、同一落法（见「记录核验器」）：答里多 `taken`（取出时用的名字）与 `path`；不取时拒 `E_EXTRACT`，`token` 写明为什么（`EXISTS` 已有同名、`LINK` 路上有链接、`CLASH` 两份要用同一个名、`NOTHING` 没有对得上的、`NOT_A_FOLDER` 不是已有的目录、`PATH` 包内路径不合格式、`CHANGED` 取出时包变了、`LANDING` 写盘失败已撤回），目录里一个字节也不写。普通包不要家、不要钥。`grant-package --package <授权包> --originals-to <目录>` 同一判法、同一落法取授权包的原件：原件凭所授作品相接，授权所名的记录随包时也凭它。

**加密记录包。** 与桌面同一种加密、同一份判法，三处结论与拒因逐字相同：

- 导出：`kit-export … --to <地址>`（`0x` 加 40 位十六进制，大小写都收，从别处复制来的带校验大小写的地址照收）或 `--to-key <公钥>`（`0x` 加 66 位或 130 位十六进制）。经桌面（`--home`）由桌面用它的网络找公钥；凭凭据（`--ledger <家>/ledger`）用这个数据目录的网络与节点、这台机器的只读网络与代理设置找（`--proxy` 给了即照它；代理设为「跟随系统代理」时照系统的代理设置，与桌面相同，不读终端里的代理变量）；只读网络里与这个数据目录本身同链同登记合约的那一行，就是它自己的网络，不另算；登记合约处答「没有代码」的节点（还没同步到部署那一块）不算数，照别的节点读；直接对普通账本目录，`--to-key` 即可，`--to` 另给 `--endpoint <链号>=<url>`（可给多个，链须在附录 A 的已知部署里）。地址的公钥照桌面同一判法找：各网络都读完而没有这个地址的锚，拒 `E_ADDRESSED`，`token` 为 `ADDRESS_NOT_ANCHORED`（退出码 1；节点明说拒答这一问的，如范围太大，读数以答了的节点为准）；有网络没读成，`token` 为 `ADDRESS_CHAIN_UNREAD`（退出码 4，答不出，不是答「没有」）。都不写任何文件。
- 用法错误（退出码 2，标准输出为空，不写文件）：`--to` 与 `--to-key` 同给；任一与 `--as folder` 同给；地址或公钥不合形；`--to` 对普通目录不给 `--endpoint`，或链不在已知部署里；`--endpoint`、`--proxy` 不与 `--to` 同给；数据目录的账本给了 `--endpoint`。
- 打开：`kit-verify --kit <加密包>`，经桌面（`--home`）以桌面的身份试开；凭凭据（`--ledger <家>/ledger`）以这台机器钥库里的各个身份试开（这时不收 `--key`、`--key-file`）；直接给 `--key-file`（或 `--key`）。解开后照普通包核验，给了 `--originals-to` 即接着取出。没有一把钥是接收方即拒 `E_ADDRESSED`，`token` 为 `ADDRESSED_NOT_RECIPIENT`；包被改过或截断为 `ADDRESSED_BROKEN`；什么钥都没给为用法错误。经桌面时桌面读自己的网络，凭凭据与直接这两路照 `--fragment` 读链，所以同一份包这两路可能写 `unread`、经桌面写 `anchored`。
- 别的读记录包的动词（`audit`、`show --entry` 等）遇到加密包即拒 `E_ADDRESSED`，`token` 为 `ADDRESSED_ELSEWHERE`。

**交接账本。** 一本账可以在两处之间来回交：比如远程机上命令行的明文账本目录，与本机桌面的数据目录。两端同一组命令。`hand-over --ledger <这一处> --out <文件>` 把整本账写成一份交接件（`.zkhand`，与记录包同一种单文件格式），这一处随即停写：再写即拒 `E_HANDED_OFF`，桌面那一侧同样不写。交出去的那一份丢了，再跑一次 `hand-over` 写出的是同一份。交出桌面的数据目录（凭凭据）先过它的写闸，与上链、写条目同判：落着只读标记（`LEDGER_NOT_FETCHED`、`NEWER_ELSEWHERE`）或账本自己的条目断了链（`BROKEN`）即答 `E_READ_ONLY`（`token` 为那一码，退出码 1），不写交接件，也不记作已交出。`take-over --ledger <这一处> --handoff <文件>` 收一份交接件：只收顺接的，这一处的每一条都在交接件里、交接件里的账是一条线，才把这一处没有的那几条按序号写进来，这一处随即复写；交出过的这一处只收交回来的那一份。不收时拒 `E_HANDOFF`，`token` 写明为什么（`NOT_BACK` 不是交回来的那一份、`AHEAD` 这一处有交接件里没有的条目、`NOT_ONE_LINE` 交接件里的账不是一条线，或文件读不出），一个字节也不写。本机那一侧凭凭据读写，桌面锁着也行；桌面开着时随即见到新条目。哪一侧上过链不随交接件走：桌面下一趟账本检查从链上现读，只把链上没有的排进待上链，另一侧上过的不会再上；明文账本目录没有队列，命令行只发 `anchor` 给它的，桌面数据目录的队列由 `anchor --ledger` 发（见上文「经凭据上链」）。哪本账交出了、收回了，记在各自机器目录里一张盲化的清单上（与收编清单同一把盐），清单单拿出去看不出是哪本账。

**远程明文账本换钥。** 命令行不写换钥条目，换钥在桌面做：明文账本先交到桌面，换完再交回。一处交出即停写，两头不会同时写，不用另外停。

1. 远程：`hand-over --ledger <明文账本> --out <交接件>`。
2. 本机：把这本账的钥导入桌面（「导入密钥」的「私钥」），打开「经凭据操作」，`take-over --ledger <桌面数据目录里的 ledger 文件夹> --handoff <交接件>`。新导入的数据目录直接收，不用先「原位收编」。
3. 桌面：「设置 > 身份密钥」的「换钥」选「本机派生换钥」走完，到条目上链、接任。
4. 本机：`hand-over --ledger <桌面数据目录里的 ledger 文件夹> --out <交接件>`。桌面随即不写这本账。再在「设置 > 身份密钥」导出新钥的密钥文件。
5. 远程：`take-over --ledger <明文账本> --handoff <交接件>`，之后用新钥写。旧钥再写即 `E_WOULD_BREAK`。

`--key-file` 收的是 64 位十六进制私钥，导出的密钥文件是加密的 keystore，给它答 `E_KEY`：先用读得了 keystore 的钱包工具解开，把私钥存成只有自己可读的文件，再交给 `--key-file`。

不想让新钥离开远程，就在第 1 步之前在远程 `keygen` 一把新钥，第 3 步选「给定地址换钥」填它的地址，上链后接第 4 步（不用导出），第 5 步用那把钥写。命令行没有换钥簿的接任；要接任，把这把钥导入一台桌面，收下账本后按「接任」。

**在链上核验。** `check-grant`、`chain-check`、`grant-package --package` 给了 `--endpoint`，给了账本而没给链上读数时（带撤销成员的授权不给账本也一样）自己读链：日志照旧全读，只检验六项核验所依的那几条锚（继任与迁移、这份授权及其后同线的条目、账本副本里没有的哈希），读数显出别的锚有关时再补检。判定与整本审计相同；答里不带账本的标签与条目数。`zikaron/1` 的不带撤销成员的授权、续接 `zikaron/1` 账本的账本，不这样判：答 `E_UNCHECKED`（退出码 4，`detail` 为 `OLD_LAW` 或 `CONTINUED`）。这两类与整本审计，先跑 `scan`，再交 `audit` 或带 `--fragment` 的核验。

**授权文件。** `check-grant --grant` 可以给授权条目文件，也可以给应用导出的授权文件（`.zkgrant`）：命令行按应用的同一读法拆开（包的形、里面记录包的法、授权码、授权码里每一跳都在包里），核的是这份文件为之而立的那一跳；拆不开即拒 `E_GRANT_FILE`。

**写条目被拒时。** 条目的某一项缺了或格式不对，标准输出为 `E_ENTRY`，其 `token` 为 `E_BODY_FIELD`（退出码 1）；标准错误另有一行人话，点名是哪一项、由哪个参数给，例如 `mode: 缺或不成形,由 --mark 与 --toolchain(或 --file) 给`（英文系统上整行是英文）。这一行只给人看，不属输出约定。

**`history` 记一份文件。** `history --file <文件>` 按应用记录文件的同一约定填：`content` 是这份文件字节的 SHA-256，`mode` 是 `{"mark":"bytes-sha256/1","toolchain":<"bytes-sha256/1" 这串字的 SHA-256>}`。同一份文件，命令行与应用记下的这两项逐字相同。`--file` 代替 `--content`、`--mark`、`--toolchain`，不能与它们同给；不给 `--file` 时这三项照旧自己给，不填的由法拒。

**其他。** `audit --out <文件>` 把这一趟组装的审计输入（四项）另存一份，可作 `chain-check --hop <授权>=<审计输入>` 的输入。`kit-export --file <包内路径>=<文件>` 的包内路径相对记录包的 `files/`，须合包内名法：每段只用小写字母、数字与 `.`、`_`、`-`，不以 `-` 起头，不是 `.` 或 `..`，每段至多 255 字节，全长至多 1024 字节，命令行不转写。不合即答 `E_KIT_PATH`（退出码 1），`token` 说是哪一条（如 `CHAR`），`detail` 说在哪一段、哪个字（如 `segment=1 char=U+6587`），不写任何文件。用法错误时，标准错误第一行是 `<拒因> <主语>`：旗写作 `--名字`，值或路径只写它在参数里排第几、有多长（`#3 (12 bytes)`），所以私钥、带访问密钥的节点地址都不会被回显。第二行是给人看的说明：系统语言（`LC_ALL`、`LC_MESSAGES`、`LANG`、`LANGUAGE` 中第一个设了的）是中文时用中文，否则用英文。`--key-file <文件>` 从文件读私钥，代替 `--key`（文件须只有本人可读）。`anchor` 与 `scan` 收 `--proxy`：`system`（默认；照终端的通行规矩，`https_proxy`、`http_proxy`、`all_proxy`、`no_proxy`（大小写两写）设了任一代理即照它们走，三个系统都一样，都没设才读系统的代理设置）、`none`，或一处代理地址，写法同设置页的「自定义代理」（`http`、`https`、`socks5`、`socks4`，可带 `用户名:口令@`，其中的 `@`、`:` 写成 `%40`、`%3A`；写在命令行上的口令在命令运行期间本机其他进程看得到）。

## 附录 B · 本机文件与加密

**机器目录**存放密钥库、身份登记、机器设置、记录包索引等。机器设置分两份：`machine.json` 只存口令门上就要用的语言与外观，其余（自动锁定、代理、网络、REST API 的钥匙、命令行的两个开关、用过的数据目录、整机备份的记录）存在加密的 `machine-<…>.sealed` 里，开锁后才读。

- 位置由指针文件 `~/.zikaron-desk` 给出（一行路径），应用每次启动都会写它；没有指针时默认为 `~/.zikaron-desk.d/`。机器目录在指针文件所在的文件夹之内时，指针记的是相对那个文件夹的路径，所以把整个用户目录拷到别处（同步盘、换盘），副本读写的是它自己的机器目录，不碰原处；在那个文件夹之外（自己选的位置）时，指针记绝对路径，照原处读。早先版本写的绝对路径指针照读，第一次启动即改写成相对路径。机器目录是从别处拷来的时，窗口出一条提示「数据从 … 搬来,今读写在此处」，每个来处只说一次。在 Windows 上，指针文件与默认机器目录都在 `%LOCALAPPDATA%\ZIKARON\` 里：`%LOCALAPPDATA%\ZIKARON\.zikaron-desk` 与 `%LOCALAPPDATA%\ZIKARON\.zikaron-desk.d\`。

**数据目录**：每个身份的每种角色一个，存放账本、设置、待上链队列、收到的授权等，分在 `ledger`、`kits`、`grants-held`、`settings` 四个子文件夹里。默认放在机器目录里：每个身份一个文件夹，名字用本机的钥算出，里面是 `author`（记录者）与 `grantee`（使用方）。

**本机加密。** 账本条目、设置、待上链队列、身份登记、记录索引、手填的记录包链接、已核对事实与已读定的链上日志（机器目录的 `checked/facts.json`，与一读一份的 `checked/logs-*.json`）、上一份整机备份含哪些内容的索引、收到的授权（连同上次核验结果与留存的授权文件）与条款文件，都用主钥派生的本机数据钥加密（XChaCha20-Poly1305）。锁着时一份也读不出，拿到这台机器文件的人没有口令也读不到。文件名与文件头里标明它是哪一份的那一段都用本机的钥算出，拿到磁盘的人也不能凭条目号或授权号猜出这台机器存着哪些条目或授权。

只按当前的加密格式写、只读当前的加密格式。别的形式（明文文件，或 0.1.2 及更早版本写的旧形式）一律不读，也不转换（见第 2 节「从早先版本升级」）。打不开的文件（新版本写的、损坏的，或旧形式的）一律不覆盖：点明原因，原样留着。本版写的文件 0.1.2 及更早版本读不了。

**不加密的文件：**

- 开锁前就要读的：密钥库本身（另有加密）、`machine.json`（只有语言与外观）、数据目录指针。
- 命令行的凭据 `cli-credential-<…>.json`（「经凭据操作」开着时才有）：只有本人能读写；里面没有钥，只有有效期和程序钥的列表，每一行是用一把程序钥封起来的主钥、一句备注和添加时间；拿到某一把程序钥的程序能像命令行一样读写封存的数据、发这个数据目录的待上链队列。所以删钥即删那一行，关掉开关即整份删去。
- 收编清单 `adopted-salt` 与 `adopted-list`：一个随机盐和每本收编账本一行「盐 + 根条目号」的 SHA-256，不含账本名、路径或条目号。交接清单 `handed-pens` 用同一把盐，每本交出或收下的账一行，同样不含这些。
- 给别人看的导出件：记录包、记录包索引、核验结果文件（机器目录的 `kits/verified/`）、授权文件、凭证、账本镜像、密钥文件、整机备份（整机备份用备份密码加密）。
- 只读网络列表（机器目录的 `read-networks.json`）：不含账户信息。
- 机器目录的 `cli-sent/`：命令行签过的锚定交易的记录，以发送那把钥导出的钥加密，只有持这把钥的人读得懂；旁边的 `logs-*` 是直发读过的日志，「全部重新核对」一并清掉。
- 机器目录的 `kits/exports.json`：明文导出件的名单（「清理明文导出」照它删），已加密。
- 别人交来的外来文件。

**整机备份**用 scrypt（标准参数 N=262144、r=8、p=1）从备份密码派生密钥，再用 XChaCha20-Poly1305 加密。

## 附录 C · 删除条目的读法

「删除存证」写进账本的是一条类型为 `retraction` 的条目，照常签名、照常上链：

| 字段 | 值 |
|---|---|
| `entryType` | `retraction` |
| 正文 `subject` | 必填：本账本里一条存证的条目 ID，`0x` 加 64 位小写十六进制 |
| 正文 `note_md` | 可选：一段说明 |

这是 ZIKARON Desk 的读法约定，不在 `zikaron/1` 协议正文里。命令行的 `zikaron retract` 写的是同一种条目，规则相同。别的工具读到它会列为未知类型（`UNKNOWN_TYPE`），账本结论不因此改变。

本应用的读法：

1. 格式正确、`subject` 指向本账本里一条没删过的存证：这条存证读作已删除，在各表中划掉，不能再签发新授权，详情页也不再出授权与导出的按钮。
2. 被删的存证如果还没公开过，删除只记在本地；已经发出或上链的，删除条目照常上链（见「存证上链」）。
3. 已上链的存证被删除后，链上记录照旧。
4. 已经签发出去的授权不受影响。
5. 同一条存证第二次被删：读作「删除无效:目标已被删除」。
6. `subject` 指向的不是存证：读作「删除无效:目标不是存证」。
7. `subject` 在本账本里找不到：读作「删除无效:目标条目不在此账本中」。
8. 缺 `subject`、格式不对或多出别的字段：读作「删除无效:内容不合约定」。
9. 无效的删除条目不影响任何存证，也不会让账本读不下去。

在「查看他人账本」里读别人的账本，按同样的规则。
