# ZIKARON Desk 使用手册

ZIKARON Desk 是一个本机桌面应用：把你的作品或文件记进一本只增不改的账本，把账本锚定到以太坊（或所选的二层网络）上，再凭账本签发授权；收到授权的一方可以在任何一台机器上独立核验。

本手册按 0.1.1 版写。界面上的字用「」标出，与窗口上显示的一字不差。

---

## 1 · 基本概念

**身份。** 一个身份就是一组签名密钥。身份有两种：

- **助记词身份**：由 12 个助记词派生，同时有记录者与使用方两把密钥。
- **本机身份**：导入的一把现成私钥或密钥文件，只占导入时选定的那一种角色。

**两种角色。** 每个身份都分「记录者」和「使用方」两种角色，在左栏顶上切换。两种角色各有自己的密钥、地址和账本（数据目录）。

- **记录者**：记录自己的作品，签发授权。
- **使用方**：收下别人的授权并核验，也可以转授权。

助记词身份的两把密钥分别由 `m/44'/60'/0'/0/0`（记录者）和 `m/44'/60'/0'/0/1`（使用方）派生，地址不同，各自需要少量 gas。每个身份记着自己选的网络，它的两种角色同用这一个；同一台机器上的不同身份可以在不同的链上。

**账本。** 每种角色有一本自己的账本，由一串签名条目组成，只能追加，不能修改或删除旧条目。第一条是「创建账本」，一本账只有这一个根。条目类型有：

| 类型 | 说明 |
|---|---|
| 创建账本 | 账本的根 |
| 存证 | 一件记录的内容指纹 |
| 授权 | 授权某个地址在一段时间内使用某件记录 |
| 撤销 | 撤销一份授权 |
| 注记 | 给某一条补充说明 |
| 导入 | 把这把密钥早先上链的锚收进账本 |
| 换密钥或移交 | 把账本交给新密钥 |
| 删除条目 | 把一条存证标为已删除（见附录 C） |

**上链（锚定）。** 新条目先进「待上链」队列，发出一笔交易（发到这个身份所选的网络：以太坊主网，或 Arbitrum One、OP Mainnet 等）后才算上链。队列里的条目可以一次全部发出，只花一笔交易的费用。上链之后，任何人都能对着链核对这本账在那个时刻已经存在。

**授权。** 授权条目写明被授权方、记录、有效期和条款文件指纹。交给对方有两种方式：

- **授权码**：以 `zikaron-grant:` 开头的一段文本，只能核验签名和有效期。
- **授权文件**：`.zkgrant` 文件，带着签发者账本，可以做完整核验。

使用方还可以在自己的账本里写**转授权**，把上游授权再授给别人。

**记录包。** 从账本导出的一个文件夹，含所选条目、原文件和上链证明，交给别人离线核验。

**本机加密。** 本机的全部数据都由一枚主钥加密。主钥由 8 位口令开启：锁着时，本机数据一份也读不出来。

**主身份。** 这台机器上第一个身份默认是主身份，之后可在「设置 > 身份密钥」改设。只有主身份的助记词或密钥文件能在忘记口令时重设口令（见第 5 节）。

## 2 · 安装

0.1.1 提供 Apple 芯片 macOS 与 x86_64 Linux 的安装包和 x86_64 Windows 的 zip 包。每个包都附带第三方组件许可（macOS 在 `ZIKARON.app/Contents/Resources/THIRD-PARTY-LICENSES.txt`，Linux 在 `/usr/share/doc/zikaron-desk/THIRD-PARTY-LICENSES.txt`，Windows 在解压出的文件夹里），应用内在「关于」里也能看到。

**macOS**

- `ZIKARON-0.1.1-macos-arm64.dmg`：打开后把 `ZIKARON.app` 拖进「应用程序」。命令行 `zikaron` 在应用包内的 `ZIKARON.app/Contents/MacOS/zikaron`。
- `ZIKARON-0.1.1-macos-arm64.pkg`：安装包，把应用装进 `/Applications`，把命令行装到 `/usr/local/bin/zikaron`。
- 应用用自签证书（Kaptonia）签名，未经公证（没有经过 Apple 的公证）。从浏览器下载的文件带有 macOS 的隔离标记，系统会拒绝打开；在较新的 macOS 上，「系统设置 > 隐私与安全性」里的「仍要打开」也不一定有效。先用 `shasum -a 256 <文件>` 核对 SHA-256，再在「终端」里去掉隔离标记：

  - 用 dmg：打开 dmg 之前先运行下面这条，再打开 dmg，把 `ZIKARON.app` 拖进「应用程序」：

    ```
    xattr -d com.apple.quarantine ~/Downloads/ZIKARON-0.1.1-macos-arm64.dmg
    ```

    如果已经拖进去了，改为运行：

    ```
    xattr -dr com.apple.quarantine /Applications/ZIKARON.app
    ```

  - 用 pkg：先运行下面这条，再双击安装：

    ```
    xattr -d com.apple.quarantine ~/Downloads/ZIKARON-0.1.1-macos-arm64.pkg
    ```

  命令里的路径按你实际下载的位置改。

**Linux**

- `zikaron-desk_0.1.1_amd64.deb`：用于 Debian、Ubuntu 及其衍生版。运行 `sudo apt install ./zikaron-desk_0.1.1_amd64.deb` 安装；窗口程序是 `zikaron-desk`（应用菜单里也有），命令行是 `zikaron`。
- `ZIKARON-0.1.1-x86_64.AppImage`：不用安装，`chmod +x` 之后直接运行，打开的是窗口程序；包里的命令行 `zikaron` 不能直接调用，要用命令行请装 `.deb`。它要用 FUSE；系统没有 FUSE 时，加 `--appimage-extract-and-run` 运行。
- 两个包都要求 glibc 2.31 或更新（Ubuntu 20.04、Debian 11 起）。包没有签名，先用 `sha256sum <文件>` 核对 SHA-256。
- 别的架构或发行版，按仓库 README 的「从源码构建」构建；在 Linux 上运行 `packaging/linux/build.sh` 可以自己打出 `.deb` 与 AppImage。
- 系统文件对话框要走桌面门户，需装 `xdg-desktop-portal` 和一个后端（如 `xdg-desktop-portal-gtk`）。没有门户时，点选文件会提示「系统的选档框在这台机器上开不了。」，这时可以把文件直接拖进窗口。
- 在 Linux 上，既收文件也收文件夹的拖放区（如新建存证）点开的选档框只能选文件；要给文件夹，请把文件夹拖进来。「选择目录…」照常选文件夹。

**Windows**

- `ZIKARON-0.1.1-windows-x86_64.zip`：用于 x86_64 的 Windows 10 与 11。不用安装：解压到任意文件夹，双击 `zikaron-desk.exe` 即开；命令行是同一文件夹里的 `zikaron.exe`。程序自带运行库，不需另装。
- 先在 PowerShell 里用 `Get-FileHash <文件> -Algorithm SHA256` 核对 SHA-256。
- 程序没有签名。首次打开时 Windows 会提示「Windows 已保护你的电脑」，按「更多信息」，再按「仍要运行」。Windows 11 开着「智能应用控制」时，未签名的程序会被直接拦下，没有「仍要运行」，也不能单独放行这一个程序；要用就先在「Windows 安全中心 › 应用和浏览器控制 › 智能应用控制设置」里把它关掉。
- 升级：用新版的文件夹替换旧的。机器数据不在解压的文件夹里，而在 `%LOCALAPPDATA%\ZIKARON\`（见附录 B），删掉解压的文件夹不会删掉它。
- 开始菜单项、桌面快捷方式和命令行进 `PATH` 都不会自动加上，需要时自己加。
- 在 Windows 上，和 Linux 一样，既收文件也收文件夹的拖放区点开的选档框只能选文件；要给文件夹，请把文件夹拖进来。

窗口程序不接受参数，带参数启动时不开窗，只说明原因；要处理文件，先打开窗口，再把文件拖进去，命令行的事用 `zikaron`。窗口打不开时（多半是显卡驱动不支持所需的 OpenGL，或在没有 3D 加速的虚拟机、远程桌面里运行）也会说明原因；在 Windows 上从资源管理器双击启动时，这句话以系统对话框显示。

在 macOS 与 Windows 上从源码构建同样见仓库的 README。

## 3 · 开始使用

### 首次启动

以下情况打开应用时，向导会自己弹出，并停在第一个没完成的步骤：还没设口令、还没有签名密钥，或当前是记录者而账本还没创建。

向导左边竖列六步，右边是当前这一步。竖列里完成的步骤打勾，可以以后再做的步骤画虚线，已完成的步骤和当前步之前的步骤可以直接点过去。每一步是否完成都按实际状态判断，不是按过「下一步」就算。

| # | 步骤 | 必做？ |
|---|---|---|
| 1 | 设置口令 | 必做 |
| 2 | 创建身份 | 必做 |
| 3 | 网络 | 必做 |
| 4 | 创建账本 | 记录者必做；使用方可「以后再说」 |
| 5 | 充值 gas | 可「以后再说」 |
| 6 | 整机备份 | 可「以后再做」 |

没设口令时向导只停在第 1 步；设了口令而还没有身份时，只停在第 2 步。

**底部按钮。**

- 左边是「上一步」，以及可跳过的步骤上的「以后再说」。最后一步上这个键写「以后再做」，按下关掉向导，提示与「完成」相同。
- 右边在这一步没完成时是它自己的动作键（第 1 步没有动作键，填满即提交），完成后换成蓝键「下一步」。最后一步是「完成」，按下后提示「首次启动已完成;未完成项见「设置 > 关于」」。

**退出。** 竖列底部的「退出向导」或 Esc 回到打开向导之前的页面。做完的步骤照旧算完。下次启动时，若还缺口令、身份，或记录者的账本还没创建，向导会再弹出；其余没做的步骤可从「设置 > 关于」的「重新运行向导」接着做。

- 新生成的助记词还没核对时，会先问「退出向导?」：「这组词尚未核对,退出后作废。」
- 真正的首次运行（既没有口令也没有身份）没有退出口。

**其他打开方式。**

| 入口 | 打开到 |
|---|---|
| 「设置 > 关于」的「重新运行向导」 | 第一个没完成的步骤；全部完成时第 1 步。当前角色还没有身份时此键不可按 |
| 「设置 > 身份密钥」的「去设置口令」 | 第 1 步 |
| 转授权页的「生成密钥…」 | 第 2 步 |
| 转授权页的「开账…」 | 第 4 步 |

凡是还没设口令，都先停在第 1 步。

#### 第 1 步 · 设置口令

1. 在八个格里输入 8 位字母或数字。区分大小写，输入的字以圆点显示。
2. 填满一遍后提示「再输入一次」，再输一遍。两遍一致即设成；不一致时整排抖一下，重新填。

- 过于简单的口令当场被拒：八位全同，或纯数字而成连号或像日期。提示「过于简单,请换一个。」
- 格下说明：「8 位字母或数字,区分大小写。」「启动时输入。忘记可用助记词恢复。」

口令排在建身份之前，因为密钥要放进由口令开启的密钥库。应用不读也不写系统钥匙串，密钥只住在本机密钥库里。

#### 第 2 步 · 创建身份

可以先在「备注」里写一个名字（可选，只给自己认），然后三选一。

**生成助记词（新身份）**

1. 按「生成助记词」。
2. 确认没人看屏幕，点遮罩「确认无人看屏幕后点按显示」，12 个词分三行四列显出。「隐藏助记词」可以随时遮回。
3. 按顺序抄在纸上，按「我已抄在纸上」（揭开过遮罩后才能按）。
4. 按提示填回随机抽的三个词（「第 N 个词」），按「确认并创建」。三个词对上即建成。

**导入已有密钥**：按「导入已有密钥…」，见「身份与密钥」一节的「导入密钥」。这时导入的是本机第一个身份，它会成为主身份；导入私钥时同一张单里一并导出它的密钥文件（填密钥文件密码两遍和保存位置），忘了口令时凭这份文件找回。

导入的密钥可能在别处写过账本，所以导入后先不能写：第 3 步选好网络后，应用自动把这把密钥在链上的上链记录与本机账本核对一次。链上没有这把密钥的记录（例如一把新钥），或记录都在账本里，就可以写了；链上有账本里没有的，见「存储」一节的「取回账本」。

**从备份恢复**：按「从备份恢复…」，选整机备份文件，填「备份密码」，按「恢复」。身份、密钥、账本和设置整份回来，用刚设的口令重新加密，向导随即关闭。

这台机器上建成的第一个身份就是主身份。

#### 第 3 步 · 网络

可选的有两项：

- 「以太坊主网」，带「推荐」标记；这台机器还没选过网络时默认选中它。
- 「自定义」：「先空着,到设置「网络」自己填链号、合约与节点(可选预设)」。

按「下一步」即选定。这里选的就是第 2 步建的那个身份的网络，它的两种角色（记录者、使用方）同用这一个：选主网，两个数据目录填好链号、登记合约、起始区块和两个公共节点；选「自定义」，这个身份的数据目录就没有网络（不论这台机器以前选过什么），读链与上链都会提示未配置，到「设置 > 网络」按「编辑节点…」手填或选一个预设，保存后才生效。这台机器也记住这一次的选择，下次向导与「新建身份」默认选中它。

Sepolia 测试网、Arbitrum One、OP Mainnet 不在这里列出，要用就选「自定义」，再到「设置 > 网络」按「编辑节点…」，在「预设」里选（见附录 A）。例外：当前身份或这台机器已选过其中某一个（例如从这样的备份恢复而来），它会列在「以太坊主网」和「自定义」之间。

在主网上锚定要花真实的 ETH 付 gas。

#### 第 4 步 · 创建账本

第 2 步导入的身份，要等第 3 步之后与链上核对过才能创建账本（见第 2 步）。

1. 在「账本说明(可选)」里写账本的用途。
2. 按「创建账本」，出确认卡：「账本说明」「费用」（「免费(仅写入本地)」），便条「创建后不可更改」；账本位置在「详细信息」里。
3. 在卡上再按「创建账本」才写。

#### 第 5 步 · 充值 gas

页面显示「密钥地址」「gas 余额」和一个付款二维码（「钱包扫码付款」）。

1. 从你的钱包往这个地址转少量 ETH。地址可以选中复制。
2. 按「我已转账」。向导不发交易，只读一次链上余额：大于零即完成，自动进入下一步；还是零时提示「链上还没看到这笔转账,稍后再按「我已转账」。」

读余额需要节点。第 3 步选了「自定义」的，先到「设置 > 网络」配好节点。

#### 第 6 步 · 整机备份

页面提示「一个备份文件恢复全部;只有助记词,只能恢复链上读得到的数据。」

按「导出备份…」，填写方法见「存储」一节的「整机备份」。导出成功后这一步即完成。

## 4 · 窗口与通用操作

#### 4.1 窗口布局

左边是左栏，右边是页面。页面顶上是工具栏：左边有后退、前进箭头和页题，右边是这一页的按钮和筛选。导入的身份在链上有账本里没有的记录时，各列表页工具栏右边另挂一枚黄色「只读」。

**左栏从上到下：**

1. **身份牌**：写当前身份的名字（没取名写「未命名」）和种类。点开是身份菜单：
   - 顶上一格「按身份名称或地址找」，下面每个身份占两行，主身份标「主身份」，当前的标「正在使用」。点另一个身份即切过去并回到首页。
   - 身份之后是「新建身份…」「导入密钥…」和「身份密钥」（打开设置里的身份密钥页），搜索时也一直在。
2. **角色切换**：分段「记录者」|「使用方」。切换后左栏整条换成那一种角色的页面，回到首页，并提示「已切换为…」。
3. **页面列表**：

   | 记录者 | 使用方 |
   |---|---|
   | 首页 | 首页 |
   | **记录**：记录存证、授权 | **授权**：我的授权 |
   | **查看**：核验、账本、提醒 | **查看**：核验、提醒 |

   - 「提醒」右边的数字是提醒页上黄灯和红灯的行数。
   - 再点一下当前所在的那一项，回到它的列表页。每一项记得你上次停在哪里。
4. **底部**：
   - 「设置」。
   - 「锁定」：设过口令才有。
   - 状态行：右端的小图标就是「同步」。

**状态行**依次显示最要紧的一种：

| 显示 | 含义 |
|---|---|
| 「进行中:…」 | 有你发起的后台任务在跑；同时有几项时写「进行中:… 等 N 项」。点它回到发起任务的那一页 |
| 「正在同步…」 | 同步在跑 |
| 「同步失败」 | 上一次读链失败；原句在「提醒」页的「详细信息」里 |
| 「上次同步 时:分」 | 上一次读链成功的时刻；时区为 UTC 时后面加「UTC」 |
| 「尚未同步」 | 还没读过链 |

**同步。** 点状态行右端的同步图标，按当前角色在后台读链：

- 两种角色都读一次签名密钥余额。
- 记录者建过账本的，再跑一趟账本检查。
- 使用方再复核一遍我的授权。

全部回来后给一条汇总提示。没配节点时提示「未配置节点:在「设置 > 网络」中添加」。

**读链怎样问。**
- 查锚时只问这本账相关地址（账本里写过的那些密钥）发的锚，别人的不问；回来的每一条照样在本机逐项核过。一个相关地址也没有的范围不问。
- 节点拒答时先原样再问，连拒三次才把查询范围拆小（节点说了上限就按上限，没说就对半），拆小之后的每一问同样有三次。
- 几个节点一致确认过的锚，本机记下它的区块时间与判词，下次不再逐条追问；账本里有哪些锚、链上有没有新锚，每次同步照样现问，链上那一块若换了（区块哈希不同），或节点交回的那条日志与记下的不一样，即重新问。只一个节点读到的、判词未证的不记。要全部重新问一遍，用「设置 > 本机数据」的「全部重新核对」。

**快捷键**（表里的 ⌘ 在 macOS 上是 Command 键，在 Linux 等其他系统上是 Ctrl 键；如 ⌘L 在 Linux 上按 Ctrl+L）：

| 键 | 作用 |
|---|---|
| ⌘1 起 | 按顺序打开左栏各项（记录者 ⌘1 至 ⌘6，使用方 ⌘1 至 ⌘4） |
| ⌘[ / ⌘] | 后退、前进 |
| ⌘, | 设置 |
| ⌘L | 锁定 |

口令门、向导或弹出的卡片开着时，快捷键不起作用。

#### 4.2 列表与详情

列表页（记录存证、待上链、账本、授权、我的授权）顶上有一格搜索。记录存证、账本、授权、我的授权四页的搜索格旁另有「开始日期」「结束日期」两格：点开是一张月历，选一天即填上，「今天」「清除」在月历底下。设了日期，列表只留上链区块时刻在这两天之间（含两头）的行，还没上链的行不列；日子按「设置 > 语言和时间」的时区算。窗口窄时两个日期格排到搜索格下面一行。

要从一张清单里挑一项的地方（新建授权的「选择记录」与「最近地址」、地址簿、注记的目标条目、切换身份），点开都是一张带搜索格的浮卡；清单里有时刻的（选择记录、注记的目标条目）也带两个日期格；导出记录包时挑条目的「选择条目」卡同样带搜索格和两个日期格。点一行进入这一条的详情页，用工具栏的后退箭头或 ⌘[（Linux 等其他系统上 Ctrl+[）返回。详情页往下滚时，页题出现在工具栏上。

窗口变窄时，带旁栏的页面（新建授权、起草转授权、导出记录包）会把旁栏排到表单下面。

#### 4.3 页顶提示条

以下情况页面顶上挂一条提示，一次只挂一条：

| 提示 | 情形 |
|---|---|
| 「账本已断链,当前只读」 | 账本检查发现断链。点「去恢复」到「设置 > 本机数据」，从整机备份恢复，或在「高级选项」里对账 |
| 「账本已移交给新密钥,当前只读」 | 这本账已移交出去 |
| 「只读:…」或「只读:未取得锁」 | 同一个数据目录已被另一个 ZIKARON 窗口占用，这个窗口只能读 |
| 「旧数据 · 日期 · 仅供查看」 | 正在查看被替换下来的旧数据；按「返回」回到当前数据 |

#### 4.4 按钮与确认卡

**按钮颜色表示角色：**

- **蓝键**：这一屏的主要动作，一屏至多一个。
- **白键**：其他动作。
- **白底红字键**：打开确认卡，或进入下一步，本身不写入。
- **红色实心键**：按下即写入账本或发上链，只出现在最后一步的确认卡上。

**写入流程。** 凡是写入账本或上链的动作，都先出一张确认卡：逐行写出要写什么、写到哪里、费用多少，末尾一句不可撤回的提醒。在卡上按红色实心键才真正写入；按「取消」或 Esc 不写。

**卡片通用规则：**

- 卡片一次只开一张，卡外点击不起作用。
- 机器数据（条目 ID、交易哈希、原始判定等）收在「详细信息」折叠里，不常用的选项收在「高级选项」折叠里。

**耗时动作。** 按钮里显示进度，完成时打勾；失败时变红并抖一下。

#### 4.5 提示（吐司）

操作结果以一张小卡出现在页面顶部中间，一次只显示一张，新的替换旧的。

- **普通提示**：显示约 3 秒。
- **错误提示**：第一行说发生了什么，第二行说下一步怎么做，显示 6 秒。带「关闭」；有原始信息时再带「详情」，展开后提示停住，直到按「关闭」或「收起详情」（收起后再显示 6 秒）。
- **提醒提示**：以「提醒:」开头，显示 6 秒。
- 任务完成时你已经离开它的页面的，提示上带「查看」，按下回到那一页。

**哪些事会提示：**

- 你按下去的操作，完成或失败时各提示一次。
- 应用自己在后台读数据，只在失败时提示；其中网络失败不弹提示，只在状态行显示「同步失败」。
- 卡片上的错误直接写在卡上，原句在「错误详情」里。

#### 4.6 拖放与选择文件

**拖放区。** 可以拖文件进来，也可以点一下打开系统的选档框；在选档框里按取消什么也不变。

- 一个拖放区一次只收一项。拖进多个文件时提示「一次只能拖入一项。多个文件先放进一个文件夹。」，一个也不收。
- 例外：「新建存证」卡里的拖放区收多个文件（批量存证），记录包的附件区也收多个；「添加授权」卡拖入多个文件时只取第一个。

**整窗拖放。** 在没有自己拖放区的页面上，把一个文件拖到窗口任意处：

- 记录者：打开「新建存证」。
- 使用方：转到「核验记录」并立即核验。

**选择路径。** 需要文件夹或文件路径的地方，一行显示已选的路径（没选时写「未选择」），旁边是「选择文件…」或「选择目录…」。输出位置同样用「选择目录…」选：记录包、授权文件、凭证和快照默认放在数据目录里的 `kits` 文件夹；备份和镜像默认上一次的位置（第一次要自己选）；密钥文件没有默认位置，要先选。

## 5 · 口令、锁定与恢复

#### 5.1 口令门

设过口令的机器，每次打开 ZIKARON 先出口令门：「输入口令」，下面八个格。

- 输满 8 位即自动验证，验证时显示「正在验证…」。
- 输错时整排抖一下，提示「口令错误,还可再试 N 次」。
- 连错 5 次，卡片变为「已锁定」，只能走恢复。

错误次数记在盘上，重开应用也不清零。这一道限制挡的是有人坐在这台机器前随手试；有人把密钥库文件拷走的话，挡住他的是口令本身和每试一次都要跑的加密计算。

另外两种情况：

- 如果密钥库文件的加密参数低于本机标准（例如被人改低过），开锁时提示「加密参数低于本机标准。」「输入口令,按本机标准重新加密。」，这一次不计错次，输入正确口令后按本机标准重新加密。
- 开锁或设口令时发现密钥库文件损坏，会提示「密钥库文件已损坏。」，库不会被改动。
- 启动时密钥库文件就读不成，口令门那一侧显示「密钥库读不成」，并写出原因和那份文件的路径；不进首启向导，也不新建密钥库（里面的密钥还在那份文件里）。修好或挪开那份文件后重开应用。

#### 5.2 锁定与自动锁定

按左栏「锁定」或 ⌘L（Linux 等其他系统上 Ctrl+L）立即锁定：

- 内存里的主钥清掉，数据目录关闭，页面上读出的数据清空。
- 后台工作不再新起：账本检查、授权复核、撤销监测、待上链发送与等待收据。正在发送或等收据、正在写入的任务会先做完，主钥随后清掉。
- 锁着时，要用密钥的动作被拒：「密钥库锁着。」「输口令解锁后再做这一步。」

解锁后，数据目录重新打开，并补做一次：该跑的账本检查和授权复核照跑，待上链队列继续等收据。

**自动锁定**在「设置 > 身份密钥」里，出厂开着：空闲满「闲置时长」（1、5、15、30、60 分钟，默认 15 分钟）即自动锁定。键盘或鼠标的任何动作都重新计时。关掉后只在按「锁定」或退出时锁定。已经发出去的交易不受锁定影响。

#### 5.3 忘记口令

在口令门按「忘记口令」进入「恢复」。只有**主身份**的凭据能重设口令：

- **主身份是助记词身份**：卡上写「输入主身份的助记词以重设口令。」，填 12 个词。
  - 整段助记词可以粘进任一格，从那一格起自动分开。
  - 每一格都以圆点显示，不在词表里的词会标红。
- **主身份是导入的本机身份**：卡上写「用主身份的密钥文件重设口令。」。按「选择文件…」选主身份导出的密钥文件，再填「文件密码」。

填好后设新口令（输两遍）。恢复成功后错误次数清零，旧口令作废，提示「已恢复,口令已重设」。

- 用次要身份的助记词或密钥文件来恢复，会被拒：「这是次要身份的助记词或密钥文件。」「只有主身份能恢复口令;用主身份的,或从备份恢复。」
- 如果密钥库还没记下哪个是主身份，两种方式都会给出；这一次开锁后即记下主身份。
- 按「取消」回到输口令的卡片。

#### 5.4 在口令门从备份恢复

恢复卡片底部有「从备份恢复…」：

1. 选整机备份文件，填「备份密码」，按「恢复」。
2. 出「以备份替换本机?」：写备份的名字和内容，便条「会以备份替换本机的身份与数据,本机有而备份里没有的都会失去。」。按「替换」。
3. 「设置新口令」，输两遍。

本机的身份、密钥和数据整份换成备份里的，用新口令重新加密，错误次数清零。常见拒绝：

| 提示 | 情形 |
|---|---|
| 「备份密码错误。」 | 备份密码不对（不计口令错次） |
| 「不是 ZIKARON 备份。」 | 选的不是备份文件 |
| 「备份来自更新的版本。」 | 需先升级应用 |
| 「备份内容不成形。」 | 备份文件已损坏 |

#### 5.5 重置空密钥库

设了口令但还没建成任何身份，又连错 5 次时，库里没有可以恢复的东西。卡上写明这一点，只给一个「重置密钥库」：

- 按下删除这份空密钥库，回到向导第 1 步。
- 之后设新口令即产生一枚新主钥。封在旧主钥下、再也打不开的本机数据，会被原样挪到机器目录的 `set-aside` 文件夹，不删除。
- 库里只要还有身份，这个按钮就不会出现。

## 6 · 记录者：一条完整的走法

**记录者席**（左栏顶上选「记录者」）：

1. **首次启动。** 按第 3 节走完向导：设口令、创建身份、选「以太坊主网」、创建账本，给记录者地址转一点 ETH，导出整机备份。
2. **存证。** 把作品文件拖进首页的拖放区，写「记录名称」，按「加入账本」，在确认卡上再按「加入账本」。
3. **上链。** 点首页的「待上链」卡（或到「记录存证」的「待上链」分段按「全部上链」），在「上链」卡上按「确认上链」。
4. **授权。** 到「授权」按「新建授权」：
   1. 填被授权方地址。
   2. 按「选择记录」选一件已上链的记录。
   3. 拖入条款文件，选有效期。
   4. 按「加入账本」，确认卡上再按一次。
   5. 然后像第 3 步一样把它上链。
5. **交付。** 在授权详情里按「复制授权码」，或「导出授权文件…」，发给对方。授权文件带着你的账本，对方能做完整核验。
6. **日常。** 看「提醒」页；需要时在授权详情里按「撤销授权…」。

## 7 · 记录者各页

#### 首页（记录者）

**左上：拖放区**「拖入记录以存证」。拖进一项或点选一项，打开「新建存证」。

**右上：「待上链」卡**，显示队里的条数，有三种状态：

- 「点击卡片上链」：点它直接打开「上链」卡。
- 「正在等待上链」：交易已发出，在等确认。
- 「已全部上链」。

**中间三格**，整格可点：

| 格 | 显示 | 点它去 |
|---|---|---|
| 「账本状态」 | 上一趟账本检查的结论「正常」或「异常」，下面「共 N 条」 | 账本页 |
| 「记录存证」 | 没被删除的存证条数，下面是最新一件的名字 | 记录存证页 |
| 「30 天内到期」 | 按链上时间 30 天内到期、没撤销的授权份数 | 授权页 |

- 还没读到数据时写「尚未读取」。
- 「30 天内到期」还没有链上时间时写「无链上时间」。

**「最近」**：账本最近五条，含序号、类型、摘要和上链状态，点一行进入它的详情。没有条目时写「暂无条目」。

### 存证上链

左栏「记录存证」。工具栏右边是分段「全部」|「待上链 N」。

「全部」分段从上到下：

- 拖放区「新建存证」。
- 搜索格「按记录名或内容指纹找」，旁边「开始日期」「结束日期」按首锚区块时刻筛。要看一份文件在不在这本账本里，把它的 SHA-256 填进搜索格。
- 记录表，列为「记录」「上链状态」「首锚区块时刻」「条目编号」，最新的在上。被删除的记录名划掉。

#### 新建存证

「新建存证」卡分两步。

**第一步：填写。**

1. 把文件、文件夹或 Git 仓库拖进卡里的拖放区，或点它选择。指纹在后台算，算好之前卡上的「加入账本」（或「立即上链」）显示「正在计算指纹」并转圈，不能按；附了几个文件时，确认后那一键显示「正在记录」，记完卡片才关。内容指纹这样算：

   | 类型 | 算法 |
   |---|---|
   | 文件 | 文件字节的 SHA-256 |
   | 文件夹 | 连同各文件名和内容一起算 |
   | Git 仓库 | 按当前提交算 |

   框里显示「已选:…」；要换就点框（「点按更换」）。「记录名称」为空时会自动填上名字（文件去掉扩展名，文件夹或仓库用全名）。
2. 填「记录名称」。
3. 可选的「为谁留证(可选)」折叠有四格：「应用」「对方身份(0x…)」「对方编号」「对方角色(可选)」。
   - 填了任一格，前三格都必须有，对方身份必须是 `0x` 加 40 位十六进制。
   - 这些字原样写进存证条目，本应用自己不读。
4. 可选的「高级选项」：「关联 Git 仓库(可选)」。
   - 下方读数：没登记仓库时是「未关联仓库」；按「添加仓库」后是「已关联,尚未检查」；按「检查新提交」后是「上次存证后新增 N 个提交」。
   - 「添加仓库」把选定的仓库记进设置。
   - 「检查新提交」对已记下的仓库重新计算新增提交数。
5. 按「加入账本」（开了「自动上链」时这个键写「立即上链」）。便条：「存证后不可修改,只能添加注记。」；开了「自动上链」时便条为「存证后不可修改,只能添加注记。上链需支付 Gas 费。」

**第二步：确认。**

- 卡上列出「文件」「为谁留证(可选)」「费用」，内容指纹和账本位置在「详细信息」里。
- 按红色的「加入账本」即写入账本并排进待上链队列，提示「#N 已加入待上链,共 N 条」，下面一行「待进入账本手动上链」（离线时为「当前离线,上链前需核对」）。
- 按「上一步」回去修改。
- 开了「自动上链」时，写入后直接估算 Gas 费，打开「上链」卡；卡上包括队里所有可发的条目。

**批量存证。** 往卡里的拖放区一次拖进两份以上文件，就成为一批：

- 框里写「已选 N 个文件 · 逐条签入」，列出文件名，「清除」可清空。
- 确认后一个文件写一条存证（指纹是文件字节的 SHA-256），「记录名称」写进每一条。
- 中途有一件失败即停下，已签入的不撤回，提示「签入 N 条后停在第 K 件:文件名 · 原因」；未处理的文件留在表里，处理后可再按。
- 批量里不能夹文件夹。

每签入一个文件（单个文件，或批量里的每一件），这台机器记下当时的文件名和位置，供导出记录包时找原件用；文件夹和 Git 仓库不记。

#### 记录详情

点记录表的一行进入。页题是记录名，下面写「#N · 存证」和上链状态。

**「基本信息」：**

- 「上链状态」「首锚区块时刻」「条目编号」。
- 「文件」：这台机器签入时的文件名。

「详细信息」里是「内容指纹」「条目 ID」「前一个条目」「大小(字节)」「上链交易」。

**按钮：**

- 还在待上链队列里：「现在上链」。
- 不在队里：「授权给他人」，要状态为「已确认」才可按；未确认时提示「上链后才能授权给他人」，或「等待本次确认」。
- 「导出记录包」。
- 页底：「删除存证…」。

#### 删除存证

按「删除存证…」，出确认卡「删除这条存证?」，便条「存证将标为已删除,已发出的授权不受影响。」。按「删除」。

- 账本里写入一条「删除条目」指向这条存证；原条目一个字节不动。
- 这件记录此后划掉显示，详情页上注明「已被条目 #N 删除,不能再授权。」，详情页不再出授权与导出的按钮，新建授权也选不到它。

删除条目本身是否上链，看被删的存证有没有公开过：

| 被删的存证 | 结果 |
|---|---|
| 还在队里没发出，或从没上链 | 存证从队里拿掉，删除只记在本地。两条分别显示「已删除」和「本地删除」，提示「已删除(条目 #N),不上链」 |
| 已经发出、入块或上链 | 删除条目进待上链队列，像其他条目一样上链 |

第一种情形的两条只留在本机。在「设置 > 本机数据」打开「隐藏本机删除的条目」后，「记录存证」与「账本」的列表不再列出这两条；已经上链后才删除的照常列出。这只影响列表显示：条目编号、各处计数、账本检查和详情页都不变，关掉即恢复。

配了网络、账本还没检查过，而这条存证又不在待上链队列里时，删除会被拒：「账本尚未检查。」「点按边栏底部的「同步」。」

条目格式与读法见附录 C。

### 待上链队列

**待上链分段**（「记录存证」工具栏的「待上链 N」）：

- 表列序号、类型、摘要和入队日期；空时写「没有待上链的条目」。
- 表下是「本批」卡：估算前写「N 条 · Gas 费待估算」，估算后写「N 条 · Gas 费估算 …」（后面是 gas 数）；按钮「全部上链」和「同步」。发过一批后，多出「上一批」一行（「已上链 N 条 · 移出 N 条」）。已提交的一批若在当前网络设置里找不到那条链的节点，表下提示「有一批已提交,正在等收据;当前没有链 N 的节点,继续不了。」
- 点一行进入详情：「摘要」「加入时间」「同批上链」（「前 N 条」，已发出的写「已提交,等待收据」）和「首锚区块时刻」；还没发出的才有按钮「现在上链」。

**上链步骤：**

1. 按「全部上链」或「现在上链」，出「上链」卡。卡上写「条目」（「前 N 条」）和「Gas 费上限」；Gas 费估算在「详细信息」里。便条「上链后不可撤回,通常几分钟内确认」。
2. 每次打开卡都重新估算（之前估过的不沿用）。估算在后台进行，这时「确认上链」显示「正在估算」并转圈，不能按，「取消」可以按（上链期间不可按）。估算完成后，按「确认上链」：签名、发出交易、等待收据；这期间那个键显示「正在上链」并转圈。

一批里的全部条目装在同一笔交易里发出。

**Gas 费上限**按链上的实际费率计算：（基础费 × 2 + 小费）× 这笔交易所带的 gas 额度。额度是节点估出的 gas 数的 1.5 倍（向上取整），最多 20 万；估出的数超过 20 万即拒，不发。基础费取各节点都已到的那一块（几个节点链高不同时取最小的），节点之间只比基础费这一项。小费取同一块往前 20 块里各块成交小费的中位数，再取这 20 个数的中位数，最高 1 gwei；节点答不出、拒答、两个节点给的不一样或格式不对时按 1 gwei 计。读不到基础费时整组按保底（上限 3 gwei、小费 1 gwei；额度照样按估算定，最多 0.0006 ETH）计，确认卡上的上限即按保底算出，卡上不会注明这是保底数，下一次打开确认卡会再问一次链。Gas 估算按同样的规则取块（各节点都已到的最低一块）。只问这一条链的节点。在 Arbitrum One、OP Mainnet 这两条二层网络上，小费同样按链上实际成交算，通常远低于 1 gwei，所以预留与实付都只有主网的零头。

**发出前的检查：**

- 余额不够付上限时一笔也不发，提示「余额不足。」「需 N ETH,当前 N ETH。」，提示上带「复制地址」，方便去充值。
- 估算失败时，卡片变成「无法估算 Gas 费」，写出原因，可按「重试」。
- 账本锁着或已断链时不能发送。发出前还会现读一次链：链上有本机没有的记录时拒绝，提示「账本不是最新」「链上有 N 条记录不在本机」。

**发出之后：**

- 30 秒内入块：提示「已上链 N 条」。
- 超时未入块：提示「已提交 N 条,等待确认」，之后每 15 秒再问一次收据。
- 关掉再开应用，会接着等那一笔交易的收据，不会重发。
- 收据显示执行失败：提示「交易已发送,但在链上执行失败。」，这些条目留在队里，可以重发。

**节点拒绝时的提示：**

- 交易本身被拒：「交易序号已被占用。」「交易已提交,等待确认。」「Gas 费出价过低。」「Gas 上限不足。」「登记合约拒绝了交易。」
- 节点限制或配置：「节点请求受限。」「节点不支持发送交易。」「节点需要访问凭据。」「节点与所选网络不符。」
- 连接问题：「无法连接任何节点。」「节点未在时限内应答。」「节点应答过长。」「节点应答无法解析。」「无法与节点建立安全连接。」
- 其他情形：「节点拒绝了交易。」，节点原话在详情里。

**上链状态词**（各页通用）：

| 状态 | 含义 |
|---|---|
| 「待上链」 | 在队里，还没发出 |
| 「正在等待上链」 | 交易已发出，等待入块 |
| 「确认中」 | 已入块，等待账本检查确认 |
| 「已确认」 | 账本检查确认它已锚定 |
| 「已确认 · 上次核 月-日 时:分」（列表里简写为「已确认 · 时:分」） | 本次检查还没回来，照上一次的结论；超过一天变灰 |
| 「已回滚」 | 交易在链上执行失败，留在队里可重发 |
| 「未发出」 | 发出前就被拒（如余额不足），留在队里 |
| 「未上链」 | 不在队里，也没上链 |
| 「已删除」「本地删除」 | 见「存证上链」一节的「删除存证」；详情页的「上链状态」把被删的存证写作「已删除,不上链」 |

需要「已确认」才能做的事（例如起草授权时选记录），只认本次的检查结论。

**自动上链。** 「设置 > 网络」的「自动上链」开关（默认关）：

- 关着：写入账本的按钮写「加入账本」，写入后留在队里等你发。
- 开着：按钮写「立即上链」，写入后直接估算 Gas 费并打开「上链」卡。

这个开关适用于存证、授权、撤销等所有写入。

### 账本内容

左栏「账本」。工具栏右边：

- 「更多」菜单：「导入已有存证…」「换密钥或移交…」「添加注记…」「为他人签认领…」。
- 分段「全部」「待上链」「授权」。「待上链」列出所有还没确认的条目。

**账本状态行**（页面顶上）：「账本状态 · 正常/异常 · 共 N 条」。

- 根条目还没确认上链时，加红字「根未确认上链」。
- 有可发的条目时，右边有「全部上链」。
- 点这一行展开账本检查卡。

**条目表**，最新在上：

- 列为序号、类型、摘要、首锚区块时刻和上链状态。
- 删除条目的摘要写「删除存证 · 记录名」；不合约定的写「删除无效:…」（见附录 C）。

**条目详情**，点一行进入：

- 存证：「记录」「上链状态」「首锚区块时刻」。按钮「导出记录包」、「用于授权」（已确认才可按）。
- 授权：见「授权列表」一节的「授权详情」。
- 其他条目：「摘要」「上链状态」「首锚区块时刻」。
- 通用按钮：
  - 还在队里的：「现在上链」。
  - 没上链也不在队里的：「排进待上链」。已经上链过的条目排不进去：「这一条已经上链了。」「不必再排队。上链状态来自上一次同步,拿不准可先同步一次。」
  - 已确认的非存证条目：「注记…」。
- 「详细信息」：「条目 ID」「类型」「序号」「作者」「前一个条目」「大小(字节)」「上链交易」。

### 账本检查

账本检查把本机账本逐条和链上的锚对一遍。它什么时候跑：

- 按「设置 > 通知」的周期自动跑，默认 300 秒；周期为 0 时不按周期跑，只在按「同步」或下一条的情况下跑。
- 这一处账本还没有检查结论，或账本变过（新写了条目、一批上了链）时，立即跑一趟。
- 前提是节点、链 ID 和登记合约都已配置。没配时显示「未检查:尚未配置网络」。

检查卡题为「账本检查 · 通过/有缺项/未通过」，逐项一盏灯一个数：

- 「已上链」「尚未上链」
- 「与链上不符」「发现的问题」「已排除」
- 「导入未证实」「无法识别的类型」「格式错误的条目」
- 「无法查询」「未证实」「作废」「弃置」

下面一句「共 N 条 · 每 N 秒检查」；原始结论在「详细信息」里。

- **「正常」的条件**：有检查结论、没断链，且问题类各项都是零。还没上链的条目不算问题。
- 删除条目在检查里算作无法识别的类型；它们的条数正好等于删除条目数时，这一项显示为绿灯「约定条目 N 条」。
- 结论为「未通过」（断链）时，整个账本转为只读，页顶挂断链提示条。

#### 注记

「添加注记…」或条目详情里的「注记…」打开「注记条目」卡：

1. 写「注记内容」（必填）。
2. 「目标条目」旁按「选择…」，在浮卡里搜索（按序号、类型或摘要，也可按首锚区块时刻的日期范围）并点选要注记的那一条；也可以在「高级选项」里「或粘贴条目 ID」。
3. 按「添加注记」即写入。

注记另存为新条目，原条目不变。

### 导入上链存证

把这把密钥早先上链、但不在账本里的锚收进账本。打开「导入已有存证」卡：

- **「密钥地址」空着**：列出本机密钥早先发过、账本里没有的锚。这份清单来自上一趟账本检查，需要配好网络并检查过一次，否则显示「未读链」。
- **填一个地址**（旁边「地址簿」可选）：扫链列出那把密钥发过的锚。

**表格。** 每行一个开关，列为「时刻」和「状态」；块号和摘要在「详细信息」里。状态有：

- 「通过」：默认勾选，只有这一种能导入。
- 「交易不存在」「发送者不符」「摘要不符」
- 「已在账本」

**导入别人的地址时，**下面多一段「对方签字」：

1. 把「文本」复制给那把密钥的持有人（「发给这把密钥的持有人,签回后粘贴。」）。
2. 对方签回后，把签字复制到剪贴板，按「签字」旁的「粘贴」。签字当场核验，灯显示「等待」「通过」或「不符」。

没有签字也能导入，只是那几枚锚记为未证实。账本再写新条目后需要重签。

**手填。** 「手填」折叠里可以手打几行锚（一行一枚），按「核验这几行」。

最后按「导入 N 枚」：写一条导入条目，进待上链队列。

**为他人签认领。** 你是对方要认领的那把密钥的持有人时，在「更多」里选「为他人签认领…」：

1. 粘入对方发来的文本。卡上写出几枚锚；谁要认领和对方账本头在「详细信息」里。
2. 输入本机口令签字。
3. 把签字复制，发回给对方。

文本读不懂时提示「这一段不是一份认领的字。」

### 移交账本

「换密钥或移交…」打开卡片，分两步：

1. 填三格，按「确认移交」：
   - 「新密钥地址」：填好即自动检查。新密钥必须没有上链存证，读数写「新密钥有 N 条上链存证」，零条才能继续。
   - 「方式」：「仅换钥」或「交给他人」。
   - 「说明」（可选）。
2. 核对后按红色的「确认移交」才写。

便条：「新密钥须无账本,移交不可撤销。」移交后这本账由新密钥续写，本机转为只读，页顶挂「账本已移交给新密钥,当前只读」。

### 授权列表

左栏「授权」。工具栏右边是蓝键「新建授权」。

**授权列表：**

- 搜索格「按被授权方、记录或状态找」，旁边「开始日期」「结束日期」按这份授权条目上链的区块时刻筛。
- 表列「记录」「有效期」「授权编号」「状态」和上链状态。
- 状态按链上时间判断：「有效」「已到期」「未生效」「已撤销」「未知」。
- 没有授权时写「还没有授权」。

### 起草授权

进入方式：

- 授权列表的「新建授权」：表单清空。
- 记录详情的「授权给他人」，或条目详情的「用于授权」：已预填这件记录。

表单各格：

- **「被授权方」**：粘贴 `0x…` 地址；右边「最近地址」打开一张带搜索的浮卡，列出地址簿和以前的被授权方。
- **「哪一条记录」**：按「选择记录」打开一张大浮卡，每行三栏：条目编号、记录名称、首锚区块时刻（还没上链写「未上链」）；可搜索，也可按首锚日期筛。只有已上链的记录能选，其余灰着并注明原因：
  - 「上链后才能授权」
  - 「上链中,请稍等」
  - 「等待本次确认」
  - 「已删除」
- **「条款文件」**（必填）：把条款文件拖进来或点选。
  - 选好后显示文件名和大小；「更换…」换一份。
  - 文件的 SHA-256 自动填进「高级选项」里的「条款文件指纹」，并注明「已从条款文件填入」。
  - 签发时这份条款文件在数据目录里留一份，之后随授权文件和记录包交给对方，对方可以自己重算指纹核对。
- **「有效期」**：「7 天」「30 天」（默认）「90 天」或「自定义」。
  - 预设按链上时间起算。还没有链上时间时提示「无链上时间,无法使用预设:先同步,或选择自定义」，请先同步或改用自定义。
  - 「自定义」填「起始(秒)」「截止(秒)」（Unix 秒）。
- **重叠检查灯**：「时段重叠的有效授权:N」，数的是同一件记录上、本机标为独占、时段重叠且未撤销的授权。
- **「独占、转授权与范围」折叠**：
  - 开关「独占授权」：「仅本机记录,签发后不可更改」。独占标记只记在本机，不写进授权；独占的约定应写在条款文件里。
  - 「上游授权(转授权用)」
  - 「使用范围」

被授权方、条款文件指纹、上游三格里的地址或哈希必须全小写。含大写字母时提示「地址含大写字母,改为全小写后再签发」，签发键不可按。

**签发步骤：**

1. 按「加入账本」（或「立即上链」）。被授权方、记录、条款文件指纹三样齐了才可按；有效期用预设时，还要先有链上时间。
2. 出确认卡「签发授权」：「记录」「有效期」「条款文件」「费用」，被授权方和各项指纹在「详细信息」里。便条「签发后只能撤销,不能修改」。
3. 在卡上再按一次即签发，提示「已签发 #N;N 条待上链」。之后照「待上链队列」一节上链。

同一件记录上已有独占授权且时段重叠时，拒绝签发，弹出「独占授权冲突」，列出撞上的授权；按「取消」关掉。

### 签发前检查

新建授权页的旁栏「签发前的检查」是一张两步清单：

- 两步是「填写条款」和「起草首份授权」，下面显示密钥余额。
- 可以在「哈希或说明」里写备注，按「标记完成:…」勾下一步；「重置清单」重来。
- 清单存在数据目录里。

#### 授权详情

点授权列表的一行进入。页题「#N · 授权」。

**「基本信息」：**

- 「记录」「有效期」「状态」「上链状态」「首锚区块时刻」
- 「独占」：「是 · 仅本机记录」、「是 · 仅本机记录 · 无条款文件」（早先版本记下的独占标记）或「否」
- 「所附条款文件」：文件名，或「无条款文件」

「详细信息」里有被授权方、条款文件指纹和条目的各项机器数据，以及「查看撤销历史」。

**按钮：**

- **「复制授权码」**：把 `zikaron-grant:…` 授权码放进剪贴板。转授权的授权码带着到根的每一跳，与这份授权的凭证和授权文件里的那一份同一串。
- **「导出授权文件…」**：在「保存位置」写出一份 `grant-<授权条目 ID 前十位>.zkgrant` 文件，同名已有即往后编号。
  - 文件里有授权链各跳的条目、签发者账本、条款文件和授权码。
  - 导出前会现读一次链，读不到链时拒绝；链上有本机没有的记录时也拒绝，提示「账本不是最新」「链上有 N 条记录不在本机」。
  - 完成提示写明位置、授权链几跳、条款文件几份。
- **「现在上链」**：还在队里时出现。
- 页底 **「撤销授权…」**：还没撤销时出现。

### 撤销授权

按「撤销授权…」出「撤销这份授权」卡：

- 卡上写「记录」「原有效期」；「详细信息」里有被授权方，以及一格「裁决文件指纹(可选)」。
- 便条：「撤销后不可恢复,对方将收到提醒」。

按「确认撤销」写入撤销条目，进待上链队列。上链后，对方的撤销监测会发现它。

### 记录包

从记录详情或条目详情的「导出记录包」进入，那一条已经选上。

**条目范围。** 「条目范围」一行显示「全部 N 条」（什么都不选即整本）或「已选 N 条」。

- 按「选择…」打开「选择条目」：顶上一格搜索和「开始日期」「结束日期」，每条一个开关，可以挑任意几条。「全部」选上搜索与日期留下的那几条，「取消选择」全清。
- 所选授权的撤销条目、账本的创建条目和移交条目会自动一并带上，核验方要靠它们认出这是谁的账本。
- 所选里有还没上链的条目时，红字提示「所选里有 N 条还没上链:包里没有这几条的上链证明」，旁边「现在上链」。

**所选记录的原件。** 列出所选存证当初在这台机器上签入的文件，可以逐件「移除」。

- 原位置已经没有文件时注明「签入时的位置已没有这份文件」。
- 文件被改动过时注明「不是所选记录的原件,不随包」。

**附件(可选)。** 拖入文件或文件夹。每项显示在包里的名字（「导出为 files/…」）。

- 包内文件名只能用小写字母、数字、`.`、`_`、`-`。不合的名字会自动转写：转小写，一段不合法的字符换成一个 `-`，去掉首尾的 `-` 和 `.`，在扩展名前加 `-` 和原名摘要的前八位（如 `name-1a2b3c4d.pdf`）。
- 改过名时，包里带一份原名对照表 `files/zikaron-names.json`。
- 转不出合法名的那一行标红「文件名无法转换,请重命名。」，这时不能导出。
- 附件必须是所选记录的原件，其他文件不随包。

**其余设置。** 「附言」写一段附言；「保存位置」默认数据目录里的 `kits`。

**导出。** 按「核验并导出」：

1. 先现读一次链。链上有本机没有的记录时拒绝，提示「账本不是最新」「链上有 N 条记录不在本机」。
2. 在保存位置建一个 `kit-<所选最早一件记录的指纹前八位>` 文件夹（所选里没有记录即 `kit`），同名已有即往后编号。
3. 包先自验，通过才写出，提示「记录包已导出到 …」。

写不成时按原因提示：

| 提示 | 原因 |
|---|---|
| 「无法写入这个位置。」 | 保存位置不可写 |
| 「保存位置已有同名的东西。」 | 同名冲突 |
| 「有文件名无法放进包内。」 | 文件名无法转写 |
| 「包内有两份文件用了同一个名字。」 | 包内重名 |
| 「包没有通过自验,没有保存。」 | 自验失败 |

**包里写明锚在哪条链。** 导出时，包的附言末尾自动加一行，不随界面语言变：`anchored-on: eip155:<链 ID> · registry <登记合约> · from <起始区块>`，取自导出那一刻这个数据目录的网络。

- 没配网络就不加这一行。
- 附言本来就以这样一行结尾时，先去掉再加，再导出不会重复。
- 「本机导出过的记录包」那份索引里，附言仍是你写的原文，这一行另记一格。
- 这一行只是指路：核验时不按它判，只按它提示要添加哪个网络（见「记录核验器」）。

**旁栏：**

- 「收件方如何核验」：对方在「核验 > 核验记录」拖入记录包即可。
- 「读数与基准(不进包)」：按「计算」算出所选第一件存证的「首次存证」「最大深度」「连续上链」三个读数。这些读数只显示在页上，不进包。
- 「本机导出过的记录包」：这台机器从这本账导出过的每个包各一段。
  - 可以设「取处」，即这个包在网上的 https 地址；空着即用发布地址加包的路径。
  - 「删除本机副本」按两下删除本地的包文件夹，账本不动。

### 深度

深度读数说明一件记录在这本账里存在了多久、上链有多连续，有三项：「首次存证」「最大深度」「连续上链」（已上链 / 跨度），在这几处看得到：

- 记录者：「记录包」页旁栏的「读数与基准(不进包)」，按「计算」。
- 使用方：「记录核验器」里填了「记录哈希(可选)」时。
- 尽调：「他人账本」页填了「记录哈希(可选)」时，「详细信息」里有「最大深度」；有只读网络这一次没读成而没读到锚时，写「未读链」。

命令行的 `depth` 动词用的是同一套算法。

## 8 · 使用方

#### 一条完整的走法

**被授权方席**（左栏顶上选「使用方」）：

1. 第一次打开应用时，向导按记录者走：设口令、建身份、选网络、创建账本（免费，只写本地），其余可以以后再做。
2. 在左栏顶上切到「使用方」。使用方的账本只在转授权时才需要，到时在转授权页按「开账…」即可。
3. 在首页「核验一份授权」卡里贴入对方发来的授权码，按「开始核验」，看结果。
4. 到「我的授权」按「添加授权」，贴授权码或拖入授权文件，按「核验并添加」，把它收进库里。
5. 收到作品文件后，到「核验 > 核验授权」，把授权、文件和条款文件一起放进去，按一次「核验」，三件一起核对。
6. 看「提醒」页：授权快到期、被撤销、签发者账本被移交，都会在这里出现。

#### 首页（使用方）

- **左上「核验一份授权」**：贴授权码，按「开始核验」，转到「核验授权」看结果。
- **右上拖放区「拖入记录包以核验记录」**：拖入或点选记录包，转到「核验记录」并立即核验。
- **三格**，整格可点：

  | 格 | 显示 | 点它去 |
  |---|---|---|
  | 「需要处理」 | 复核过而没全部通过的授权份数 | 我的授权 |
  | 「有效授权」 | 在有效期内的授权份数，下面「N 个签发者」（库里全部授权的签发者数） | 我的授权 |
  | 「核对收到的记录」 | 上一次授权核验里文件是否「相符」 | 核验授权 |

  - 本次还没复核时：「需要处理」照上一次的结论显示，并注「上次核 月-日 时:分」；「有效授权」显示持有的总份数，注「未核验」。
  - 「核对收到的记录」只看这一次运行里的授权核验：还没核过，或核验时没放文件，显示「--」。
- **「最近」**：这一次运行里的核验结果、撤销监测提醒和待上链条数，点一行进对应的页面。没有时写「暂无活动」。

### 授权库

左栏「我的授权」。工具栏：分段「全部」|「按签发者」、「重新核验」、蓝键「添加授权」。卡片上方有搜索框「按记录、签发者或判定找」，以及「开始日期」「结束日期」两格，按每份授权的上链时刻筛选。

#### 添加授权

「添加授权」对话框：

- 在「粘贴授权码」里贴入授权码，或把授权文件拖进「拖入授权文件」。授权码若带着转授权链，链上各跳一并收下。
- 拖入授权文件时当场显示「… 已验证 · 授权链 N 跳 · 条款文件 M 份」。
- 贴授权码时提示：授权码不带签发者账本，只能核验签名和有效期；要完整核验，请让签发者导出授权文件。
- 可选「授权备注」「签发者备注」，只存本机。备注只记在这次添加的那一份授权（转授权链的最末一跳）和它的签发者上，链上更早几跳的签发者不受影响。

按「核验并添加」：

- 先核验签名和格式；任何一份不通过，这次一份也不收，对话框不关，写出原因。
- 库里已有且完全相同的会跳过；全部都已在库里时提示「该授权已在「我的授权」中。」，对话框不关。
- 授权文件会在数据目录里留一份，其中的签发者账本以后用于核验。

#### 授权卡片

每份授权一张卡：判定、记录名、签发者、有效期，和这份授权在签发者账本里的上链时刻（还没读到时写「上链时间未读取」）。

- 判定有「全部通过」「有缺项」「未通过」「已被撤销」。
- 本次还没复核的，显示上一次的判定并注「上次核 …」，超过一天变灰。
- 从没复核过写「未核验」。
- 库里有读不成的文件时，页面顶上逐份注明「未通过的文件:…」。

点卡片进入详情：

- **「基本信息」**：
  - 「签发者」「有效期」「首锚区块时刻」
  - 「剩余」：如「N 天后到期」，按链上时间计算
  - 「上游」：「无(签发者即作者)」或上游账本的状态
- **状态提示**：
  - 被撤销：「签发者已撤销这份授权。」「由它派生的转授权同时失效。」
  - 有缺项：哪一处都没找到签发者账本时，提示缺少签发者账本；其余缺口（包括读不到链、没配节点）一律提示「这份授权还未确认上链:几分钟后再核验。」
  - 签发者账本已移交：「签发者账本已移交给新密钥」。
- **凭证卡**：「保存位置」和「生成凭证」。本次运行复核过且六项核验全部通过时，另有「转授权给他人」。
- **「高级选项」**：「上游账本目录(可选)」，按「保存上游」记下；留空保存即清除。
- **「详细信息」**：条目 ID、条款文件指纹、内容指纹、判定和六项原始结果。

#### 重新核验

「重新核验」逐份复核整个库：

1. 找签发者账本，先在本机找，再在保管库里找（收下的授权文件带来的账本，以及「保存上游」记下的目录）。
2. 扫链，更新每张卡片的判定，并记下这次的结论。这里只读主网络，不读只读网络：锚在只读网络上的授权在这里一直是「有缺项」，也不会出「转授权给他人」，撤销监测也看不到它；这样的授权请到「核验 > 核验授权」核。

复核也会按「设置 > 通知」的周期自动跑，默认 600 秒。前提是节点、链 ID 和登记合约都已配置。

### 上游账本

「我的授权」工具栏的分段切到「按签发者」，按签发者分组，有问题的组排在最上。组头写签发者账本的状态。还没复核过的单列一组「未核验」。

### 凭证

凭证是给第三方（例如你的顾客）看的授权证明，是一份文本和一张二维码。在详情的凭证卡上按「生成凭证」：

- 需要已配好网络，并现读一次链；链上有本机没有的记录时拒绝，提示「账本不是最新」「链上有 N 条记录不在本机」。
- 应用从库里把授权链一直接到根，在保存位置建一个 `badge-<授权 ID 前十位>` 文件夹，里面有 `badge.txt` 和 `badge.svg`（二维码）。
- 详情上显示「凭证已生成」和二维码。

对方在「核验 > 核验授权」贴入文本即可核验。

### 起草转授权

**入口。** 本次运行复核过、六项核验全部通过的授权，详情上有「转授权给他人」：

1. 出确认卡「转授权」：写「记录」「签发者」「上游有效期」，便条「上游授权撤销或到期后,转授权随之失效。」
2. 按「起草…」进入转授权页。这一步还不写任何东西。

**转授权页。** 上半写上游授权的信息，下半是与「起草授权」相同的表单：

- 记录固定为上游的那件。
- 有效期不会自动按上游封顶，请自己留意。
- 按「加入账本」（开了「自动上链」时写「立即上链」），确认卡题为「签发转授权」，再按一次即签发。

转授权写进你自己（使用方）的账本，进你自己的待上链队列。签完后表单下出现「去上链」和「待上链 N 条」。

**前提。** 转授权需要使用方有签名密钥和账本：

- 没有密钥：页面提示「尚未生成密钥。」，按「生成密钥…」。
- 没有账本：提示「还没有账本。」「先开账,再转授权。」，按「开账…」。

### 撤销监测

每次整库复核之后，应用检查两件事：

- 签发者是否撤销了你持有的某份授权。
- 签发者账本是否移交给了新密钥。

发现其中之一时：

- 窗口向系统请求一次注意（macOS 上程序坞图标会跳动），并出一条提示「提醒:我的授权已被撤销」或「提醒:签发者账本已移交给新密钥」。
- 「提醒」页末尾加一行红灯「撤销监测」，链接到我的授权。

同一件事只提醒一次。首次启动向导开着时不弹提示。

## 9 · 核验

左栏「核验」。两种角色都有「核验授权」「核验记录」和「查看他人账本」三个标签。首页与整窗拖放的去处仍按角色分：记录者拖入的文件进「新建存证」，使用方拖入的进「核验记录」。

核验不发交易。会写进本机的有三样：地址簿的增删，「存快照」写出的快照文件，和「核验记录」写出的核验结果档（见「记录核验器」）。

### 授权核验

一次准备好三样，按一次「核验」：

1. **「授权」**：贴授权码，或按「选择文件…」选授权文件。
2. **「文件」（可选）**：拖入或选择收到的作品文件。
3. **「条款」（可选）**：拖入或选择条款文件。

放上的文件显示名字和大小，「移除」可以去掉。

**「高级选项」：**

- 「账本目录(每跳一个)」：为授权链的每一跳手动指定签发者账本的目录。
- 「核验用节点(每行一个,可选)」「核验用登记合约(可选)」「核验起始区块」：预先填着设置里主网络的值，可以改；只决定主网络。
- 「核验时间点(秒,可选)」：空着即按链上时间。

**读哪些网络。** 核验读主网络，再加设置里全部「只读网络」；只配了只读网络、没配主网络时照样核，不报「未配置节点」。没读成的网络逐个写出名字和「不通」或「指纹不符」；这时没找到锚的「上链已确认」灰灯写「暂时读不到链」，下一步是「暂时读不到链:稍后再核验。」，不写「未确认上链」，因为锚可能在没读成的那条链上。

**签发者账本从哪里来。** 应用按以下顺序自动查找：

1. 本机：同一台机器上签发者的账本。
2. 保管库：收下的授权文件带来的账本，以及记下的上游目录。
3. 记录包：你指定的记录包或授权文件，以及正在核验的授权文件自带的账本。
4. 发布地址：签发者公布的 https 地址，逐个文件取回并通过包验证后才用。

结果卡里「作品」「有效期」「首锚区块时刻」下面，每一跳一行「账本来源:本机/保管库/记录包/发布地址」，一处也没找到写「无」。

- 可以按「更换…」或「添加…」手动指定一个 https 地址、记录包、账本目录或授权文件，再按「开始核验」。
- 取自发布地址时写「来自 https://… · N 个文件 · 已验证」，旁边「重新获取」。
- 哪一级读不成，都会逐级写明原因。

**结果卡**顶上三行：

| 行 | 显示 |
|---|---|
| 「授权」 | 「六项全部通过」「有缺项」或「未通过」；标签「有效」「待定」「无效」 |
| 「文件」 | 文件名；标签「相符」或「不符」（与授权指向的作品哈希比，多跳时比最末一跳） |
| 「条款」 | 文件名；标签「相符」或「不符」（与授权记录的条款指纹比） |

没提供的写「未提供」，读不出来的写「读不出」。下面是「作品」「有效期」「首锚区块时刻」。

**「六项核验」折叠：**

- 「授权签名」「签发者账本完整」「在签发者账本里」
- 「上链已确认」「在有效期内」「未被撤销」

**灰灯。** 没能核成的项是灰灯，旁边注明原因：

- 「缺少签发者账本」「签发者账本读不成」
- 「未配置节点」，旁边链接「前往设置」
- 「暂时读不到链」「未确认上链」「读不到链上时间」

下面按缺口各给一句下一步，例如：

- 「缺少签发者账本:拖入记录包或授权文件,或输入 https 发布地址后再核验。」
- 「这份授权还未确认上链:几分钟后再核验。」
- 「未配置节点:在设置中配置网络后再核验。」

**转授权（多跳）。** 每一跳各有一组六盏灯，跳与跳之间还有一盏「第 N 跳接上第 N+1 跳」。

**底部总结：**

- 「全部相符」（绿框）：授权六项全部通过，提供了的文件和条款都相符。没提供的不影响这个结论。
- 「N 项不符」（红框）：授权未通过，或文件、条款不符，每样算一项。
- 「未全部核成」：没有不符，但授权有缺项，或文件读不出。

「有缺项」永远不等于通过。

### 核对收到的记录

收到作品文件后，在「核验授权」页的「文件」一格放入它，与授权一起按「核验」：应用算出文件字节的 SHA-256，与授权指向的作品哈希比（多跳时比最末一跳）。结果卡「文件」一行显示「相符」或「不符」；「详细信息」里并排写字节数、实算摘要和应为摘要。换了文件要再按一次「核验」。使用方首页的「核对收到的记录」格显示上一次的结果。

### 记录核验器

左栏「核验」的「核验记录」标签（两种角色都有）。

把记录包文件夹、授权文件或单个记录文件拖进「拖入记录包或记录文件」，或点选；放入即核验，也可以按「立即核验」重来。取自发布地址时，结果卡顶上写「来自 https://… · N 个文件 · 已验证」，旁边「重新获取」。

**「高级选项」：**

- 「记录内容(可选)」：可填本地路径或 `https://` 发布地址；填 `http://` 地址时提示「仅支持 https 地址。」。
- 「记录哈希(可选)」

**结果卡「核验结果」**有三盏灯：

| 灯 | 可能的显示 |
|---|---|
| 记录包 | 「记录包完整,签名有效」、「记录包校验未通过:…」，或不是记录包（单个文件、条目文件夹）时「按单个文件核验」 |
| 与链上存证 | 「N 条与链上一致」「N 条未上链」，或读不到链（包括没配网络）、有网络没读成时「未与链上比对」 |
| 签发者账本 | 账本检查的结论；记录包只含账本的一部分时写「这是账本的一部分」；没读成时「签发者账本未读取」 |

**逐条记录。** 核验的是记录包、授权文件或发布地址时，下面有「逐条记录」表，包里每件记录一行：

- 「包内原件」：重算原件指纹并比对，结果为 ✓、✗ 或缺。
- 「上链状态」
- 「首锚区块时刻」

**结论：**

- 没有不符：绿框「全部相符」。
- 有不符：「有 N 处不符。」「查看错误详情,与对方核实后再接收。」
- 链没读成也算不符：读链失败算一处，没读成的网络里每件记录各算一处。所以包写明的网络没添加、没配网络或节点不通时，包再完整，结论也是「有 N 处不符。」。

填了记录哈希时，另外显示这件记录的「首次存证」「最大深度」「连续上链」三个读数。这一次有链没读成时，没有读数或读数不足的那几格写「未读链」。

**包写明的网络没添加时。** 记录包写明锚在哪条链（见「记录包」），而那条链连同登记合约既不是主网络、也不在「只读网络」里时：

- 包照核，上链不核，上链存证那一盏灯写「未添加」，逐条记录的上链状态是没读链。
- 页上一条提示：链名、「作者自述」、「请在设置中添加网络」，旁边「添加」。按「添加」到「设置 > 网络」，新起一栏，链 ID、登记合约、起始区块已经填好，节点自己填。

**读了哪些网络。** 结果卡里列出这一次读成的网络名。有网络（只读网络，或配了只读网络时的主网络）没读成的，逐个写出名字和「不通」或「指纹不符」；这时读成的链上找不到锚的记录，上链状态是没读链，不写「未上链」，因为它的锚可能在没读成的那条链上。链 ID、登记合约、每件记录首锚的区块号与交易号都在「详细信息」里，交易号写全；这次结果档的路径（写不成时是原因）也在「详细信息」的「结果档」里。

**核验结果档。** 每核一个记录包、授权文件或发布地址，就在机器目录的 `kits/verified/` 里写一份结果，文件名是 `0x<包清单文件的 sha256>.json`，再核整份替换。

- 写的是：包成不成立；每件记录最早的那一枚计入的锚（链 ID、登记合约、区块、时刻、交易）；这次扫到的锚，各带登记合约；这次读成的网络；这次没读成的网络（链 ID、登记合约和读法代码 `down`（不通）或 `fingerprint`（指纹不符））；判这一次的核的摘要。包不成立时只写判定。
- 包不成立也写；包成立而这一次一条链也没读成时不写（包写明的网络没添加、没配网络、节点都不通）。
- 这份档不加密，是给别的应用读的。ZIKARON 自己不读它，它也不改任何判定。

### 他人账本

左栏「核验」的「查看他人账本」标签。

填「作者地址」（右边「地址簿」可选），按「读取」：扫链找这个地址的上链存证，并按「授权核验」一节的四级顺序找它的账本内容。要先配好主网络（只配了只读网络时不读）；配了只读网络的，在主网络之外一并读。

- 「高级选项」里的「记录内容(可选)」可以给出记录包、授权文件、账本目录或 https 发布地址。
- 「存入地址簿」「从地址簿移除」只影响本机的地址簿。

**「概览」**有四格：

| 格 | 显示 |
|---|---|
| 「账本状态」 | 检查结论；只有上链存证而没有账本内容时，写「仅有上链存证,无账本内容」 |
| 「记录数」 | 不含已删除的记录 |
| 「历史授权」 | 下面写「链上存证 N 条」 |
| 「最近上链」 | 最近一次上链的时间 |

- 四级都没找到账本时写「未取得账本内容:提供记录包或发布地址」，记录数和授权数写「未取得」，不写 0。
- 概览下面是授权表：作品、有效期、首锚区块时刻。

**「条目列表」**逐条列出对方账本，点一行看只读详情。删除条目的读法与本机相同（附录 C）。有网络这一次没读成时，「概览」里逐个写出它的名字和「不通」或「指纹不符」；读成的链上找不到锚的条目是灰灯，点开详情「上链状态」写「未读链」，不写「未上链」。

### 尽调

使用方在「查看他人账本」这一页做尽调：「高级选项」里多几样：

- 「记录哈希(可选)」
- 「所需有效期(可选)」：「起(秒)」「止(秒)」
- 「快照存放位置」和「存快照」

「概览」多一块「授权冲突检查」：检查你所需的期限是否与对方已有的有效授权重叠。要同时填「记录哈希(可选)」和「所需有效期(可选)」才检查；缺记录时写「未填记录,未检查」，缺期限时写「未填期限,未检查」。它下面的「详细信息」列出「密钥沿革」，填了记录哈希时还有「最大深度」（有网络没读成而没读到锚时写「未读链」）。

- 重叠时红字：「N 份有效授权与所选期限重叠」
- 不重叠时绿字：「无有效授权与所选期限重叠」

「存快照」把这次尽调写成 `snapshot-<地址前十位>.json`。快照不能作为凭据。

## 10 · 提醒

### 提醒事项

左栏「提醒」。表中每行一件事：一盏灯、事项和现状。需要处理的行右端有「去…」链接，点这一行即转到该处理的页面，并打开相关的部分（例如账本检查卡、按签发者分组）。没事的行写「无需处理」。

| 记录者 | 使用方 |
|---|---|
| 「待上链」 | 「我的授权即将到期」 |
| 「队列积压」 | 「授权被撤销」 |
| 「授权即将到期」 | 「整机备份」 |
| 「整机备份」 | 「账本移交」 |
| 「账本检查结论」 | 「上游异常」 |

- 「待上链」和「队列积压」说的是同一件事时，合并为一行。
- **「整机备份」**：从没导出过时为「还没有备份」；上次备份后又多了账本条目或收到的授权时，为「N 条未备份」。
- **撤销监测**的提醒排在表末，每件一行。它们只在发现的那一次运行里列出（「授权被撤销」「账本移交」两行也只数这些）；重启应用后不再列出，被撤销的授权在「我的授权」里仍标「已被撤销」。
- 左栏「提醒」旁的数字，数的是黄灯和红灯的行。
- 上一次读链失败的原句在「详细信息」里。

**提醒怎么通知你。** 发路是窗口注意请求加吐司。下列事项新出现时，窗口向系统请求一次注意，并出一条提醒提示：记录者的「授权即将到期」「整机备份」，以及「账本检查结论」为断链时；使用方的「我的授权即将到期」（含已过期）「整机备份」「上游异常」，以及撤销监测。其余黄灯、红灯（例如「待上链」「队列积压」）只在本页和左栏数字里显示，不另行提醒。

- 同一件事只提醒一次，提醒过的记在数据目录的设置里。情况变了（期限变了、账本在别处断了、上游账本有了新条目）算新的一件，会再提醒。
- 网络错误不提醒，只在状态行显示「同步失败」。
- 设置里没有关闭通知的开关。

## 11 · 设置

左栏「设置」打开设置首页，列出七项，点一项进入那一页。两种角色的设置项相同。

| 项 | 内容 |
|---|---|
| 「语言和时间」 | 界面语言与时区 |
| 「外观」 | 浅色、深色或跟随系统 |
| 「身份密钥」 | 身份、口令与密钥备份 |
| 「网络」 | 节点、登记合约与发布地址 |
| 「通知」 | 账本检查或授权核验的周期 |
| 「本机数据」 | 加密、备份与数据目录 |
| 「关于」 | 版本与设置检查 |

**设置存在哪里：**

- 外观、自动锁定、最后选的语言和上次整机备份的记录：存在这台机器上，对所有身份生效，口令门上也用。「只读网络」一栏也存在这台机器上，所有身份共用。向导里最后选的网络也记在这里，但只决定新建身份时默认选中哪一项；每个身份用自己的网络。
- 其余设置：存在当前数据目录里。没有数据目录或只读时改不了，页面不变并提示原因。

#### 11.1 语言和时间

- **「语言」**：「中文」或「English」。口令门用最后选的语言。
- **「时区」**：「UTC」（默认）或「跟随系统」。
  - 窗口里所有时刻都按它显示。完整的写法是 `2026-09-24 23:46:12`，位置窄的地方只写日期或「月-日 时:分」。
  - 读不出系统时区时提示「读不出系统时区,时刻按 UTC 显示」。

#### 11.2 外观

「浅色」（默认）、「深色」或「跟随系统」，立即生效。

### 身份与密钥

设置「身份密钥」。

顶上一张卡写当前身份的名字和「角色 · 种类」，按「复制地址」复制当前角色的签名地址。

**「身份」组：**

| 项 | 说明 |
|---|---|
| 「当前身份」 | 角色、种类和名字 |
| 「建于」 | 这个身份建成的日期 |
| 「gas 余额」 | 当前角色签名地址的余额，或「未读取」 |
| 「备份状态」 | 「已抄录助记词并导出密钥文件」「已抄录助记词」「已导出密钥文件」或「未备份」 |
| 「备份档」 | 导出的密钥文件此刻是否还在盘上（按实际文件判断） |
| 「保存位置」 | 「本机密钥库(口令加密)」 |

当前角色取不到密钥时，多出一行「密钥地址」说明原因，例如「尚无签名密钥」「密钥不在本机密钥库」。本机身份的空着的那一种角色，写「未启用 · 导入另一把密钥,或改用助记词身份」。

**「主身份」组**（「只有主身份能恢复口令。」）：

- 当前就是主身份：写「这个身份」，并注明凭助记词还是凭密钥文件恢复口令。
- 当前不是主身份：写主身份的名字，下面是「设为主身份…」。
  - 在「设为主身份」卡上输入本机口令，按「设为主身份」。
  - 原主身份降为次要身份。所有密钥和本机数据都换一枚新主钥重新加密，口令不变。这一步要么全部完成，要么完全不变。
  - 只用私钥导入、还没导出过密钥文件的本机身份，要先导出密钥文件才能设为主身份。
  - 有数据目录不在原处（外置盘没接），或有后台写入在跑时，会拒绝，稍后再试。

**「口令」组：**

- **「自动锁定」**开关和**「闲置时长」**（见 5.2）。
- **「修改口令…」**：先输当前口令，再输两遍新口令，提示「口令已更新」。输错当前口令会计入错误次数。
- 当前口令是纯数字时，提示「当前为纯数字口令,建议加入字母。」
- 还没设口令时，只有「去设置口令」。

**「导出」组：**

- **「导出密钥文件…」**：给别的钱包用的标准 keystore 文件。本机身份作为主身份时，也凭它恢复口令。步骤：
  1. 输入本机口令。
  2. 设文件密码，至少 8 位。强度条只作参考，不会拦你。
  3. 选保存位置，按「导出密钥文件」。
  - 文件权限为仅本人可读。写出后应用会读回核对一次，通过才提示「密钥已备份到 …」并更新备份状态。
- **「显示助记词…」**：输入口令后显示 12 个词，按「收起并关闭」清掉。本机身份没有助记词，这一行不可用。

**「更换身份」组：**

- **「切换身份…」**：列出所有身份，点一行展开，看到两种角色的完整地址，按「切换」才换过去。
- **「新建身份…」**：写可选的「备注」，在下面的「网络」里选这个身份用哪个网络，然后生成、抄写并核对 12 个词，方法同向导第 2 步。
  - 「网络」列出附录 A 的各个预置网络，加「自定义」；默认选中这台机器上次在向导里选的那一项，从没选过即以太坊主网。
  - 选的网络填进这个身份两种角色的数据目录，两种角色同用。
  - 早先版本建的身份没有记下网络：升级后第一次打开数据目录时，照这台机器在向导里选过的那一项替它记下（选的是「自定义」、从没选过，或它的数据目录已在另一条链上，即不记），此后两种角色都用这一项，这台机器再改选也不变。
  - 选「自定义」，这个身份的数据目录没有网络，读链与上链都会提示未配置；到「设置 > 网络」填好保存（手填或选预设）后才生效。在其中一种角色里填好保存，另一种角色打开时取同一份；别的身份不受影响。
- **「导入密钥…」**：三个标签「助记词」「私钥」「密钥文件」。
  - 助记词：12 格，整段可粘贴。
  - 私钥：64 位十六进制，可带 0x。
  - 密钥文件：拖入 keystore 文件，填「密钥文件密码」。
  - 导入私钥或密钥文件时选「导入为哪一身份」（「记录者」或「使用方」）；这把密钥只占这一种角色，另一种留空。
  - 这台机器上还没有身份时，导入的即成主身份。这时导入私钥要同时导出它的密钥文件：单上多出「密码,至少 8 位」「确认密码」和「保存位置」，导出的文件读回核对过才建成身份；不填即拒「这个身份还没导出过密钥文件。」。
  - 可选「备注」，「网络」同「新建身份」。按「导入身份」。在向导里打开时没有「网络」这一格，由向导第 3 步决定。
  - 已有身份时导入的是次要身份，不能恢复本机口令。已经在本机的身份不会重复导入，但如果它缺了密钥，导入会把缺的补回来。
  - 导入的身份先不能写，要等它的账本与链上这把密钥的上链记录核对过（见「存储」一节的「取回账本」）。
- **「重命名…」**：给身份改一个备注名，只用于分辨，不影响任何判定。

新建和导入的身份都是次要身份。这台机器上还没有身份时除外，建成的第一个即是主身份。

**删除身份。** 页底「删除身份…」：

- **主身份不能直接删除**：先把另一个身份设为主身份（「去设主身份」）；只有它一个时，先新建或导入一个再设。
- **删除次要身份**：
  - 卡上写影响（记录者「账本将无法续写」，使用方「此身份下的授权不再归你」），并列出哪种角色的账本已有条目。
  - 输入本机口令后按「删除身份」。
  - 只删除密钥库里的密钥和身份登记，数据目录保留。
- **没备份过的身份不能删**：「此身份尚未备份,无法删除。」「先备份密钥或确认助记词;记录者也可先登记移交。」
- 记录者删除前，应先登记移交（见「移交账本」），否则新密钥无法续写这本账。

**「详细信息」：**

- 两种角色的完整地址。
- 派生路径：仅助记词身份有。
- 身份列表文件。
- 这一身份能签的签名域：记录者能签条目和连署、发锚定交易；使用方能签自己账本的条目、发锚定交易。

#### 11.4 网络

**读数：**

- **「网络」**：写这个数据目录的网络来源。
  - 「以太坊主网」等预置的名字：这个数据目录的四格与附录 A 那一行相同。身份日后改选别的网络，已有网络的数据目录不跟着变。
  - 「自定义」：自己配置过
  - 黄灯「尚未配置网络」，下面一行提示到「编辑节点…」手填或选预设。
- **「链上读取」**：
  - 「N 个节点一致」
  - 「仅 1 个节点响应,无法交叉核对」
  - 「未读取」
- 节点、登记合约、链 ID、起始区块在「详细信息」里。

**「自动上链」**：开关，默认关，每个数据目录各记一份（见「待上链队列」）。

**按钮：**

- **「编辑节点…」**：展开编辑区。没有网络的数据目录只能在这里填。
  - 「预设」：下拉选附录 A 的一个预置网络，节点、链 ID、登记合约、起始区块四格随之填好；选「自定义」则保留已填的。预设只是填格子，仍要按下面两个保存键才生效。只读网络栏的「预设」是同一张表。
  - 节点写成 `链号=节点地址`，多个用空格分开，按「保存节点」。
  - 「链 ID」「登记合约」「起始区块」三格，按「保存链设置」。
  - 自己保存过后，「网络」显示为「自定义」；若存下的链 ID、登记合约、起始区块与节点（不论次序）与附录 A 某一行今天的值全等，即显示那一行的名字。
  - 存下别的节点或链设置后，手上的 Gas 估算与费随即作废，下次打开「上链」卡重新估算。
  - 这个身份建时选的是「自定义」时，链 ID、登记合约和节点在一种角色里配齐，就记在这个身份上：另一种角色的数据目录打开时照它填，不用再配一遍。别的身份不取。
- **「读取链上数据」**：读一次签名密钥余额。

**节点连接。** 节点地址以 `https://` 或 `http://` 开头。连 https 节点时每次都校验证书和主机名，证书不通过就读不到链。节点拒绝或连接失败时，提示写明原因（限流、要凭据、网络不符、证书、超时等），原话在详情里。

**发布地址。** 你打算把记录包放到网上的 https 地址：

- 只收 `https://`，填别的提示「仅支持 https 地址。」
- 应用不替你上传，记录包需要你自己放到那个静态托管上。
- 填好地址按「保存发布地址」。保存后出现「对照的记录包」和「检查发布」。「检查发布」从发布地址逐个文件取回记录包，与本地那一份比对：
  - 「已发布」：「N 个文件全部一致。」
  - 「发布不完整」：「缺 N 个文件,M 个不一致。」，并列出缺的和不一致的文件。
  - 「无法访问发布地址」，并写明原因。

**只读网络。** 主网络之下的「只读网络」一栏，这台机器上所有身份共用，存在机器目录里，一个也没有时不留文件。

- 只用来核别人的东西：「核验记录」、「查看他人账本」、授权核验和尽调读主网络加这里的每一个网络。写账本、上链、余额、账本检查只用主网络。
- 按「添加」起一栏新的；有一栏还没保存时不显示「添加」。「预设」可选附录 A 的各个预置网络，或「自定义」自己填。
- 每栏填「名称」「链 ID」「登记合约」「起始区块」「节点」（一行一个），按「保存」。保存只写这台机器，不读链。
- 「名称」：链 ID 是以太坊主网、OP Mainnet、Base、Arbitrum One 或它们的测试网时自动显示，不能改；别的链可以自己起名，不填即显示「链 <链 ID>」。名称只在这台机器上显示。
- 同一条链、同一个登记合约已在列表里，或就是主网络时，拒绝：「该网络已存在。」
- 列表里每栏平时只显示名称和读数；点开才是各格和「保存」「读链」「移除」三个按钮。「移除」先问「移除此网络?」，再按「移除」。
- 「读链」的读数：「一致」（答了的节点都给出钉定那一版登记合约的代码）、「单源」（只有一个节点答）、「不通」（没有节点答）、「指纹不符」（登记合约的代码不是 ZIKARON 钉定的那一版）。
- 每次读只读网络之前都先核它登记合约的代码。「指纹不符」的那一栏这一次不用，它上面的锚一枚也不算。主网络不做这一核。
- 同一条链上的几栏读成一扇窗：登记合约全读，起始区块取最早的那个。哪一栏这一次没读成，结果里点名，其余照核。

#### 整机备份

一份备份文件恢复全部：这台机器上的所有身份和密钥、全部本机数据和设置。不含主钥、口令和错误次数；也不含已核对事实（恢复后重新问链）、只读网络列表、导出的记录包及其索引与核验结果。

- 「上次备份」：时刻，或「从未」。
- 「未备份」：上次备份后新增的条数。
- 「导出备份…」：
  1. 输入本机口令。
  2. 在「备份密码,至少 8 位」里设备份密码，在「再输一次」里再输一遍。
  3. 选保存位置，按「导出」。
  - 文件名为 `zikaron-backup-年-月-日.zikaron`，同一天再导出即往后编号，不覆盖。
  - 写出后应用会读回并打开一次核对，通过才提示「已导出备份:…」。
  - 忘记备份密码，备份就无法恢复。
- 「从备份恢复…」：
  - 选备份文件，填「备份密码」和本机口令，按「恢复」。
  - 本机的身份、密钥和数据整份换成备份里的，口令不变。本机有而备份里没有的内容会失去。
  - 这一步要么全部完成，要么完全不变。
  - 恢复后仍然打不开的旧文件，会被原样挪到机器目录的 `set-aside` 文件夹，不删除。

只有助记词而没有整机备份时，只能恢复链上读得到的数据。

#### 取回账本（导入的身份）

凭助记词、私钥或密钥文件导入一个身份时，它的账本不会随之回来，而这把密钥可能在别处写过。所以导入后这个身份先不能写账本（能读），这一页顶上出现红框「这个身份是导入的:账本还没与链上核对」。

能不能写只看一件事：这一种角色的账本与链上这把密钥的上链记录核对过，链上的每一条都在账本里。账本从哪来不论：

- 配好网络后应用自动核对一次（导入时已配好网络的，导入后当即核对）。链上没有这把密钥的记录（例如一把新钥），或记录都在账本里，即可写。
- 用「原位收编」接管了一个既有的账本目录后，会再核对一次，对上了即可写。
- 链上有账本里没有的记录时，红框变为「别处有更新的条目:链上有 N 条上链记录不在取回的账本里」，仍然只读，需要从整机备份取回账本。

从整机备份取回：

1. 选一份整机备份，填「备份密码」，按「取回账本」。
2. 应用从备份里取出这个身份的账本，再与链上这把密钥的锚核对：
   - **全部对上**：提示「取回 N 条,链上 N 条上链记录都在账本里:可以写了」，恢复写入。
   - **链上有账本里没有的锚**：红框变为「别处有更新的条目:链上有 N 条上链记录不在取回的账本里」，仍然只读。请找更新的那份备份再取一次。
   - **本机已有的条目与取回的冲突**：出冲突卡，按「取回并替换」后，本机原有的数据保留为「旧数据」，可以在这一页的「旧数据」组里「查看」（只读）。

## 12 · 命令行（`zikaron`）

命令行读写的是你指定的账本目录。

ZIKARON Desk 自己数据目录里的账本是加密的，命令行没有口令，读到时拒绝：`E_UNREADABLE` 后面跟账本路径，下一行「已锁定:这是 ZIKARON Desk 封存的本机数据,命令行不读」，退出码 2。要交给命令行处理，导出「账本镜像」或「记录包」：`audit`（以及经它的 `check-grant`、`chain-check`、`depth`）和 `show --entry` 的 `--ledger` 可以直接指向镜像文件夹（含 `mirror.json` 的那一层）或记录包文件夹。记录包先按记录包的法核一遍，不通过即拒 `E_KIT`。写条目的动词与 `init` 只收账本目录。

**写之前先审。** 每个写条目的动词（含 `init`、`retract`）写之前，把「这个账本加上这一条」交核心离线审一遍；会新添一条链上发现（换了密钥之后旧钥再写、跳号、同一位置写第二条、接错上一条）即拒 `E_WOULD_BREAK`，`names` 写明是哪几种，一个字节也不写。手给 `--seq`、`--prev` 也一样过这一道。

**节点地址**可以是 `http://` 或 `https://`，大小写都认；https 校验证书链与主机名，与应用同一个连法。`anchor` 等收据时，一轮被节点拒了不算答案，按间隔再问，直到 `--wait-secs` 用完；整段时间里节点从没答过才报 `E_UNREACHABLE`。

**`anchor` 发前先估气。** 读完费之后，先请节点按这一笔交易估一次 gas（与应用同一个算法），交易所带的额度是估数的 1.5 倍（向上取整），最多 20 万。节点以错误拒答这一问（会回滚，或限流等，原话在 `detail`），或估数超过 20 万，即拒 `E_GAS_REFUSED`（退出码 1），一笔也不发；节点没答这一问，报 `E_UNREACHABLE`（退出码 4），也不发。

**授权文件。** `check-grant --grant` 可以给授权条目文件，也可以给应用导出的授权文件（`.zkgrant`）：命令行按应用的同一读法拆开（包的形、里面记录包的法、授权码、授权码里每一跳都在包里），核的是这份文件为之而立的那一跳；拆不开即拒 `E_GRANT_FILE`。

**写条目被拒时。** 条目的某一项缺了或格式不对，标准输出为 `E_ENTRY`，其 `token` 为 `E_BODY_FIELD`（退出码 1）；标准错误另有一行人话，点名是哪一项、由哪个参数给，例如 `mode: 缺或不成形,由 --mark 与 --toolchain(或 --file) 给`。这一行只给人看，不属输出约定。

**`history` 记一份文件。** `history --file <文件>` 按应用记录文件的同一约定填：`content` 是这份文件字节的 SHA-256，`mode` 是 `{"mark":"bytes-sha256/1","toolchain":<"bytes-sha256/1" 这串字的 SHA-256>}`。同一份文件，命令行与应用记下的这两项逐字相同。`--file` 代替 `--content`、`--mark`、`--toolchain`，不能与它们同给；不给 `--file` 时这三项照旧自己给，不填的由法拒。

**其他。** `audit --out <文件>` 把这一趟组装的审计输入（六项）另存一份，可作 `chain-check --hop <授权>=<审计输入>` 的输入。`kit-export --file <包内路径>=<文件>` 的包内路径相对记录包的 `files/`，`--proof` 相对 `proofs/`。用法错误时，标准错误第一行是 `<拒因> <主语>`（只写出错的那一旗、值或路径），第二行是给人看的说明。

| 动词 | 作用 |
|---|---|
| `keygen` | 生成一把密钥，输出地址与私钥 |
| `init` | 在空账本上写创建账本条目 |
| `history` | 追加一条存证（`--file` 按应用的约定记一份文件） |
| `grant` | 签一份授权并写入账本 |
| `revoke` | 签一份撤销并写入账本（裁决文件摘要可选） |
| `adopt` | 写一条导入条目 |
| `attest` | 用外部密钥出一份连署 |
| `succeed` | 写一条换密钥或移交条目 |
| `annotate` | 写一条注记 |
| `retract` | 写一条删除条目（目标须是本账本里一条还没删过的存证） |
| `anchor` | 把哈希锚定上链（调用登记合约，或自转账裸锚） |
| `scan` | 按链设置扫描锚（`--endpoint` 收 http 与 https） |
| `audit` | 用扫描结果加账本做审计，输出报告与结论（`--ledger` 收账本目录、账本镜像或记录包） |
| `check-grant` | 六项核验一份授权（`--grant` 收授权条目文件或授权文件） |
| `chain-check` | 逐跳核验转授权链（`--hop <授权文件>[=<审计输入文件>]`，可重复） |
| `depth` | 一件记录的深度读数 |
| `fpm-sign` | 签指纹清单 |
| `ack-sign` | 签收执 |
| `badge` | 编码或解码凭证（`--encode` 与 `--decode` 二选一） |
| `kit-export` | 导出记录包（自验通过才写出） |
| `show` | 显示一条条目的作者、ID、类型、上一条、序号与内容 |

**退出码：**

| 码 | 含义 |
|---|---|
| 0 | 肯定 |
| 1 | 否定（条目被拒，或结论为 FAIL、BROKEN_CHAIN、NO_LABEL） |
| 2 | 用法错误（标准输出为空） |
| 3 | 部分（PARTIAL、GAPS、UNAVAILABLE） |
| 4 | 答不出（节点不通、读数不一致等） |

标准输出是一个规范 JSON 值，没有结尾换行。`--now` 注入判定时刻；不给即只用链上时间。输出格式与全部参数见仓库里的 `CLI-SCHEMA.md`。

## 附录 B · 本机文件与加密

**机器目录**存放密钥库、身份登记、机器设置 `machine.json`、记录包索引等。

- 位置由指针文件 `~/.zikaron-desk` 给出（一行绝对路径）；没有指针时默认为 `~/.zikaron-desk.d/`。在 Windows 上，指针文件与默认机器目录都在 `%LOCALAPPDATA%\ZIKARON\` 里：`%LOCALAPPDATA%\ZIKARON\.zikaron-desk` 与 `%LOCALAPPDATA%\ZIKARON\.zikaron-desk.d\`。
- 早先版本把机器目录放在 `~/Library/Application Support/ZIKARON`：没有指针而这个文件夹存在时，应用会沿用它。

**数据目录**：每个身份的每种角色一个，存放账本、设置、待上链队列、收到的授权等。

**本机加密。** 账本条目、设置、待上链队列、身份登记、记录索引、手填的记录包链接、已核对事实（机器目录的 `checked/facts.json`）、收到的授权与条款文件，都用主钥派生的本机数据钥加密（XChaCha20-Poly1305）。锁着时一份也读不出，拿到这台机器文件的人没有口令也读不到。

**不加密的文件：**

- 开锁前就要读的：密钥库本身（另有加密）、`machine.json`、数据目录指针。
- 给别人看的导出件：记录包、记录包索引、核验结果文件（机器目录的 `kits/verified/`）、授权文件、凭证、账本镜像、密钥文件、整机备份（整机备份用备份密码加密）。
- 只读网络列表（机器目录的 `read-networks.json`）：不含账户信息。
- 别人交来的外来文件。

**整机备份**用 scrypt（标准参数 N=262144、r=8、p=1）从备份密码派生密钥，再用 XChaCha20-Poly1305 加密。

## 附录 C · 删除条目的读法

「删除存证…」写进账本的是一条类型为 `retraction` 的条目，照常签名、照常上链：

| 字段 | 值 |
|---|---|
| `entryType` | `retraction` |
| 正文 `subject` | 必填：本账本里一条存证的条目 ID，`0x` 加 64 位小写十六进制 |
| 正文 `note_md` | 可选：一段说明 |

这是 ZIKARON Desk 的读法约定，不在 `zikaron/1` 协议正文里。别的工具读到它会列为未知类型（`UNKNOWN_TYPE`），账本结论不因此改变。

本应用的读法：

1. 格式正确、`subject` 指向本账本里一条没删过的存证：这条存证读作已删除，在各表中划掉，不能再签发新授权，详情页也不再出授权与导出的按钮。
2. 被删的存证如果还没公开过，删除只记在本地；已经发出或上链的，删除条目照常上链（见「存证上链」）。
3. 已上链的存证被删除后，链上记录照旧，深度照旧计入。
4. 已经签发出去的授权不受影响。
5. 同一条存证第二次被删：读作「删除无效:目标已被删除」。
6. `subject` 指向的不是存证：读作「删除无效:目标不是存证」。
7. `subject` 在本账本里找不到：读作「删除无效:目标条目不在此账本中」。
8. 缺 `subject`、格式不对或多出别的字段：读作「删除无效:内容不合约定」。
9. 无效的删除条目不影响任何存证，也不会让账本读不下去。

在「查看他人账本」里读别人的账本，按同样的规则。
