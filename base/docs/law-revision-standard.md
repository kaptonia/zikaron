# 法文本修订的标准流程与门槛

适用于 Court 所管的一切法文本、它们的判据核、语料、量具与记录簿,以及随法冻结的合约。判官另有裁定的,以裁定为准。

---

## 一 · 名词

| 名词 | 含义 |
|---|---|
| 判据核 | 法的参照实现,纯 Python、只用标准库;摘要由 `criterion-digest*.sh` 计算,内嵌上游核时把上游摘要行一并计入 |
| 量具 | 量具契约(`HARNESS*.md`)、生成器、比对器、bcov、边界表、回放、参照场所;属工装层,随时可修 |
| 承诺层 | 法文本的谓词与 MUST、§7 各行、判据核、合约的编译字节 |
| 承重项 | 两位细心的实现者可能得出不同输出、合约可能与文字行为相异的发现,以及语料缺见证 |
| 措辞项 | 其余只动散文的发现 |
| 收口轮 | 一个核的三家实现用上一轮程序原样首测,种子 1 至 6 全部零分歧的一轮 |
| 开发期 | 法发布之前;接口法以首个场所为使用而部署为界 |

---

## 二 · 总则

1. **法文本即判据。** 命名之前,判据程序与文本相左时以文本为准,程序之差即为发现。判官材料供读意图;设计稿是施工参考;什么算成文法由判官定;冻结的上游法只引用。
2. **门槛只计承诺层。** 量具的缺口为信息级,随到随折(铜蛇律:封行为,不封尺)。
3. **两问。** 语义改动与新机制在折入前答:倒转形态是什么;受害者是谁;既有机制是否已覆盖;复杂度是否值得。答不出具体内容的撤案。措辞项与语料见证照改。
4. **机制只防外部攻击者**(GALEED 家族,判官 10-22、10-23)。审计发现与机制类发现须说出外部攻击者或任何人皆可为的捣乱,以及它得到或破坏了什么。
5. **互不依赖的项目,法互不点名**(galeed/1 与 zikaron/1;ERAVON 与 CHELEK)。内嵌上游核的法按节号引上游,在 §x.4 钉上游摘要。法外的包 README 可以提及他项目。
6. **开发期就地修订。** 原位修改,版本字面照旧,用同一法定动作重新命名,被取代的摘要与身份留在记录簿。开发期过后的改动照该法冻结节办(接口法改 ABI、MUST 或 §7 各行即立 `/2`)。未发布的标准只用一代字面。
7. **对外文字取代式更新。** 法文本条文、量具契约、README 正文只写现行内容;经过写进记录簿与 git。Court 改动接收方的设计档时只出告知稿;ERAVON 的设计卷、架构档、路线档已是历史档。
8. **超出判官稿的语义改动**,在汇报里单列,附各选择的后果,由判官定去留。讨论中的改动先报方案,批后再改。
9. **写作三条**用于新增散文:正面陈述,避开「不是…而是…」句式,避开破折号。法文本里照法意需要的 MUST NOT 与 never 保留。

## 三 · 角色

| 角色 | 职责与边界 |
|---|---|
| 判官 | 下令,给修订稿与方案,裁定选项与门槛 |
| 接收方 | 给基底与修订稿,收包重钉 |
| 编排者 | 亲自施工(法文本、判据、量具、语料、回放、合约、记录簿、命名、打包),派席,折入,收口判断,汇报 |
| 读者席 | 读法文本,报两读、矛盾、悬空引用、缺口,附引文与建议措辞,每部法明言可否命名;可把判据与比对器当黑盒跑 |
| 实现席 | 只凭法文本、量具契约、语料文件与语料 README 写出完整实现;判据只在自己的命令写成后当黑盒跑;记录簿的逐轮发现在首测之后读;保留程序与 `run.sh` 供下一轮原样复测 |
| 审计席 | SEC、VULN、ADV、FUZZ,对合约编译字节出发现;在自己的拷贝里构建 |
| 场所席 | 接口法首次冻结时,各照一份家族场所文档建一个场所跑回放;场所代码留在仓外 |
| 测试席 | 回放改动后移植历来全部变异体与合法对照 |
| 核查席 | 读折入 diff |

所有席位用 opus;施工与收口判断只由编排者做。

---

## 四 · 流程

### 0. 接件

1. 读完材料包全部文件;以最新一版为准。判官要事项清单的,先报清单再开工。
2. 工作底取 Court 现行提交,先核它与接收方现行基底(产品仓或判官给的 `base/` 及其 `BASE-LOCK.json`)逐树相同;材料包比 Court 旧的,以 Court 为准并保留 Court 其后的教科书改动。
3. 修订稿的每段「现文」用脚本到底里检索,须恰好一次;再扫一遍改动的波及面(家族其他法文本里同类的句子、连字形、引用)。
4. 先提交一次作检查点。

### 1. 第〇轮

1. 判官稿原样施入,照 Court 宽度 76 列折行。摘要或身份会变的(核要动,或所嵌上游核要动),冻结节退回未命名形。
2. 判官稿留有选择、判据只能取一之处,写明所取读法,请第一轮读者核。
3. 改判据、量具契约、生成器;种子 1 至 6 重生,判据对预测零差;判据改前改后在旧语料上对照,证明稿外的答案原样。
4. 合约有改动的:写合约与测试,算 codeHash,回放与参照场所随改,套件全过。
5. 记录簿开一节,写为何修、改了什么、第〇轮。提交。

### 2. 各轮

1. **派席。** 共同简报写明:每席独自做,一步到底,只交一次报告,疑问自定并写明所取;Court 只读(法席只用 `git diff`、`git show`;审计席把合约连同 `contracts/lib` 拷出,git 与构建都在拷贝里做);席位离线工作,钥与口令留在一切档案之外;比对脚本一次一个,forge 进程至多三个;工具链 forge 1.8.3、Python 3.12 venv(含 pycryptodome);报告形状:结果与数字、分歧与发现、文本疑点、语料外探针、建议(附倒转形态与受害者);判官已定的项与已撤回的项照已定读。
2. **快照。** 席位量派遣时的提交,一轮之内 HEAD 原位;种子 2 至 6 各建独立比对树,比对器先打印清单的种子与摘要。
3. **一步纪律。** 一轮派出后编排者只收报告。判官中途的裁定落盘,攒到折入时施行;中途通信(暂停、续跑、迁机)只在判官下令时发。判官说一轮回来先停,就只收报告、记折入项。
4. **收件。** 席位写不了文件时,最后一条消息即报告,编排者存档。
5. **折入。** 全部交回后一次折入:
   - 每条先核实成立,记为取、不取(附理由)、只记录、待判官定、随报(本次范围之外,只报判官);
   - 用脚本按唯一锚点施行(旧文须恰好一次,替换文本以非空白开头),施后按 76 列折行;
   - 改了生成器,最后一次改动之后重生种子 1,工作树干净再提交;种子 2 至 6 随之重生;
   - 回放改了派测试席;改动及于 MUST、§7 各行或谓词的派核查席;
   - 记录簿加本轮一节;提交。
6. **判官中途加的修订稿**与当轮折入一并施行,下一轮读新法。

### 3. 收口与命名

1. 各核按第五节之一各自收口,接口法按之三,合约按之二。法与合约共用常数的(类型串、验证器),命名等合约过门。
2. 收口轮残余一次折入;折入的句子由读者或核查席再读一遍,确认只有一种读法,随即命名。
3. 命名脚本先 `--check` 再实做,按依赖次序:上游核摘要写入其冻结节,该摘要行写入各子法 §x.4,子法脚本算各自摘要,接口法 §10 写接口文件 sha256。命名节写旁证(收口轮、种子 1 至 6、探针数、模糊次数或缓做);接口法 §10 只写现行身份。
4. 命名后:全部摘要脚本复算一致,比对器种子 1 至 6 退出 0,forge 全过;记录簿加命名一节(摘要、本文 sha256、被取代者)。

### 4. 其他路径

- **教科书修订**(谓词原样):免派席位。摘要复算同值,`gen.py --seed 1` 按字节重建语料,比对器以判据自比种子 1 至 6 零差,夹具全部重放;会改身份的字节(合约注释、语料样本)保持原样;记录簿写改处与新文本 sha256。下游发起的散文修改,下游出「说明加现行法文本」,Court 照此办。
- **命名后再改:** 读者或核查席核改动;回放改了的测试席重跑;动到判据答案的,原程序首测,差异须恰为改动所致,照改后复测零;记录簿补一节;重做命名,重出包。
- **上游核重命名后:** 内嵌它的下游法以自身 §x.5 一次动作重钉;判据字节原样的,判据对预测零差、摘要脚本复算即可。
- **只改合约或标准文档、法原样:** 合约审计按之二;法文本中的散文走教科书修订;出包附 README。

### 5. 自查

1. 修订稿所列废词与已删成员名,在法文本、量具与核心树里检索归零(换行折为空格),例外写明出处;修订稿给的逐法问题逐一作答。
2. 交叉引用全部可解析。
3. 摘要、种子 1 至 6、forge、codeHash 皆与所载一致。

### 6. 打包与汇报

1. 目录 `~/Documents/<修订名>-<日期>-court/`,分接收方各放一包:
   - `base/`:本次所改各法文本、git 所跟踪的量具与核心树、forge 库(路径同 Court)、`.gitattributes`;
   - `BASE-LOCK.json`(位置随接收方):来源提交、各核摘要、接口身份、各合约 codeHash、forge 测试数、夹具数、语料数、`external`、`fileCount`、逐文件 sha256;
   - `reference/`:记录簿与审计档,只读参照;
   - `MANIFEST.sha256`;
   - 中文 `README.md`:包里有什么;哈希表(改前、改后);这一轮做了什么;接收方跟着做的事(含接收方复验种子 1 至 6);请判官定夺或知悉;Court 提交号。
2. 打包脚本断言锁中各值等于命名值;包拷到草稿区复验:MANIFEST 全过,摘要复算一致,forge 全过,比对器种子 1 至 6 退出 0。
3. 给他席的接线稿只写施工内容,常数指向 `CODEHASH.md` 现行表。
4. 做到标准再找判官。汇报写:包的路径,各新值,各门槛怎样达到,承重项几项、是否都在本次范围内,待判官定的事项及各选择的后果。影响判官决定的错误一句讲清;其余小错汇报里略去,记录簿照记。

## 五 · 门槛

### 之一 · 有判据核的法(判官 09-16、10-17、10-23)

1. 每核三家独立实现(Rust、Node、Python);原语是否准用库照该次简报。
2. 收口轮:三家用上一轮程序原样首测当轮语料,种子 1 至 6 全部零分歧;这次首测单独先报。
3. 每家在语料外以判据为黑盒探针,全部一致。
4. 种子 1 至 6 上判据对预测零差。
5. 法 §x.1 所列闭合边界在每个种子下两侧有见证;边界清单先于语料。
6. 法冻结节所列前提逐条满足(例如 galeed/1 §12.1:一家独立实现在十万次以上模糊样本上与核一致,零崩溃、零挂起、零不确定、零错收);准许缓做的,命名节写明。
7. 收口轮读者残余一次折入。折入改变判据任何答案的,该轮作为下一轮的前一轮;折入只动文字或只添语料案例、判据答案原样的,三家原程序在折入后的语料上复测种子 1 至 6,全部零分歧即收口。
8. 读者明言可否命名;折入的句子再读一遍只有一种读法。
9. 措辞项照改,门槛之外(判官 10-17)。

### 之二 · 合约(判官 10-17、10-23)

1. 每轮四席:SEC、VULN、ADV、FUZZ。发现附等级(严重、高、中、低、信息)、位置、场景、证明(Foundry 测试与命令,或说理)、修法;报告列出查过且安好的面与全部命令、种子。
2. **合约本体连续两轮审计、对抗与模糊皆无高、中、低任一级发现即过;信息级随到随折。** 合约本体指要冻结上链的码;回放、参照场所、法文、客户端规则的发现归信息级。
3. 计数的两轮所审编译字节相同;编译字节改动,门槛从改后重新起算;只改注释、编译字节原样的,照计。
4. 每轮从干净构建复算 codeHash,与 `CODEHASH.md` 一致;编译字节改动即出新表,旧表留存。
5. 法侧的承重项走法侧门槛。

### 之三 · 接口法(只立 MUST 与 ABI)

1. 首次冻结:场所席五席两次零分歧。
2. 读者核:接口文件逐字等于 §1;§8 说的正是回放所做;参照场所守全部 MUST;回放拒掉的场所确属违法。
3. §2 至 §7 与回放相抵、而回放自冻结起即量、参照场所皆守的,法文取回放之规;回放超出法文的,改 §8 文字。
4. 凡要约束场所的规则写成 MUST,并在 §7 补行。
5. 改动及于 MUST、§7 各行或谓词的,核查席读折入 diff;所报缺陷照改再核,到只剩措辞。
6. 参照场所套件全过;测试席把存活变异体逐个归为合法、不可观测、已否决的设计、已知残余或缺口,缺口附回放补丁。测试席预备的补丁逐字照用时,其变异结果直接有效。

## 六 · 席位配置

按范围配:
1. 每个要重新收口的核要有三家独立实现;一家实现席可以写同族的几个核(判官 10-24)。
2. 读者席两种配法:按法分席;或一席通读全部法文本。另加语料与比对器一席、工装与生态一席;有合约或接口法的,加一席读法文对合约与回放。
3. 有合约改动的修订,每轮四个审计席。
4. 回放改动后一个测试席;改动及于约束文字时一个核查席。

---

## 七 · 记录

1. 每部法一本记录簿,每次修订一节:为何修、改了什么、第〇轮、各轮(席位、数字、所见、所折、不取与理由、判官裁定)、命名(摘要、本文 sha256、被取代者)。已由机制承载的裁定,以机制为记录。
2. 合约审计记在该合约所属的记录簿或审计档:门槛、各轮各席所报等级与数目、修法与复跑。
3. 记录簿与审计档照实记录经过。

---

## 附 · 待判官定

1. 只改散文的法,是否用原程序复跑代替实现席。
2. 合约审计是否等合约代码定稿后再开。
3. 收口轮带改变法意的文字承重项,能否照之一第 7 条收口。
4. 接口 ABI 改动时是否重派场所席。
5. 「机制只防外部攻击者」是否适用于 GALEED 以外的法。
6. 每轮并行派十余席(实现席作为量具),与「施工不派并行 agent」的边界。
