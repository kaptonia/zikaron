# ZIKARON family components

Shared components of the three desktop apps of the family (ZIKARON, GALEED, ERAVON). Each component carries a family version number. A project that changes a component bumps its number at release; the others see the higher number, read the diff between the two releases of that project, and decide what to pull. The number records what was done, not bytes; it moves only at release.

This list is ZIKARON's, as of release 0.1.3. Paths are relative to this repository at that release. The machine-readable form is `family-components.json`; the literals a port must replace are in `crates/app/family-literals.json`.

## Changes in 0.1.3

- `transport` 3: the system's automatic configuration script (PAC) is run in an isolated QuickJS engine (standard PAC functions only, no network, files, modules or timers; time, memory and stack caps; name lookups answered outside), and the ways it names are tried in turn, `SOCKS` as SOCKS5 then SOCKS4a; a script is fetched only from this machine over `http` or from anywhere over `https`, redirects included (`PAC_REMOTE_HTTP` otherwise); automatic discovery (WPAD) is not done; proxies that ask for credentials (HTTP Basic, SOCKS5 user name and password) are answered, and a missing or refused credential is named apart from an unreachable proxy; HTTPS proxies (TLS to the proxy and to the node, each certificate checked) and SOCKS4/4a; under a custom proxy, private, link-local, loopback and `.local` nodes go straight; TLS reads and handshakes are driven one socket step at a time, so a peer that trickles bytes meets the deadline; why a connection went without its script is kept until a connection to that node is made, so a failure can say it; the custom proxy's cells are judged in one place (`proxycells`): a whole address is split into them on one paste or when the host cell is left, never mid-typing, and a saved password stays only with the very proxy it was given to (same kind, host, port and user name).
- `node-answer` 4: a proxy asking for credentials is its own sentence and code, given or not; a failure after the script was left unused carries the script's trouble as its next step; when every node fails, the first failure is kept whole with every node's words as its evidence; node answers moved with the sender (`zikaron-send`, `node`); a nonce that cannot be read is structured evidence, said in each language; the proxy member is read in one place (`node::route_of`); a broken way to a node is structure (`rpc::Broke`: the deadline, the cap, an HTTP status, a proxy and its question about credentials, the process winding down), told apart by its structure and never by words, its evidence in machine form.
- `log-scan` 4: a public paged reader of logs over a block window, its filter forms pinned (no address, an open topic, one topic, any of several); a refusal's evidence is structure (the method, the node's own words, the transport's structure) in machine form, said in each end's words; the range a node takes is read from its own words only.
- `tx-send` 4: gas estimates are judged as a quantity across nodes (the largest is taken); the queue holds exactly the entries not yet seen confirmed on chain (an entry the audit sees on chain leaves unless its transaction is out, one the chain lacks is queued again); the command line asks the registry before sending and does not send what is already there (`E_ON_CHAIN`); earlier data forms are not read; the sender is one crate (`zikaron-send`) for the desktop's queue, the command line through the desktop and the command line with its credential (`anchor --ledger`), each road asking the registry first; a batch is recorded in flight before its bytes go and asked about by its hash after a stop; marking never overwrites an entry in flight; the desktop follows the queue file the command line writes; settling moves only the entries still awaiting that batch; a refusal before sending is `E_SEND_REFUSED` on both command-line roads; the home's write gates (read-only mark, a broken ledger, handed off) are asked from disk before every send, a list of handed ledgers that does not read answering by its own reason; a batch landed in flight whose broadcast no node answered is out, never answered as nothing sent; a void judged on transactions its entries no longer await is no void of theirs; with the credential, a batch no node holds whose nonce is unused is signed again at that nonce when the switch says send, and entries the reading every node agrees on finds on chain leave the queue, as on the desktop.
- `node-agreement` 4: `eth_estimateGas` is judged by quantity, not by sameness; waiting for a receipt does not end early because one node lags; the agreement across nodes moved with the sender (`zikaron-send`, `agree`).
- `os-platform` 3: Linux reads the desktop's proxy settings from disk (KDE `kioslaverc`; GNOME, Cinnamon and MATE GSettings from the dconf database or keyfile, no program started) before the environment; Windows reads the current connection's settings as browsers do, the machine's under the machine-wide policy, and every proxy-list spelling; automatic discovery is not read; the command line reads the terminal's proxy variables before the system; Windows time zones take each year's rule; the one memory wipe lives here, and every other crate forbids `unsafe`; an entry a folder listed is judged on its way out by its own state (not there, or on Windows being deleted), so walking a live folder takes it as not there.
- `durable-write` 4: one temporary-name shape for every write, a write that does not land removes its temporary file, and the writer sweeps leftovers on opening; files are created owner-only; the machine settings are split into a plain file holding only what the passcode gate needs (language, appearance) and an encrypted part read after unlocking; earlier data forms are named and left as they are, never converted; the machine settings' command-line members and their types moved to the sealed layer (`zikaron_seal::machine`), written and read the same by both sides; walking the live machine folder and homes (the whole-machine count, a home's usage), an entry listed and gone by the time it is looked at is not there, not a missing file; the verification note every record kit carries says the same steps and counts in Chinese and in English.
- `single-writer` 4: with the command line writing on its own, the desktop takes the writer lock for each write and releases it, rereading first if the command line wrote; a ledger handed off stops being written here until its handoff comes back, and only a handoff that follows on is taken (`handover`); the writer lock and its outcomes live in the sealed layer; a send holds the writer lock while it readies and sends a batch, lets it go while it waits for the receipt and takes it back to settle, on the desktop and the command line alike; a receipt settles under the lock this process keeps for the home now (one taken again after the home was left and entered), never under one held as no writer's; adopting a ledger is the writer's alone.
- `local-seal` 3: the envelope, its keys and names moved to the sealed layer (`zikaron-seal`) so the desktop and the command line seal and open through one implementation; only this version's forms are read.
- `passcode-gate` 3: a passcode checked in the background only checks it, and an action whose vault locked meanwhile is not done; the key store moved to the sealed layer; each secret of a mnemonic identity has its own recovery seal, so one can be recovered from its private key as well as from its words.
- `key-file` 3: an identity lands on the seat in use when it has one, else its first seat, by one rule for create, import, restore and switch; key derivation moved to the sealed layer; secrets are wiped by the platform layer's one wipe.

- `ui-kit` 5: the page table is the product's, handed to the kit (routes, history, sidebar, wizard steps); the first-run wizard's Back follows its pages; a passcode row takes keys only on the topmost layer; floating cards stay inside the pane they open from; `Show` is followed every frame; pages declare their own drop zones; toasts wait for the last to fade; full-window pages keep clear of the scroll bar; the sidebar's last sync shows the date across days; a toast's key and icon share one rule; a widget standing in a row takes one cell of its caller's layout (`width::cell`) and sits on the row's middle line; every scroll area goes in through `scroll`, a nested one keeping the wheel at its end; a table's first row under its head keeps its top corners square.

- `app-skeleton` 4: new named refusals for the command-line credential, writing locks, adoption, handoffs and proxy credentials; a PAC failure is said as the next step of the connection failure it caused; a task that waits on the chain runs without the writer's turn (`Tasks::spawn_turnless`); a send's codes map onto the desktop's closed table in one place (`fault::known_of_sent`), an anchor already on chain carrying its evidence (`ON_CHAIN`).

## Changes in 0.1.2

- `transport` 2: a peer that does not speak TLS is named as the handshake layer; node sentences never repeat a key from the address; every socket read waits one 250 ms slice at most and then looks at the shutdown flag, so quitting cuts an exchange in flight on every system, and each cut is counted.
- `node-answer` 2: node errors and addresses are said without the key in the address, whatever its form (a node address is its own type, said only through its sayable form); every channel names its own place.
- `log-scan` 2: the code question and the fingerprint check wait out rate limits by the patience table; spans are remembered per place.
- `tx-send` 2: the command line's direct send asks by hash before signing again and records what it signed; the balance check is pinned to the lowest head and compared; a voided batch is named.
- `os-platform` 2: the home is read from the variable the system sets for it first (`HOME`, `USERPROFILE`), and the profile folder is recognised however it is spelled; kernel locks are listed and closed in a starting child; the desktop channel closes at once on every system and checks a client's user in a second step; on Windows a rename waits out a file another handle holds for at most a second, then refuses as the system did.
- `node-agreement` 2: a chain height in the wrong shape is refused by name, never read as zero; the balance is compared across nodes.
